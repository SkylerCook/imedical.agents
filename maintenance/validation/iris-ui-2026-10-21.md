提供一个日常 UI skill、一个纯初始化 skill、一条领域增量 rule、标注/生命周期/匿名案例参考、一份任务模板及只读测量函数。编码、HISUI vendor、部署器和测试状态继续归原 owner；没有新增运行器、项目 UI profile、状态机或传输实现。

编码入口按 enabled 与 UI 信号条件读取领域规则，继续原编码流程。该路由本批仅核对文本和结构；后续实际宿主任务是否按条件加载，仍需观察，不能由文件存在推定。

## 已处理的验证缺口

- 首轮隔离目录因沙箱不能写默认 D 盘临时根而失败；增加权限限制时的系统临时目录回退。两种 PowerShell 场景均在 finally 验证删除自己的独占目录，未清理共享临时根。
- 审查指出原测试名称包含函数源码调用，但只有全脚本执行；已补 CommonJS 导出函数在另一 DOM realm 重新构造并成功测量。
- 首轮夹具展开取到了动画中间值；改为等待明确的最终状态，并增加展开后尺寸恢复断言。没有用固定延时掩盖时序。
- 审查指出动态主题 CSS 与 ready 之间存在取样窗口；改为在初始 HTML 输出目标主题，并核对实际响应。
- 当前宿主的本地 CommonJS 动态 import 与性能对象读取能力存在限制；文档不假定该导入方式可用，真实采样采用独立函数源码，资源证据采用现有 CDP Network 能力。未改变浏览器安全设置。

## 首次本地试点与流程纠正

首次试点通过共享层 DryRun 快进能力基线，随后手工同步新插件、编码路由及使用文档，逐文件 SHA-256 一致。这只能证明未发布开发版副本一致，不能作为完整框架更新部署：共享 Context 未执行 Write，中间文件同步也不是正式发布。

当时仅在试点模块的原注册表启用清单及 plugin_profile 增加 iris-ui。Overlay 以 `-NoPull -Plugin iris-ui` 执行 DryRun → Write → Check，核对实际技能/规则源映射与纯 init 排除；其余模块未启用。该定向调用会跳过其它插件，不能证明编码依赖等已完成生成层刷新。模块验证器的 PS7/PS5.1 结构检查也不能替代完整更新流程。

用户随后明确要求模块部署必须走框架更新流程，并授权先提交、推送框架。已修正 iris-ui-init、README 和使用指南：按源仓发布 → 共享根 DryRun/Write/Check → 项目既有模块管理入口对指定模块 DryRun/Write/Check（固定 -NoPull）→ 模块验证。手工同步或单独生成薄索引不再作为正式部署完成依据；正式运行结果留目标项目回执，未执行的步骤不预记为成功。

项目原始复盘和完整业务材料留在项目自己的 UI 文档目录，未复制入本仓。试点的文件可达与版本检查不等于真实 UI 需求路由或视觉验收。

## 收尾与后续

本批测试标签已关闭，夹具服务已确认退出；临时隔离目录由用例验证清理。首次无交互 stdin 的服务停止调用失败，核对其精确命令行与 PID 后已终止；最终使用交互会话输入 stop 正常退出。
