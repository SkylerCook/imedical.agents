## 方法与发现

旧 scan_project_xml.js 仅扫描部分目录的 XML/JS，提取首个 Class/CSP，忽略 TXT 类源码、例程、CSS 等；JS 名称规则遗漏数字和点号，部分 CSP 名被错误追加 .csp。新维护扫描器读取源码声明、XML 全部顶层对象、类型明确的例程和运行 Web 目录，忽略 ProjectItem 引用。Project 目录另核对：8.5 为 74 项、9.0 为 325 项、9.0.2 为 393 项、9.1 为 325 项，仅引用不能证明源码存在。

仅在来源中找到准确对象时修正 .csr.csp、.js.csp 及旧 Web 前缀；重复折叠后数量不等于原条目加新增数。大小写冲突优先保留既有清单拼写，否则采用 XML 声明。排除独立产品、备份、示例、测试和二进制资源，未将源码或私有连接信息写入清单。

## 待实例确认的边界

- 9.1 的 1049 项旧条目在 tag 和 trunk 均未找到，8.4 有 2 项；保持原范围，缺失不等于已删除。9.1 对应来源并未覆盖全部原清单。
- 各版本还有 69 个未自动纳入的候选：9 个例程缺少确定类型，60 个 Web 文件无法确定部署路径。详细路径与原因在 JSON 的 scan.unresolved 中，不能用组织目录名猜 Web 路径。
- Web 基准采用 /imedical/web/，原 XML 也含 /dthealth/web/；现场须用显式路径映射。9.1 剩余旧前缀仍需确认。对象声明不说明当前实例的 Namespace，也不证明依赖闭包完整。
- TXT 是唯一维护源；原 ProjectItem XML 范围格式已弃用。读取来源 XML 用于取证，不恢复 XML 基线兼容。实际源码 XML 导出与导入功能保持。
- 本轮提升标准范围覆盖率，未做现场逐项导出或业务运行验证，不能声明所有医院通用完整。

## 重复核对

维护扫描器 tools/iris-code-export/scan-tag-scope.js 的 scan(coreProRoot) 返回 found Map 与 report；它不修改源码、不自动改写 TXT。先审查报告及路径/大小写冲突，再合并清单并重建工具目录。正式交付仍只使用版本 TXT，旧批次维持原摘要，新范围新建批次。
