# UI 技能使用复盘与框架回归

本记录汇总一轮 CSP＋HISUI 改造及后续局部修复中的技能使用。来源样本为一个项目的一组页面和本次会话；只提炼已查证机制及执行偏差，不据此宣称所有工程存在相同缺陷或框架已经提效。工程截图、需求台账、连接、身份、原始页面清单和部署快照留在源项目。

## 本次执行偏差与修正

确定的局部控件配置被按上一轮复杂布局改造的强度执行；“按主题、宽度、状态选择”和“页面行为才走浏览器”又被机械拼成额外矩阵。偏差主要在执行判断，共享协议与 UI 入口缺少足够明确的普通小改动结束口径。

[共享测试协议](../../agents/_shared/testing-protocol.md#验证范围与停止条件)统一规定按实际差异和剩余风险选检查：已知局部调整可完成必要静态检查后交付；动态布局、交互和状态风险选择相应运行场景；数据、权限、接口和设备契约仍沿原运行层级。有效证据复用，选定检查完成且无新增风险即停止；工具故障先与产品缺陷区分。

iris-ui skill/rule 只引用该唯一规则。前端控件状态检查限定本次实际改变的表现，局部容器调整不自动触发全部控件状态。普通静态交付不等于运行通过，受管夜跑 UI 最低层级及部署核验保持。

## 证据边界

- 公司两套规范已有原件/标注依据，通用层原规则保持；未把公司资料或业务 CSS 复制到适配插件。
- 预览案例有四份模板、两风格的匿名坐标与替换检查，并有用户对该批视觉改造的通过结论；实际打印设备及其它模板不由此验收。
- 空工具栏机制由当前 HISUI 源码及匿名组件几何核实；局部代码已改与已部署、实页已通过分别记。本地工具另有未归因诊断异常，未作为产品缺陷或扩大业务修复。
- 本次验证范围纠偏来自单次使用反馈；尚无升级后真实宿主、跨模型或前后耗时对照，不给出节省比例。后续沿既有 P2 UI 使用观察，不增加平行队列。

- 定向检查：文档部署链接/技能归属、UI 依赖与条件路由、夜跑最低验证层级三个现有专项各1项通过；`git diff --check` 通过。没有为纯指导文档重跑薄索引、浏览器矩阵、业务测试或完整安装更新回归。
- 一次独立只读差异审查及四场景试读通过：已知工具栏配置采用轻量交付；共享尺寸/侧栏回归取得对应运行证据；一行保存/权限变更仍验证契约与副作用；受管夜跑 UI 保持既定运行层级。试读不是实际宿主执行或提效对照。
- 工作树组件版本校验识别两个正常 PATCH 和兼容依赖；全仓仍返回三份既有 xc 发布记录缺 commit 的6条历史错误，本轮未改变这些记录且无新增问题，不宣称全仓门禁通过。后续获得提交授权时仍需按实际 index 执行 staged 门禁。
- 本轮实施范围为 canonical 源仓维护，后续用户另行授权提交与推送；实际结果以 Git 记录为准，不隐含业务副本更新或远端部署。正常更新仍沿根 capability 后模块 `-NoPull` 的既有流程；未手工修补部署态副本。
