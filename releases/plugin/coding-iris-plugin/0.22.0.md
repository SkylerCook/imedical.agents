# 接入 IRIS XML 双通道导出与代码基线

新增 iris-xml-export 与 iris-code-baseline，统一对象范围、当前实例源码及项目分支编排。XML 专用类与原生系统执行通道均去除 QTZ 依赖；基线只采代码，图片预筛排除并统计，初始缺失保留 partial，受管多会话只在目标资格通过后启用。

沿既有插件与根公共库更新、刷新已启用薄索引取得。可选服务端类需单独准备和授权部署，普通更新不连接服务器、覆盖类或启用多会话；项目增补清单、私有配置和恢复状态保持。全局旧技能按明确范围单列迁移，源仓实现不代表业务副本、真实 IRIS、License 或跨平台验证已经完成。

新可选类使用 Dispatch/GetExportInfo 受约束协议；目标外部既有同名 XmlPackage 的旧导出／导入签名不兼容，部署前必须查调用方并核验迁移及恢复方案。本版此前未承诺该外部接口，更新器不替换服务器实现。

## Migration

本版收紧已有 source-sync 的读取与 partial 行为，`0.x` 按 MINOR 发布 breaking 变更：

1. 更新完整 owner、根公共库和 vendor，保留项目私有配置及原断点。source-sync 已改用受管 read-pool；超过 5 个文档时，旧 `bulkQualification` 仅有状态和证据文件不再足够，必须补齐新的 `readBatch.qualification` 内容绑定证据。
2. 在获授权窗口以明确的最小范围、会话数、间隔和预算运行资格试验；回执先保持 pending。独立核对真实资源占用、所有自有会话退出及回落，审查通过后才登记 verified。新证据绑定 Atelier 通道、目标和配置指纹、读取运行时指纹、服务器版本／实例、会话／间隔／文档上限及内容摘要；不能仅把旧 JSON 字段改成 verified。每批从同一会话读取 serverInfo，绑定变化时重新核验。
3. 日常同步对已有服务器基线的对象返回 404 时停止，不再将其直接当删除。初始 partial 保留 `excludedReadItems`；存在成功子集时须审阅完整排除清单，并在已有本地提交授权下将当前 `partialAcceptanceToken` 传给 `apply --accept-partial <token>`，只应用已核验成功项。
4. XML 原生执行默认使用同一个受管 MCP 进程中的 WS terminal，须通过 API v7／IRIS 2023.2+ 及目标资格预检；32KiB UTF-8 命令上限之外选专用类。显式 `--executor mcp` 才使用 HTTP iris_execute；该 vendor 通道可内部尝试最多 3 次，须有 `qualification.channels.mcp.acceptInternalRetries=true` 的适用资格并在回执披露，不能当作自动 fallback。
5. 未知远端结果先核实资源和原服务器任务，并按现有 iris-remote 的 status／reconcile 流程恢复公共 owner，再 inspect 原任务；本机 `recover-lock` 只恢复本地计划锁，不解除公共熔断。现有恢复资料保留，不自动升级或删除。

commit 记录实施前基点；最终提交归属及验证结果以维护日志和 Git 记录为准。
