# BOS 查询角色与上游参数支持

通过既有 CLI / bos_demand_query 开放上游声明的全部 18 项 string 和可选 body，新增发起人、接受人、接受组查询。普通列表至少有一个人员或组条件，显式空 cuser / cgroup 可以分别清除默认当前人/组；多项明确条件继续组合，不自动扩大请求。未给人员/组口径时保留个人默认值，默认身份缺失停止，避免意外变成整组查询。

body 仅透传 JSON 对象，不推断其内部协议；非空且非 "0" 的 explain 原样交给上游，返回不做本地列表过滤或排序。真实服务的取值、权限、日期边界与完整性仍需独立验证，不以合成测试或 schema 声明代替。

## Migration

此前 cuser: "" 表示回落到默认本人；升级后表示明确清除当前人限制。旧调用需要继承本人时应省略 cuser；默认“我的待办”的省略参数调用与 cgroup 的显式空字符串行为保持原样。按发起/接受人员或纯组查询时，明确清除不需要的默认 cuser / cgroup，以免形成额外交集。
