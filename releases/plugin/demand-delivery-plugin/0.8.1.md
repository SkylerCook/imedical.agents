# BOS 补录与 Git 发布解耦

验收默认先提交推送再补 BOS 日志；自身及 parent 子项的 pending/failed/running/unknown 日志均不阻塞 push。全部约定 Git 动作成功后释放发布权与 checkout 写入占有，保留日志交付者和原实仓选择；部分 push 继续串行保护。BOS 授权在自身阶段校验，实仓门禁、未知结果核对和完整交付条件保留。

正常更新完整能力包并刷新已启用索引。旧 v1/v2 的 schema、scopeHash、授权和回执保持，首次状态写入释放已完成 Git 的占有；原日志先于 push 的顺序仍可续接。无需配置迁移、旧文件清理或自动重发，业务副本未自动更新。commit 记录实施基点。
