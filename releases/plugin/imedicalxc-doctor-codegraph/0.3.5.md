# 前端链路索引补齐页面内联脚本函数体

页面把初始化函数和事件 handler 直接写在 HTML 的内联 `<script>` 里时，请求写在函数体中，旧扫描只从内联块抽 `appPath` 等前缀常量，整段函数体不进索引：`ipcare/oeord/html/patorderview.html` 的 `initServerObj()`（顶层第 112 行调用）发出 `/ipcare/oeord/ipCareInPatOrderView/getInitViewData`，但链路库里没有任何入口，影响分析只能判成「无前端入口」。

## 变更

- `scripts/front/html_scan.py`：新增 `_inline_script_blocks()`，对每个非 `src` 内联块复用 `js_scan.scan_text()`，保留 functions / bindings / toolbar / config_calls / inline_elements，`_shift_lines()` 把行号换算成页面文件行号；`scan_page` 输出 `inline_scripts[]`（前缀常量仍输出到 `inline_constants`）。
- `scripts/front/build_front_chain_db.py`：`ChainBuilder` 以 `<页面>#inline#<块序号>` 把内联单元注册为页面私有脚本（函数、常量、绑定、配置调用同表），`effective_scripts + inline_units` 参与 handler 解析、页面加载探索与常量回填；`chains[].path[]` 的内联步骤带 `inline=true`；未被页面装载的脚本判定把内联单元视为已装载。
- `scripts/query_front_back_chain.py`：`uiEntries[].jsPath[]` 保留内联步骤（`file` 指回 HTML 文件，`inline=true`），不再因 `#inline#` 伪路径不是文件而丢弃。

## 界面归属分级（0.3.4 后的代码增量，随本版本发布）

`query_front_back_chain.py` 给每条界面证据打 `attribution`（`direct` / `load` / `indirect` / `heuristic`），提交级与 `meta.stats` 汇总为 `uiAttribution`；commit-report 的 eval pack digest、`uiCounts`、报告「界面证据」行与评级口径（只按 `direct` 判「页面上有可操作入口」）同步消费。旧 `front-chains-<label>.json` 无该字段时按缺失处理。

## 实测（2026-11-23 全量重建，前端检出 a21984e3）

- 1,564 页 / 5,825 个内联块 / 12,356 个函数入库；带内联步骤的 page_load 链路新增 3,900 条（`getInitViewData` 6 条：patorderview / patinfoview / patorderviewnurse / mhint.patinfoview / opdoc.integrated.treat / doc.surgeryord）。
- 未解析 handler 1,753 → 1,460；可达函数 46,357 → 47,839；链路 43,344 → 49,990（同期前端检出 b2f3104 → a21984e 亦有源码变更）。
- 新旧链路差集：移除 70 条，其中 68 条所在页面或其脚本在两次检出间有变更（`__jsstr_<line>_*` / `__toolbar_<line>_*` 键随行号变化），2 条（`alltest.html::submitForm`、`restapitest.html::sendRequest`）由跨文件误配改为页面内联同名函数，属预期收紧。
- 产物：`front_chain_db.json` 84.4 → 93.0 MB，`front_chains.jsonl` 35.5 → 42.0 MB。
