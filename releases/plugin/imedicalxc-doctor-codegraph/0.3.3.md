# 方法图补扫 hiscfsv 公共配置子仓库，BLH 继承链不再断在 jar 边界

周报复核发现：`hiscfsv-ipcare-doctor` 的 `BusInterfaceConfigAbstract.findLinkSubValByCode` 改动（24ce958c）取证结果为 `not_in_graph`，报告只能写「无页面入口证据」。根因是 Step 2 只扫 12 个业务子仓库，业务模块按 BLH 类型直接调用的 `hiscfsv-*` 实现不在图上——`@Resource BusInterfaceConfigBLH` 这类 jar 级调用变成悬空边，反向 BFS 没有起点。

- `config.py` 新增 `HISCFSV_SCAN_REPOS`：Tier 1（与业务仓库同名）hiscfsv-ipcare / opcare / opreg / curc / ma / tr，Tier 2（跨模块公共）hiscfsv-bsp / papat / mr / phin，共 10 个子模块。方法与 classpath 一致的命名范围，不整仓扩扫。
- `build_method_graph.py` 的 `build_graph()` 改为 `WORKSPACE_REPOS + HISCFSV_SCAN_REPOS`（两遍扫描共用同一列表，父类索引覆盖新增仓库）；`_infer_service` 增加 `hiscfsv-mediway → hiscfsv`，模块名沿用既有 `SERVICE_MODULE_MAP['hiscfsv'] = hiscfsv-mediway`。
- 不进入 `WORKSPACE_REPOS` / `WORKSPACE_SERVICES`：hiscfsv 仍是公共配置服务，在穿透口径里保持外部叶子，不改变「工作区业务仓库内部调用」的契约。

实测（24ce958c）：

|---|---|---|
| 取证来源 | fallback，`confidence: none` | graph，`confidence: graph` |

| 界面证据 | 无 | 69 条，含门诊结算「保存(F10)」、挂号 `opreg/adm/opregist`、审核医嘱 `saveOeOrdItem` |
