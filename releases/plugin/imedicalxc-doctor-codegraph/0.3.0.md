# 医生站调用图索引插件补齐链路探索取证：前端源指纹、常量反查与需求单元归并

针对周报链路探索缺陷（案例 53 配置类提交 0 入口、前端转介页不在链路库、同需求兄弟提交证据不互通）整改取证链：

- **前端链路库源指纹**：`scripts/front/config.py` 新增 `source_fingerprint()` / `warn_if_stale()`，`html_scan.py`、`js_scan.py`、`build_front_chain_db.py` 启动时比对 `HEAD` 与本地 `origin/master` 并告警（不自动 fetch）；`front_chain_db.json` 的 `meta.source` 记录 `head` / `originMaster` / `checkoutStale` / `capturedAt`，`front_scan_stats.json` 落 `source_head` / `source_head_date` / `source_origin_master` / `source_origin_master_date` / `source_checkout_stale`。
- **提交级覆盖判定**：`query_front_back_chain.py commit-impact` 增加 `meta.frontChainIndex`（`builtAt` / `coveredUntil` / `checkoutStale` / `source` / `commitsAfterIndex` / `commitsUndetermined`），每条提交输出 `date` / `frontIndexFresh` / `uiGapReason`（`index-stale` / `sibling-only`）；索引无源指纹或提交晚于覆盖点时在 stderr 告警，避免把「索引旧」写成「无页面入口」。
- **需求号变更单元归并**：`query_commit_impact.py` 与 `query_front_back_chain.py` 解析 subject 中的 `BOS<数字>` / `【需求: <数字>】` / `需求: <数字>` 为 `unitId`（采集产物缺 `unitId` 时回退 subject 正则）；`meta.units` 汇总同需求多提交，`uiEntries` 为空的提交注入兄弟证据 `siblingUi`。
- **常量类反查**：`query_commit_impact.py` 对 `skippedFiles` 中路径含 `/constant/` 且未入图的变更解析 `ST_CODE` 与常量字段（支持 `CommonConfigItemUtil<T>` 等泛型包装）及配置项名字面量，跨后端仓库 `git grep` 消费点 → `analyze_method` 上溯入口 → 并入 `entrypoints`（带 `reverse=<消费方法>`），`confidence=partial-reverse`；结果写入 `commits[].reverseProbe` 与 `meta.stats.reverseProbeCommits` / `reverseProbeEntrypoints`。
- Skill 文档同步：codegraph-search 查询 7 / 8.1 的 schema、口径与边界（含 msup 药房 `*ClientController` 静态索引边界），front-gen 增加「前置：源码新鲜度」与覆盖点说明。

本次为新增字段与查询口径扩展，既有索引可继续查询（仅缺新字段）；建议重建后端索引与前端链路库以启用全部整改项。
