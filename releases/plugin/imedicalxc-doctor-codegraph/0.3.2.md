# commit-impact 界面证据上限放宽，避免组内页面被挤掉

周报实测发现：一次提交有 55 个后端方法组时，`commit-impact` 默认 40 条上限让「每个后端方法轮流取一条」的第一轮就已超额，同组第二个页面起全部被丢。医嘱保存链路（`IpCareOeOrdItemEntryHandleController.saveOeOrdItem`）排在组内第 3、4 条，导致医嘱录入页（`doc.oeorder.iplistcustom.new.html` / `oplistcustom.new.html` 的「审核医嘱(S)」）在周报证据里消失，只剩组内第一条门诊结算「保存(F10)」。

- `--max-ui-entries` 默认值 40 → 400。超出上限时仍按后端方法轮转均分；正常提交（入口命中 < 400 条）不再截断，全部命中页面保留在 `front-chains-<label>.json`。
- 同步更新 `imedicalxc-doctor-codegraph-search` SKILL 查询 8.1 的参数说明。

下游影响：`build-eval-packs.js` 的 `evidenceDigest.ui` 每页只取一条、最多 4 条，包体积不受上游条目总数影响；`front-chains` 产物增大约 2–4 倍（MB 级），仍只由评估包切包脚本消费，不读入主上下文。
