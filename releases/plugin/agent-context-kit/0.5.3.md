# 宿主发现依据与项目规则路由

`coding-agent-adaptation` 新增 `references/source.md`，集中记录宿主形态、项目技能目录、项目规则 MD、配置/版本条件、官方来源与本机历史探索的脱敏边界。技能和 runbook 通过引用使用同一依据；未知项由用户说明，用户级路径不能推导项目路径，目录 Check 不代表项目规则加载。

纠正“缺少品牌 MD 即缺少规则”和 WorkBuddy 用户级目录可直接当项目目录的推断。对当前命名 adapter 与官方发现路径的已知差异，先核对目标机制，再复用显式自定义目录能力，不自动变更已有链接。

`project-context-maintenance` 补齐规则路由的落地与完成判定：引用的索引或专项入口必须存在，触发条件明确，受影响链须走查到真实正文；初始化和优化引用同一流程。复用等价索引或小工程直接路由，模板明确工程任务先读索引，文件链走查与客户端实际加载分层报告。

本轮未改变脚本参数、默认映射、安装/更新器或兼容入口创建行为，不创建 CLAUDE.md / CODEBUDDY.md，不修改个人配置或 Git 设置。已部署工程正常更新能力包即可取得指导，现有 thin-index 继续引用源 skill；规则路由在授权的项目上下文维护中定点修复，普通更新不覆盖 AGENTS、规则或 profile，无新增配置或旧文件清理。commit 为本轮实施基线。
