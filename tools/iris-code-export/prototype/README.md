# 项目源码基线交互原型

待验证的问题：一个医院/项目持续维护同一份当前基线，区分增补、重新采集检查更新和历史记录；普通操作无需理解批次、试读或 Cookie。

这是可丢弃的设计原型，不是正式 GUI，不连接服务器，不修改源码、不持久化数据，也不随工具 ZIP 分发。读取用户选择的 TXT/XML 仅用于本地演示。

从仓库根执行：

```powershell
node tools/iris-code-export/prototype/serve-prototype.js
```

打开 `http://127.0.0.1:4387/`，Ctrl+C 停止服务；也可双击 index.html。当前只有一版基线工作台，不再要求选择 A/B/C，左右方向键恢复普通输入行为。旧的 variant=A/B/C 链接统一进入本版。

用户确认的融合方向：A 的基线工作台为主体，B 的文件拖入/粘贴直接增补为主入口，C 的文件分类、搜索和筛选融入同一工作区。左侧增补和浏览，右侧显示当前基线、常驻进度计时及文件列表。2026-11-04 已按用户认可方向接入正式 WinForms 源码，实际入口与依赖边界见 [GUI 使用说明](../GUI.md)。

三版比较稿只读保留在 `history/2026-11-03-three-layouts.html`，用于设计追溯，不由当前预览服务提供，不作为第二个维护入口。统一原型随原生工具实现一同维护。

场景可选日常基线、增补中、发现服务器变化、认证失败。支持粘贴/导入、同范围去重、原目录增补、检查更新后的内容对比与接纳、暂停继续、结果筛选、复制对象名、历史记录。原型中的版本范围与源码内容都是示例，不代表正式版本清单。

重点检查：错误摘要是否一眼可见、日志是否按需展开并在认证失败时自动展开、清单默认至少 8 行且可调整高度、同一个基线目录是否始终明确、检查时间与内容更新时间是否能区分。

原型是保留的设计比较材料，仍只使用示例数据；正式 GUI 复用原采集器并增加持久化项目索引，二者的运行和数据边界不同。不将此 HTML 当作生产采集代码。

进度与计时：结果列表上方的常驻任务条显示处理数量、成功/未找到/失败和用时；暂停停止计时，继续累计，结束后保留。导入 TXT/XML 时，导入框单独显示 FileReader 读取进度、识别和去重数量及读取/解析耗时。原型采集进度为模拟，清单读取耗时为本地实际测量。

统一版已在浏览器核对类型与名称组合筛选、完整名称复制、重复及已有对象跳过、同目录增补结果、暂停计时和认证错误自动展开；1100px 与 700px 窗口未出现页面横向溢出。Console 无错误，Network 仅请求本地 HTML。这些验证只覆盖示例交互，不代表正式采集或持久化已经实现。
