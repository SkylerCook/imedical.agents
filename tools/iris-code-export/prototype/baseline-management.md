# 项目源码基线管理设计草案

状态：用户已认可统一原型并授权接入。2026-11-04 已沿现有 C# WinForms / PowerShell 引擎接入项目基线工作台，不增加现场运行依赖；单目标小批只读实际验证增补与检查更新，Win7 / Win10 真机兼容仍待验收。原型保留为设计历史。

## 推荐模型

**一个项目长期维护一份当前基线；每次采集有独立、可追溯的记录；需要交付时生成一份完整的冻结副本。**

项目可以是医院或明确的工程。项目内按实例、环境和 Namespace 隔离源码，界面使用人能识别的环境名称。更换来源不能沿用旧基线悄悄混入源码。输入来源与采集记录不是新的项目，也不要求用户管理多个 batch 文件夹。

## 用户只需理解三种动作

| 动作 | 什么时候用 | 如何处理已有文件 |
| --- | --- | --- |
| 增补源码 | 粘贴对象名，加入 TXT / 源码 XML / 版本范围 | 范围合并去重，默认只补新对象及需要补取的对象；已有完整文件不重取 |
| 检查更新 | 想知道服务器是否有改动 | 在所选范围内重新读取，用内容 SHA-256 比较；先显示新增、修改、未取得和未变化，再接纳变化 |
| 导出交付副本 | 发给别人、带回离线开发、保留一个确定版本 | 从当前确认的基线生成一份完整源码和说明，不要求合并多次采集目录；以后增补不改变这份副本 |

不把“试读/正式导出”拆成两个任务。普通导出默认单会话，第一项读取和落盘检查在同一次采集里完成，正常后自动继续。中断后显示“继续上次采集”，不要求用户选择 job.json。主动选择多会话加速时再说明所需资源资格；未知会话不能靠界面确认自动视为已经释放。

## 稳定目录

```text
项目基线/
  正式环境/                   # 单环境时可以直接使用项目根目录
    src/                      # 唯一的当前源码树
    基线说明.txt              # 来源、登记范围、取得情况、时间
    未取得对象.txt
    .export/                  # 工具管理，日常操作不要求用户理解
      当前对象索引
      各次采集的范围和结果
      更新前后版本及恢复信息
  测试环境/                   # 仅实际配置多环境时出现
```

每次粘贴、导入、重试或检查更新都落在同一项目/环境下。内部采集可以有新记录或暂存位置，但不再制造需要用户合并的新交付根目录。初期复用文件回执、清单及变更前后内容保存；不要求现场安装数据库或 Git，不复制一套采集引擎。

## 增补、更新与时间

- 所有输入合并到同一个对象范围，保留来源记录。大小写或落盘路径冲突必须说明，不能任意覆盖。
- “增补”不保证已存在对象是服务器最新版；要验证已有对象必须重新读取，或取得可信服务器版本证据。
- 单独记录每个对象的**最近检查时间**和**内容更新时间**。内容相同只更新检查记录，不强行改文件时间来制造“已更新”。全范围检查与局部增补分别标注，避免局部采集冒充全库刷新。
- 重新采集时先保存候选结果和差异。用户接纳后更新当前基线，保留旧版和采集证据；中断能从记录恢复，不发布无法解释的半更新状态。
- 远端返回 404 不等于对象删除。已有文件保留为旧版并标明“本次远端未取得”；以前从未取得的对象继续列入缺失。
- 读取失败、空内容和本地文件改动分别报告。本地摘要与当前基线索引不一致时，停止覆盖该对象，允许保留本地或另存服务器版；不自动合并源码。
- “本轮不再补取”只结束当前采集的重复尝试，不永久排除下次明确的检查更新。真正移出长期范围是独立的显式操作，也不自动删除已保存文件。

## 一次检查更新的结果

```text
已检查 557 项
未变化 550；新增 1；服务器修改 3；未取得 3
其中 1 个修改对象也有本地改动，需要单独处理

[查看差异]  [更新可接纳的 3 项]
```

示意中的新增和修改数量允许存在本地冲突子集，界面应明确可接纳数量与仍需处理数量。示例不作为现场统计。无变化也显示“已重新检查，内容未变化”，而不是仅保留旧文件时间令用户猜测。

## 界面原则

主界面只突出项目/环境、当前文件数量、最近检查、未取得/待处理、稳定目录，以及“增补源码”“检查更新”。错误原因和下一步操作在主内容区常驻；详细日志可以折叠，但错误时自动展开，不能用折叠替代错误提示。粘贴清单至少 8 行且能调整高度；对象名称可直接选中和复制。

更新历史展示“什么时间、增补或检查了什么、发现多少变化、是否更新当前基线”。内部 run ID、Cookie、回执 JSON 和手工批次选择放进诊断层。恢复、缺失补取和会话退出继续由工具衔接。

## 进度与耗时

结果列表上方保留常驻任务条：当前操作、阶段、已处理/总数、成功/未找到/失败、百分比、本次用时；暂停冻结计时，继续累计，结束后不清空。历史采集保留各自的耗时。进度代表处理完成度，不等于全部源码已取得。

导入清单是另一段本地操作：在导入框显示字节读取进度、识别/去重数量及读取和解析耗时；随后连接、采集和落盘核对由任务条接续。首次检查包含在同一次任务中，既不另建目录，也不把计时重置成另一个批次。

## 与现有能力衔接

现有人工 exporter 已有对象规范化、Cookie 复用、原子保存、SHA-256、逐项状态、范围/目标/运行时绑定与断点保护，可继续复用。当前 Resume 主要跳过已有且摘要一致的文件，并不检查远端已发生的变化；“检查更新”必须使用独立采集记录，不能假装由 Resume 完成。

已有 source-delivery 的 `.baseline` 是离线开发时冻结的原件，Prepare/Pack/Verify 保护它不被改变。新设计不改写这层语义：持续维护的项目基线与已经交付给开发者的原始副本分开。交付时生成独立范围和回执，再复用既有离线准备与核对流程。

实现入口为同目录上级的 ExporterWorkbench.cs / ProjectBaseline.cs，使用说明见 ../GUI.md。后续补 Win7 / Win10 实机、真实高 DPI 和大范围中断恢复证据；只允许使用现场已有依赖，不自动安装或升级组件。旧批次仍沿原工具恢复，不自动接管普通非空目录。
