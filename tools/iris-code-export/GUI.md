# 医院源码导出 EXE 使用说明

适合需要从医院 IRIS 取回源码、按版本导出或临时补取几个对象的同事。全程在窗口内操作，不需要输入 PowerShell 命令，也不必自己创建清单 TXT 或批次文件夹。

工具只读取服务器源码，不导入、不编译、不修改服务器对象。版本代表“取哪些对象”，取得的是当前服务器内容，并不是恢复该版本历史上的源码。

## 先选你要做的事

| 你要做什么 | 操作入口 |
| --- | --- |
| 第一次使用 | 按下面“首次配置”和“小批试验”操作 |
| 导出某版本的完整清单 | “导出范围”选版本，取消“小批试验”，点击“预览并开始” |
| 只补几个类、程序或 JS | “导出范围”选“粘贴的对象清单”，在大输入框每行粘贴一个对象 |
| 本批有 missing，想用第一档复核 | 点击“单会话补取 missing”，核对预览后确认 |
| 上次没导完，接着导 | 点击“继续已有批次”，选择原批次里的 job.json |
| 正在导出，想停下来 | 点击“安全停止”，等在途请求收束 |
| 今天不导了，释放会话 | 等读取结束，点击“断开并核对退出”，核对结果后关闭窗口 |
| 按钮变灰、提示会话阻断 | 看下面“常见问题”，先核实服务器遗留会话 |

## 1. 解压与打开

1. 将 iris-code-export-gui.zip **完整解压**到一个独立目录。
2. 双击其中的 IRISSourceExporter.exe。不要在压缩包里直接运行，也不要只复制 EXE；脚本和 catalogs 文件夹必须一起保留。
3. 点击窗口里的“使用说明”，可随时用记事本打开本文。

运行电脑需要 Windows PowerShell 5.1 和 .NET Framework 4.5 或更高版本，不需要安装 Node、Python、Git 或 AI 工具。如果在远程桌面里访问医院，就在远程桌面里运行本工具。

## 2. 首次配置：每个框填什么

| 界面字段 | 怎么填写 |
| --- | --- |
| 医院配置 | 自己起的连接名称，如“某医院测试环境”。不是医院编码，也不会自动创建服务器配置。以后可以从下拉框选回已保存的连接。 |
| Atelier URL | 向管理员取得完整接口地址，带 http:// 或 https://、实际端口，以 /api/atelier/ 结尾。不能填医生站登录页面地址。 |
| Namespace | 要读取源码所在的命名空间，由现场确认；同名对象在不同空间可能不同。 |
| 用户名、密码 | 当前服务器允许读取源码的账号和密码。密码默认隐藏。 |
| 记住密码（本机加密） | 可选。勾选后点击“保存连接配置”，下次不用再输密码；仅当前 Windows 用户可解密。取消勾选并再次保存，会移除已保存密码。 |
| 保存根目录 | 点击“浏览…”选择本机磁盘目录，所有新批次会自动放到这里。可以重复使用同一个根目录，不需要每次起文件夹名。 |

填好连接、医院配置名称和保存根目录，点击“保存连接配置”。保存并不等于连接验证，真正验证通过小批试验完成。保存的内容包括连接和根目录；版本、速度和预算确认每次仍需核对。配置保存在当前用户 LocalAppData/ImedicalSourceExporter，不要把这个目录作为源码交付材料。

## 3. 速度怎么选

**默认保留第一档，第二、三档由你手工选择。打开窗口或切换档位本身不会创建服务器会话；预览确认后才开始读取。**

| 档位 | 会话上限 / 每会话请求间隔 | 什么时候用 |
| --- | --- | --- |
| 安全 | 1 / 200ms | 第一次接触目标环境、尚未确认多会话预算时 |
| 均衡 | 4 / 100ms | 当前目标已经完成四会话试验并核对资源回落后 |
| 快速 | 10 / 50ms | 当前目标单独完成十会话试验和预算核对后；四会话通过不等于十会话已通过 |

现场样本中第三档更快，但出现部分对象本轮 missing、另轮单会话可取的差异。因此第三档暂不建议作为日常首选；missing 应单独核实，不能直接作为对象确实不存在的结论。

间隔是同一个会话相邻请求的最小开始间隔。每个会话同时最多处理一个请求，实际速度还受服务器响应、网络、文件大小和本地保存影响；十会话不保证比四会话快 2.5 倍。

“会话数”不等于实际 License 单元数。管理员应核对服务器 Web Sessions、License Usage 和其它程序占用。工具只限制自己的会话，不管理 IDE、其它电脑或其它工具的连接。

## 4. 第一次：先做小批试验

1. 选好连接、保存根目录、导出范围和准备使用的速度。
2. 保留勾选“先做小批试验（每会话 1 个对象）”。这时只取少量对象：第一档最多 1 个，第二档最多 4 个，第三档最多 10 个；不会把版本清单全部导出。
3. 点击“预览并开始”。预览只解析本地清单，核对对象数量、版本、Web 前缀和速度，确认后才访问服务器。
4. 等试验结束，核对对象结果和日志。小批结束会收束会话；管理员同时核对服务器资源是否回到试验前基线。
5. 多会话核实通过后，取消“小批试验”，勾选“当前目标已验证所选会话预算与资源回落”，再开始正式导出。

预算复选框是你对现场核实结果的确认，不是自动检测。更换 URL、Namespace、账号、密码或速度会清除此确认。没有核实依据时使用第一档；不能只为了让按钮通过而勾选。

小批已经保存的文件可以继续用：取消试验并完成预算确认后，点击“继续已有批次”，选择试验批次的 job.json。也可以点击“预览并开始”另建完整批次，两者不要混淆。

## 5. 导出某个版本的全部对象

1. “导出范围”选择需要的版本：v8.4～v9.1 是医生站范围；v9.2 是全产品清单。
2. 只取版本清单时，大输入框留空。需要额外补充对象时，每行填写一个；版本模式会把它们与清单合并。
3. 核对预览中的 Web 前缀与现场实际路径。需要确认时才勾选“已核对版本 Web 路径”；勾选不会自动替换路径。路径不一致时不要盲目确认，当前显式 Web 映射需按 README.md 命令行入口处理。
4. 取消“小批试验”；多会话时完成上节预算确认。
5. 点击“预览并开始”，确认预览写的是“本轮导出完整清单”，再点“确定”。
6. 状态栏会显示已处理数量、本轮用时；下面对象列表每页 200 项，可以滚动或翻页查看。
7. 读取结束后，点击“断开并核对退出”，查看最终日志和缺失、空内容、失败数量。

这里的“全部”是所选版本清单里的全部对象，不是扫描命名空间内所有源码。文件很多时预览需要几秒钟，预览时间不计入导出用时。

## 6. 补取几个对象：直接粘贴就行

“导出范围”切换为“粘贴的对象清单”，大输入框每行一个完整对象名。例如以下只是格式示例，需换成现场真实对象：

```text
Demo.Order.cls
DemoExec.mac
/webapp/scripts/order.js
```

- 类、程序必须带完整名称和扩展名，不要只写类名的一部分。
- Web 文件要写以 / 开头的完整服务器虚拟路径，不能填本机磁盘路径，也不能只填 scripts/ 后面的片段；前缀请按实际 Web 应用填写。
- 已有 UTF-8 TXT 时可点“导入 TXT”；没有 TXT 就直接粘贴，工具会自动生成清单。
- 核对“小批试验”是否需要取消，否则只会读取每会话一个对象。

点击“预览并开始”会创建一个新补取批次，不会自动合并到旧批次。若对象 missing，先核实名称、大小写、Web 前缀和 Namespace；不要反复下载相同错误范围。切换命名空间后的补取应另建批次。

## 7. missing 怎么补：优先点一个按钮

**missing 可能确实不存在，也可能只是在这次请求中返回了 404。** 补取是再次尝试，不是保证补全，也不意味着原结果一定误报。

### 最简单：一键补取

1. 等当前批次读取结束。只要本批还有 missing，窗口里的“单会话补取 missing”按钮就会可用。
2. 点击这个按钮。工具自动读取本批缺失 TXT，切换到“粘贴的对象清单”和**第一档（1 会话 / 200ms）**，取消小批试验，并在同一个保存根目录下创建新的补取批次。
3. 核对弹出的补取对象数量，点击“确定”。不需要自己创建 TXT、输入路径或手工调整速度。
4. 补取结束后核对结果。成功的源码保存在新批次；仍然 missing 的对象继续写入新批次清单，供核实名称、路径、命名空间或实际是否存在。
5. 如果本次没有其它导出任务，点击“断开并核对退出”。

原批次与原源码不会被覆盖，也不会自动把新源码合并回去。日志会显示补取来源和本次批次路径；交付时保留原批次及有效补取批次。不会自动无限重试，是否再次补取由你决定。

如果你已改了连接或命名空间，先切回原批次对应的连接，再点击补取。上次会话未核实而阻断时，仍须先核对服务器，补取按钮不能绕过阻断。

### TXT 在哪里，什么时候更新

每次实际读取返回结果后，工具在本批次的 **export/missing-objects.txt** 生成或更新缺失清单：

- 只收集 missing，不混入 empty、failed、pending 或 fetched；这些其它状态需要分别处理。
- 类和程序保留完整对象名；Web 文件自动补上导入所需的前导 /。
- 没有 missing 时文件为空，一键补取按钮不可用；续传后的清单按最新结果更新，不沿用已补齐的旧条目。
- 仅本地预览不生成结果清单。强制终止进程可能来不及更新，不能把旧 TXT 当成最新回执。
- TXT 是方便补取的派生清单，原始对象状态仍以同目录 baseline-state.json 为准。

### 换电脑、重开窗口或手动补取

窗口只对当前批次提供一键补取。要补以前的批次：选择原连接，导出范围选“粘贴的对象清单” → 点击“导入 TXT” → 选择该批次 export/missing-objects.txt → 手工选择第一档 → 取消“小批试验” → 点击“预览并开始”。

这里应使用“预览并开始”创建第一档补取批次，**不是“继续已有批次”**：续传会恢复原批次的会话档位，不能把旧四/十会话批次直接改成第一档。旧版本没有自动生成 TXT 时，不要改原回执伪造结果，应从原回执提取 missing 或请维护人员补生成。

## 8. 停止、续传、连续多批

| 按钮 | 实际作用 |
| --- | --- |
| 安全停止 | 停止派发新请求，等待已经发出的请求结束并保存结果；网络超时时可能需要等待。不会删除已经下载的文件。 |
| 继续已有批次 | 选择原批次的 job.json，读取原范围和速度，校验已有文件摘要，跳过一致的已完成文件，再处理未完成项。 |
| 预览并开始 | 新建一个批次。不是续传，也不会覆盖旧批次。 |
| 单会话补取 missing | 自动导入当前缺失清单、切第一档并另建补取批次，确认预览后读取；不覆盖原批次。 |
| 断开并核对退出 | 注销本窗口持有的自有会话并更新回执。读完一批不等于会话已经断开。 |
| 打开结果 | 打开当前批次文件夹。 |
| 处理会话阻断 | 仅在服务器遗留会话及资源已核实后登记依据并解除本地阻断；不会替你清理服务器。 |

续传前确保当前连接和账号对应原批次，不要移动或改写旧批次。续传会恢复该批次的版本和速度，不能用当前下拉框偷偷改变旧批次参数。本地源码被修改会阻止恢复，应保留原始导出，开发时另用副本。

同一个窗口、相同连接和会话设置下，连续新建批次会复用会话，不是每导一批再叠加一套。空闲 120 秒会自动注销，不会发送保活请求。连接身份或会话设置改变时，先收束旧池；退出未核实则阻断后续连接。

关闭窗口时若仍在读取，会先安全停止，并提示请求结束后再次关闭。不要把任务管理器强制结束当作正常退出。正常停止后下一轮用时重新计时，不累计上一轮。

## 9. 结果怎么看、哪些文件要带走

| 结果 | 含义和处理 |
| --- | --- |
| fetched | 源码已保存并通过摘要读回校验。 |
| missing | 本次请求返回 HTTP 404；可能确实不存在，也可能需要再次核实。可点“单会话补取 missing”。 |
| empty | 返回内容为空；单独核实，不能算取得完整源码。 |
| failed | 请求、会话或内容校验出错；先看日志原因，再决定续传或处理阻断。 |
| pending | 尚未处理；小批试验或安全停止后出现属于正常情况。 |
| writing | 正在保存；不能当作已完成文件。 |

complete 表示全部对象取得且退出核对通过。partial 不一定是程序故障：还有缺失、空内容、待处理，或会话仍保留，都可能是 partial。应同时看各项数量及退出结果，不能只看进度条或“已处理”。

```text
你选择的保存根目录/
└─ batch-日期时间-随机编号/
   ├─ job.json                 续传时选择这个文件
   ├─ files.txt                手工/补充对象清单，按需生成
   └─ export/
      ├─ baseline-state.json   对象状态、文件摘要和退出回执
      ├─ missing-objects.txt   可供第一档复核的缺失清单，没有缺失时为空
      └─ …                    实际源码及其它范围记录
```

保留整个批次文件夹，交付时把源码、回执和范围记录一起带走；不要只复制几个源码文件后丢掉批次。批次可能含私有连接标识和源码，仅发给获授权人员；用户 LocalAppData 下的密码配置不属于交付内容。

### 为什么保存根目录里有多个 batch 文件夹？

每次“预览并开始”或“单会话补取 missing”都会创建独立批次；名称里的日期时间表示创建时间，末尾短编号用于避免重名。文件夹多不代表重复占用服务器会话。

例如按“先试验 → 完整导出 → 补取”操作后，可能有三个目录：

| 批次 | 里面是什么 | 怎么使用 |
| --- | --- | --- |
| 第一个：小批试验 | 只取得每会话一个对象，其余仍 pending | 用来验证连接和资源；可沿原档位续传，也可保留后另建全量批次 |
| 第二个：完整导出 | 完整版本清单的处理结果，可能包含 missing、empty | 作为主要源码批次，查看回执与缺失清单 |
| 第三个：补取 | 只处理前一批 missing 中需要再次尝试的对象 | 作为补充材料，与主要批次一起保留；不是一套新的全量源码 |

不要只根据目录时间或数量判断“哪个全部成功”。打开各批次的 job.json 看范围/档位，再看 export/baseline-state.json 的数量和状态。需要继续同一目录时用“继续已有批次”；不要反复点新建来代替续传。工具不会自动删除旧批次。

## 10. 常见问题

| 现象 | 处理办法 |
| --- | --- |
| 点开始提示保存目录或账号不全 | 填写用户名、密码和完整保存根目录；选清单模式时还必须粘贴对象。 |
| 明明选了版本，却只导了几个 | 检查“小批试验”是否仍勾选；取消后续传原批次或新建完整批次。 |
| 开始按钮灰色，显示上次会话未核对 | 重解压或重启不能解决；先让管理员核实本工具遗留会话和资源回落，再点“处理会话阻断”填写方式、时间和结果。 |
| 注销超时，但过一会服务器会话消失了 | 保留原始退出未核实记录，核实服务器确已回到基线后登记依据。不能把超时当成注销成功。 |
| 停止后没有立刻停 | 在等在途请求结束或超时，请保留窗口等待收束。 |
| 版本清单里缺少想要的类 | 在版本模式的大输入框中补充，或切到清单模式另建补取批次。 |
| 旧批次提示运行时/范围不匹配 | 用创建该批次的原工具继续，不要手改回执绕过检查；新版可另建新批次。 |
| 证书或连接失败 | 核对 URL、网络和受信任证书；工具不绕过 TLS 证书校验，也不含旧版 Caché/Ensemble 兼容桥。 |

## 11. 更新工具

先正常关闭旧窗口，再将新 ZIP 完整解压到新目录。当前 Windows 用户的连接配置可继续读取；旧导出批次和创建它的旧工具目录先保留，方便续传。不要把不同版本的 EXE、脚本和 catalogs 混放。

## 构建与维护（使用者可跳过）

源仓执行 tools/iris-code-export/build-gui.ps1，正式 ZIP 生成到 tools/dist/iris-code-export-gui.zip。构建电脑需要 Node 和 Windows .NET Framework 编译器，现场运行不需要。GUI 复用 export-iris-code.ps1，gui-worker.ps1 管理跨批会话。本地模拟回归入口为 scripts/tests/iris-export-gui.tests.cjs，回执分组与中断恢复见 scripts/tests/iris-export-checkpoints.tests.cjs。独立工具不宣称已接入共享框架 IPC。

## 验证边界

- 同一授权目标 v9.2 的第三档（10会话/50ms）全量读取4分38秒，第二档（4会话/100ms）为8分58秒；这是档位对比，同时改变会话数和间隔，且为单次现场样本。第三档已取得文件全部摘要通过，认证10次、10次注销核实，服务器会话11→1（含原门户），刷新后的许可单元为1。两轮存在100个 missing/fetched 差异，抽查其中3个在后续单会话均取得；旧四会话也出现相同缺失数量，根因未定，不能宣称第三档完整性已经普遍验证或将差异归因于并发。
