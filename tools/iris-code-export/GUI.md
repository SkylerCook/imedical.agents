# 项目源码基线工具使用说明

工具只读取当前服务器源码，不导入、不编译、不修改服务器对象。完整解压 `iris-code-export-gui.zip` 后运行 `IRISSourceExporter.exe`。界面继续使用 C# WinForms，采集仍使用原有 PowerShell 引擎，没有新增浏览器或其它运行时依赖。

现场环境仍需 Windows PowerShell 5.1 及其 .NET Framework 前置条件（WMF 5.1 要求至少 4.5.2）；无需 Node、Git 或 AI 工具。启动时检查 PowerShell 版本，缺依赖会明确停止，不安装、不升级系统组件。已具备这些环境的 Win7 SP1 可进入验收范围；Windows 版本名本身不代表已满足依赖。新界面尚未在 Win7、Win10 真机验收，不把本机通过称为三系统均已支持。

## 一个项目，一份当前源码

首次打开“连接设置”，填写项目 / 环境名称、Atelier URL、Namespace 和账号，并选择一个新的空目录。也可“打开项目目录”选择本工具已有的基线目录。URL 填到 `/api/atelier/`。密码可按当前 Windows 用户 DPAPI 加密保存。每个目录绑定来源指纹，更换服务器或 Namespace 应使用独立目录。

目录里 `src/` 是当前源码，`基线说明.txt` 与 `未取得对象.txt` 便于交接；`.export/` 保存项目索引、历次范围和回执、服务器候选及更新前版本。日常增补、补取和检查更新都使用同一目录。工具内部保留独立采集记录，使用者不需要合并 batch 文件夹。

已有其它文件的普通目录不会被自动接管。旧版 batch 继续使用原工具和原路径；新 GUI 的“连接设置 → 恢复旧批次”仍沿旧恢复契约，不会自动迁移或覆盖旧结果。

## 从你要做的事开始

| 你要做什么 | 操作 |
| --- | --- |
| 粘贴对象名补充源码 | 点“增补源码”或“粘贴对象名”，每行一个完整对象名，再点“增补到当前基线” |
| 导入 TXT 或源码 XML | 点“选择 TXT / XML”，可见读取进度、去重数量和耗时；也可将一个文件拖入窗口 |
| 先小批量试采 | 首次增补默认勾选“先试采前”，点“开始试采”；已有基线可自行勾选。默认 10 项，可选 1–100 项；按当前采集速度和解析后的范围顺序取前 N 项，沿用当前目录。结束后点“继续增补剩余项”，完整范围已随记录保存，已取得且未改动的文件自动跳过；失败项会再次尝试 |
| 按版本补充范围 | 点“按版本补充”；版本表示对象范围，读取的是服务器当前源码 |
| 核实服务器有没有变化 | 点“检查更新”；重新读取登记范围，按 SHA-256 对比，先保存候选 |
| 接纳服务器变化 | 双击对象查看本地和服务器候选，点“接纳可更新项”；有本地改动的项保持保护 |
| 保留当前版本 | 点“保留当前版本”；候选内容和回执仍保留在更新记录，本地冲突不会因此冒充已解决 |
| 补取未取得对象 | 点“补取未取得项”，范围合入同一项目目录 |
| 暂停或继续 | 点“暂停”，等在途请求收束；再点“继续上次采集”，或下次打开同一项目继续 |
| 带走一份完整文件夹 | 点“交付副本”，选择当前基线之外的空目录；逐文件核验后保留独立副本 |
| 结束使用 | 点右上角 ×；等待停止、保存和注销，未核实退出会明确提示并保留保护 |

## 增补与检查更新的区别

增补会自动合并完全重复的对象，跳过当前文件已存在且摘要与索引一致的项。自定义清单例如 `Demo.Patient.cls`、`Demo.Tools.mac`、`/app/example.js`。TXT 使用 UTF-8。源码 Export XML 仅提取顶层 Class 名称，不向服务器导入内容；大小写冲突、DTD、损坏 XML 会阻断。ProjectItem 范围 XML 不支持。

默认单会话，首项读取和持久化核验包含在同一次采集中，随后自动处理剩余项，不另建试读目录。清单与目标仍绑定采集回执，不能改写回执绕过摘要不匹配。试采与多会话小批验证共用同一个入口，试采结束自动停下，成功、未找到、失败和用时在主界面展示。多会话试采复用连接；完整多会话采集仍需在连接设置确认实际资源预算，也可切回默认单会话继续，无需再次试采。

检查更新会重新读取，而不只是跳过已有文件。内容相同只更新“最近检查”，保持“内容更新”和文件时间；内容不同先保存候选，确认后更新当前源码并保留旧版。远端 404 不删除已有文件；本地文件摘要变化或文件被删除时保护该项，不自动覆盖或自动合并。

版本 Web 路径仍须按现场实际情况核对。版本范围可能包含当前服务器不存在的对象，处理完成不等于所有源码均已取得。

## 进度、查找和复制

任务条位于结果列表上方，显示当前操作、已处理 / 总数、成功、未找到、失败、进度及本次用时。暂停停止计时，继续累计，结束后保留；更新记录保留历次范围、变化 / 接纳数量与用时。导入清单的读取和解析耗时另行显示。

结果可按范围、问题、文件类型和名称组合查找，每页 200 项。选择行后 Ctrl+C 复制完整对象名；右键可复制所选行详情或全部分页的未找到清单。Web 名保留前导 `/`，可以重新导入。双击对象可只读查看当前与服务器候选内容。大文件从项目目录或采集记录查看完整内容。

当前未完成采集中的 missing 可右键登记本轮不补取；同次续传只跳过原回执中对应的 404，原始缺失不改写为成功。以后明确补取或检查更新仍可重新请求。

## 认证失败、诊断和退出

错误摘要直接显示在主区，诊断详情自动展开。401 先核对凭据和 Atelier 认证配置；只有观察到自有会话且退出响应核实后才允许显式重试。未知 Cookie 或退出状态不确定时仍阻断，不能用“密码错了”推断服务器已经没有会话。

“连接设置 → 核查会话”填写实际核查方式和结果，只登记依据，不自动清理服务器。TLS 问题不通过关闭证书校验规避。读取结束后会话可复用，空闲 120 秒自动注销；“断开连接”主动注销，关闭窗口会先安全收束。退出响应和真实 License 回落分开判断。

## 交付与更新

交付副本包含独立 `src/`、基线说明、未取得对象清单和逐文件摘要；不会复制连接凭据或持续变化的内部采集目录，以后增补不改变该副本。有未取得 / 待处理项时明确标注不完整。本地源码被编辑时，交付先停止，避免把未经核对的修改混作服务器基线。

工具升级完整解压到新目录。旧批次保留原运行时恢复，不自动删除旧工具或改写摘要；新版项目的未完成采集也遵守原始范围、路径和引擎摘要。已经交给开发者的冻结原件及 source-delivery `.baseline` 语义保持独立，离线准备继续沿人工 README 的既有流程。

## 构建与维护

`build-gui.ps1` 在 Windows 构建 `tools/dist/iris-code-export-gui.zip`；构建电脑需要 Node 22.5+ 和 .NET Framework 编译器，现场不需要 Node。界面在 ExporterForm / ExporterWorkflow / ExporterWorkbench；项目索引、候选接纳、发布恢复和交付核验在 ProjectBaseline；网络和会话仍由原 exporter / gui-worker 负责。

专项测试：`scripts/tests/iris-project-baseline.tests.cjs` 覆盖持续增补、检查更新、保护与恢复，并实际跑原生窗体到模拟服务器的完整链路；`scripts/tests/iris-export-gui.tests.cjs` 覆盖采集、会话和原生布局；分组落盘与恢复沿 checkpoint 专项。模拟字体缩放不替代 Win7 / Win10 真机与远程桌面验收。

## 读取引擎的历史验证与限制

- 同一授权目标 v9.2 的第三档（10会话/50ms）全量读取4分38秒，第二档（4会话/100ms）为8分58秒；这是档位对比，同时改变会话数和间隔，且为单次现场样本。第三档已取得文件全部摘要通过，认证10次、10次注销核实，服务器会话11→1（含原门户），刷新后的许可单元为1。两轮存在100个 missing/fetched 差异，抽查其中3个在后续单会话均取得；旧四会话也出现相同缺失数量，根因未定，不能宣称第三档完整性已经普遍验证或将差异归因于并发。

- 已完成响应按组保存回执：先记录整组 `writing` 与预期摘要，再逐文件原子落盘、读回校验，最后保存整组结果；不等待未完成请求，不增加会话数。`checkpointCount` 记录本轮回执保存次数。Windows PowerShell 5.1 本地模拟的同范围单次对照（5352 项清单、读取 200 项、4 会话/100ms、响应延迟 40ms）为 27.9 秒→15.5 秒，耗时减少约 44%；实际收益随服务器和磁盘变化。分组发布前、发布首个文件后强制中断均可恢复，已发布且摘要一致的文件不重复请求，本地改动仍在联网前阻断。
- 一个授权环境完整清单实测读取用时 8分58秒，上版两段读取合计15分59秒（上版含一次超时及续传，两次负载和缺失结果不同，非严格基准）。本轮已取得文件全部独立摘要核验通过，失败/待处理/写入中均为零，认证4次；首次200个成功对象名称与摘要相同，处理跨度35.7秒→18.6秒。退出时3次注销核实、1次超时，工具按预期阻断；后续服务器自行回到原门户会话及许可基线，登记现场依据后恢复。原始退出未核实回执保留，现场核实不改写成自动注销成功。
- 预览路径检查使用直接文件属性读取，仍逐级拒绝链接路径；对象集合避免逐项复制数组。Windows PowerShell 5.1 本机 v9.2 全量 5352 对象的独立预览一次对比为 15.4 秒→4.2 秒，完整版本入口另一次为 2.6 秒；这些是本地样本，不承诺其它机器耗时。预览不创建服务器会话。更新仍须保留旧批次原运行时用于恢复。
- 结果列表每页 200 项，使用双缓冲和变化行重绘；刷新保持当前页及滚动位置，读取回执允许原子替换。续传时界面显示所选批次的范围和会话数，工作器输入显式 UTF-8；日志显示退出收束后的回执摘要。大列表自检及小批验证不替代真实全量导出验收。
- 已识别的 50 字符 CSP token 允许网关可变部分及 MAC 更新，第 9–22 位固定身份、Cookie 作用域必须完全一致；保留最新 Cookie 注销，并统计 cookieRefreshCount，不重新认证。未知格式仍逐值检查。真正身份变化时停止派发并记录摘要、阶段及耗时，不保存 Cookie 原文；退出核对成功才允许显式续传。Cookie 值变化本身不能证明空闲超时或 License 增长。

- Windows PowerShell 5.1 本地模拟验证 1/4/10 会话、跨批认证复用、空闲注销、503、取消、异常进程退出阻断、恢复证据、身份切换及断点续取。10 是客户端会话上限，不是承诺占用 10 个或更少 License 单元。
- 原生窗口自检覆盖 DPAPI 往返、取消密码保存、结果列表和预览。实际窗口已执行预览、小批、两轮连续导出、断开和关闭。
- 一个授权环境已完成单会话小批及四会话连续两批；后者两批认证次数分别 4 和 0，断开后均 complete/logoutVerified=true，文件摘要一致。服务器观察导出期间增加 4 个 Web 会话、重复批次未翻倍、断开后恢复原门户会话基线；这是该环境样本，不代表其它服务器 License 计费规律。此前全量遇到 Base64 HTML 被拒绝，修复后这三个对象已实测成功；修复版全量清单已处理完，失败/待处理均为零；缺失与空内容仍如实保留 partial。期间一次请求超时按安全退出、现场核实、同批续传完成，已保存文件均通过独立摘要核验。
- 本工具的互斥和预算只覆盖本机本用户自己的导出器，不合并 IDE、其它程序或其它电脑的连接。异常断线下无法保证服务器即时释放，工具会保留阻断状态，需要现场核实后登记依据。
- 打包器逐文件校验 ZIP SHA-256；包内 manifest 可核对内容。更新时完整解压到新目录，已有配置保留；未关闭的旧窗口须先退出。旧批次绑定运行时摘要，不能绕过不匹配检查。

## 慢请求诊断

新采集默认在 `.export/runs/<记录>/export/baseline-state.json` 的各对象 `timing` 中记录毫秒级阶段耗时，无需开启日志：`responseObservedMs` 是请求发送至主循环观察到响应体已缓冲完成（包含服务器、网络和客户端调度等待）；`parseValidateMs` 包含响应读取、JSON 解析、内容校验和准备；`writeVerifyMs` 包含写盘、刷新及摘要回读；`totalMs` 为发送到该项处理完成，包含阶段间等待，不包含最终整批回执落盘。失败或未进入某阶段时字段可能为 null，不应当作零耗时。时间使用 Stopwatch，开始时间另外记录 UTC。

计时不增加网络请求或逐事件写盘，随原有回执保存，不记录请求头、凭据或源码。命令行 `export-iris-code.ps1 -DisableTiming` 可用于对照，新界面不增加设置项。该计时不能单独区分服务器执行时间与网络延迟。旧记录不补造时间；未完成的旧批次应使用原包继续，完成后再更换完整新版包。
