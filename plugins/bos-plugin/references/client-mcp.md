# 可选客户端 MCP 注册

日常使用默认是 skill → CLI → 远端 BOS MCP，不要求客户端注册。需要客户端直接发现 bos_demand_query 时，注册本插件的本地 stdio 适配器；它不会创建远端 BOS 服务。

## 服务与配置来源

远端 BOS MCP 服务地址和个人凭据由组织的服务维护方通过既有安全渠道提供。本插件不提供服务器、账号或 Token。按 [个人配置说明](usage.md)运行 bos-init 生成并填写私有配置，或复用已有完整私有配置，再执行 check。连接失败不通过复制他人配置解决。

## 注册示例

以下是采用 mcpServers 格式的客户端用户级配置片段；具体配置位置、外层结构、启用和信任流程按该客户端当前机制核对。不能把通用片段直接覆盖客户端完整配置。

```json
{
  "mcpServers": {
    "bos-demand-query": {
      "command": "node",
      "args": ["<本机框架安装目录>/plugins/bos-plugin/scripts/bos-demand-query.js", "serve"],
      "env": {
        "BOS_MCP_CONFIG": "<本人仓外私有配置文件绝对路径>"
      }
    }
  }
}
```

示例仅包含程序和配置文件路径，不含连接或凭据填写位。标准私有配置保存个人凭据，公司地址由插件管理；客户端 env 只需指向 BOS_MCP_CONFIG。完整旧私有配置也可仅传该路径。GUI 客户端可能不继承终端环境，应使用其受支持的环境/凭据机制，不能把终端验证成功当成客户端配置成功。

在客户端界面手动添加时，类型选 stdio，命令填 node 的可用路径，参数分别填写脚本绝对路径与 serve，环境项填写 BOS_MCP_CONFIG。框架源码安装和项目部署副本均可使用；用户级复用优先选稳定的框架安装目录，避免依赖会被删除的工程。脚本不能使用旧技能目录中的相对路径。

## 初始化与验收

bos-init 默认只处理个人身份或明确的项目接入。用户明确要求注册客户端 MCP 后，先核对目标客户端、已有同名服务、配置文件及其加载机制；准备最小增量配置，保留其它服务和有效身份，不修改未知定制。

注册后按目标客户端机制刷新并查看工具列表，确认出现 bos_demand_query；工具发现与真实查询分开验证。只有查询授权存在时才执行实际 BOS 查询，未验证的宿主明确标记待验。stdio 协议在合成测试中验证，不代表所有客户端均已加载。
