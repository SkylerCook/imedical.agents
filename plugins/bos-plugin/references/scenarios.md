# BOS 处理场景验收

使用合成需求编号 12345，正文示例：“选择产品后只展示有效选项，实际包含失效项”。不使用生产数据；场景不自动连接 BOS、提交业务仓库或部署。

| 场景 | 操作及预期 |
|---|---|
| 默认个人待办 | 省略当前人/组时使用默认本人＋所在组；默认本人缺失且无其它明确口径时停止，不能悄悄变成整组查询 |
| 发起/接受人员与组 | 查询“我发起的历史”或指定接受组待办；复用本人作为正确角色，显式清除不用的 cuser / cgroup，模拟请求核对没有隐含默认交集；六种人员/组条件均可独立或明确组合 |
| 字段说明与不透明 body | 使用上游确认的 explain 值或明确提供的 JSON 对象；原样发送，字段说明不套列表计数，body 不推断内部结构或身份；真实上游语义仍需另行确认 |
| IRIS 标版 | 已启用 BOS 与 IRIS、明确 standard 的隔离工程；复用编号/标题/最终 diff 生成三行提交计划，正文不重复查询 |
| 简单前端 | 仅修正按钮文案或局部样式，需求与文件明确；直达 iris-frontend-coding，由当前 Agent 连续修改、自查和可见状态验证，保留编码及命中领域门禁；不加载总编码入口或正式协作协议、不生成阶段报告 |
| 简单后端 | 仅修正一个方法的边界判断；直达 iris-backend-coding，验证相关边界，远端编译仍需授权；不因单一方法改动检查无关集合或所有调用方 |
| 混合或风险升级 | 前端过滤关联后端返回契约，或调查发现共享逻辑受影响；进入 iris-coding，按领域规则扩大调查与验证；风险升级本身不创建 run |
| 非 IRIS 简单需求 | 仅修改局部文案；沿用项目规范，核对可见结果，不要求填写 IRIS 信息、形式化角色交接或无关临界值/空集合检查 |
| 非 IRIS | 仅启用 BOS 的工程；按项目规范处理，不读取 IRIS profile 或要求 IRIS MCP |
| 不同项目技术栈 | Java + Web、Java + Android 分别使用项目已启用插件的对应入口；插件缺失时沿用项目规范，不要求 IRIS 配置；这些是场景设定，不声明已提供对应插件 |
| Android + IRIS | 只改 Android 页面仅加载相关能力；接口联动才组合双方体系，IRIS 查询、部署、编译沿现有路由与授权执行 |
| 夜跑能力继承 | worktree 引用原项目入口与启用状态；复用上下文，仅将计划所需入口列入 requiredSkills/requiredRules/requiredScripts，不扫描全仓或预加载全部插件 |
| 已启用但无人值守能力不足 | 插件能编码但缺部署、设备或验收能力时，按已有预检缩小自动范围或人工留项；不把 Web 验收当成原生设备验收，不临时新增适配器 |
| 查询失败 | 提供完整正文、使 BOS 配置不可用；继续本地调查与实现，只报告在线资料未核实 |
| 关键截图与附件 | 正文引用截图中的操作和附件中的规则；处理需求时主动读取并纳入实现/验收条件，不等待额外指令，不把链接当作读取证据 |
| 纯图片与相关性不明 | 正文为空但含截图，附件可能包含关键要求；先查看内容再判断，不因正文空或文件名不明确而跳过 |
| 媒体读取失败 | 关键附件访问受限或格式不支持；说明具体缺口，继续独立调查，澄清后才实施依赖部分；事实已充分则说明限制后继续 |
| 媒体证据复用 | 上下文已有确认仍适用的截图/附件内容；直接复用，无关附件不批量下载；仅查询仍按用户需要读取 |
| 无提交授权 | “处理 12345”，随后“验收通过”；不得暂存或提交 |
| 预先授权 | “处理 12345，验收后提交”；验收后展示计划并直接进入既有门禁，不重复询问 |
| 单仓提交后补录 | 本次 demand-commit 返回整体及每仓 verified；仅将返回的 root/完整 commit hash 传入日志 plan，后来产生的新 HEAD 不得进入计划；展示具体计划后才请求 BOS 授权 |
| 多仓提交后补录 | 所有仓库校验成功才进入日志阶段；按提交结果选择全部仓库，在同一次请求中保留每仓文件/hash 和不同说明，不枚举其它仓库 |
| 部分提交失败 | 任一仓提交或校验失败时不自动准备/提交 BOS 日志；保留已成功的本地提交，报告未完成仓库，恢复后重新核实全部结果 |
| 日志配置缺失 | 本地全部 verified，但日志段缺失或 token/linkProject 为 TODO；本地提交保持完成，仅报告日志待办和缺失字段，不借用查询凭据 |
| 日志预授权与拒绝 | 精确预授权“本需求提交后补录这些提交的 BOS 代码日志”时展示计划后直接提交；只有 commit/push 授权仍需具体 BOS 授权，用户拒绝后零日志请求 |
| 仅预览日志 | 明确仅预览本次提交的 BOS 日志时，交付 plan 后停止，不发日志请求、不追加写入授权问题 |
| 日志范围漂移 | 等待授权期间选择、需求或配置变化；重做并核对计划，范围扩大重新确认，不沿用旧计划静默写入 |
| 日志失败与结果未知 | 明确失败保留待补录；超时/断连/不完整响应先核对 BOS，不自动重试、不回滚本地提交、不按某仓猜测成功 |
| 交接恢复与去重 | 复用已有上下文/交接/run 的明确 repo/hash 及日志结果；已确认成功不再写入，未知结果先核实，不另建普通需求状态库 |
| 裸提交技能 | 无预授权地调用 demand-commit；只说明 --plan / --commit 选择，不承诺或执行提交 |
| 按需交接 | 普通处理不产生档案；明确要求交接才调用 task-handoff；正式 run 引用原状态 |
| 多 Agent 不可用 | 按 Markdown 串行覆盖相同阶段；不伪称启动独立 Reviewer |
| 证据不足 | 仅静态检查时远端编译、页面行为标为未验证，用户验收单独记录 |
| 新进程发现 | 读取生成的 thin-index，解析实际 SKILL 和脚本，再执行 defaults；真实宿主发现另行验收 |

自动测试覆盖传输、配置、发现产物、合成 BOS 编号/完整标题到现有 IRIS 标版三行提交计划的工具衔接、隔离 Git 门禁，以及单仓/多仓 verified 结果到日志计划与模拟提交的精确映射；本表中的语言路由、授权理解、失败阶段选择和交接去重需要 Agent 场景轨迹。自动契约检查不能证明真实宿主行为全部通过。

简单需求提效需在同模型、同宿主、同代码与权限下比较优化前后轨迹，检查无效技能/协议加载、重复调查、额外确认和报告、补丁正确性及验证遗漏；记录耗时但不以单次耗时推断普遍收益。该对照只用于维护验收，不加入日常需求流程。

## 标版需求拆分审查场景

以下用于 Agent 场景验收，不把静态文案检查视为真实宿主已执行。

| 输入/事实 | 预期 |
|---|---|
| `--split`；仅一个问题及其测试、Parameter 调整 | 隐含 `--text`，展示审查并保留一条，不强拆 |
| `--excel` 或 `--Excel` | 隐含 `--text`，维持默认业务目的拆分，按需导出 |
| `--split --excel`；两项独立成果、文件可隔离 | 审查价值/范围/验收/代码归属/依赖/理由后，用相同条目生成文本、draft、Excel |
| `--text --split --rev <hash> --excel` 或 `--split --range <base>..<head> --repo <root> --file <path>` | 保留明确来源限制；历史来源仍不能创建提交计划 |
| `--split --bind 123`、`--split --plan`、`--split --commit`、`--help --split`、未知参数、rev 与 range 同用 | 显示用法并停止，不取证、不写入 |
| `--help` | 展示 split、excel 组合与限制，不读取业务仓库 |
| 公共查询能力与业务开关各有独立验收 | 可分条、标依赖，不重复计算公共能力 |
| 业务上独立但共享待提交文件或同提交同文件 | 提供候选文本及片段边界，报告该批 draft/Excel 受阻，不绕过 prepare 或自动拆历史 |
| Excel 缺模块编码 | 先交可生成的文本和草稿，再集中询问必需字段，不虚构 |
| 未传 split | 保留已有按独立业务目的拆分，不强制输出审查表 |

| `--work --split --excel`，没有 Git 仓库 | 按指定工作记录生成文本/v3/Excel，不加载提交依赖；默认调用仍走代码 |
| 会议已开、数据仍待准备 | 记录实际进度，不把新功能写成已实现；目标/内容后按依据写可选预期成果或结果，不强填验收标准 |
| `--work --rev/--range/--repo/--file/--commit` | 用户参数层停止；不能混合来源或伪造代码取证 |
| 工作草稿 bind 后请求 plan/commit | 编号已保存但无代码提交对象，Git 与来源文件保持不变 |
| 有来源文件或仅口述 | locator 保留可核对的来源；bind 均不改原文，来源写回需另行明确请求，口述无来源不回填 |

## 退出夜跑后的串行场景

按[单 Agent 降级契约](../../../workflows/bos-demand-unattended.workflow.md#单-agent-降级)试读并演练：未确认只做规划；确认后逐 GitRoot 建独立工作区，创建失败保持停止；保留原预算/三截止及未知端点；已有代码精确迁移、其他会话修改保留；中断恢复仍定位同一 worktree；自审与独立审查分开。工具夹具只能验证 Git/Overlay 与记录恢复，不能证明真实宿主遵循或无人值守停止能力。
