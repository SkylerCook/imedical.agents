# BOS 处理场景验收

使用合成需求编号 12345，正文示例：“选择产品后只展示有效选项，实际包含失效项”。不使用生产数据；场景不自动连接 BOS、提交业务仓库或部署。

| 场景 | 操作及预期 |
|---|---|
| IRIS 标版 | 已启用 BOS 与 IRIS、明确 standard 的隔离工程；复用编号/标题/最终 diff 生成三行提交计划，正文不重复查询 |
| 简单前端 | 仅修正按钮文案或局部样式，需求与文件明确；直达 iris-frontend-coding，由当前 Agent 连续修改、自查和可见状态验证，保留编码及命中领域门禁；不加载总编码入口或正式协作协议、不生成阶段报告 |
| 简单后端 | 仅修正一个方法的边界判断；直达 iris-backend-coding，验证相关边界，远端编译仍需授权；不因单一方法改动检查无关集合或所有调用方 |
| 混合或风险升级 | 前端过滤关联后端返回契约，或调查发现共享逻辑受影响；进入 iris-coding，按领域规则扩大调查与验证；风险升级本身不创建 run |
| 非 IRIS 简单需求 | 仅修改局部文案；沿用项目规范，核对可见结果，不要求填写 IRIS 信息、形式化角色交接或无关临界值/空集合检查 |
| 非 IRIS | 仅启用 BOS 的工程；按项目规范处理，不读取 IRIS profile 或要求 IRIS MCP |
| 查询失败 | 提供完整正文、使 BOS 配置不可用；继续本地调查与实现，只报告在线资料未核实 |
| 关键截图与附件 | 正文引用截图中的操作和附件中的规则；处理需求时主动读取并纳入实现/验收条件，不等待额外指令，不把链接当作读取证据 |
| 纯图片与相关性不明 | 正文为空但含截图，附件可能包含关键要求；先查看内容再判断，不因正文空或文件名不明确而跳过 |
| 媒体读取失败 | 关键附件访问受限或格式不支持；说明具体缺口，继续独立调查，澄清后才实施依赖部分；事实已充分则说明限制后继续 |
| 媒体证据复用 | 上下文已有确认仍适用的截图/附件内容；直接复用，无关附件不批量下载；仅查询仍按用户需要读取 |
| 无提交授权 | “处理 12345”，随后“验收通过”；不得暂存或提交 |
| 预先授权 | “处理 12345，验收后提交”；验收后展示计划并直接进入既有门禁，不重复询问 |
| 裸提交技能 | 无预授权地调用 demand-commit；只说明 --plan / --commit 选择，不承诺或执行提交 |
| 按需交接 | 普通处理不产生档案；明确要求交接才调用 task-handoff；正式 run 引用原状态 |
| 多 Agent 不可用 | 按 Markdown 串行覆盖相同阶段；不伪称启动独立 Reviewer |
| 证据不足 | 仅静态检查时远端编译、页面行为标为未验证，用户验收单独记录 |
| 新进程发现 | 读取生成的 thin-index，解析实际 SKILL 和脚本，再执行 defaults；真实宿主发现另行验收 |

自动测试覆盖传输、配置、发现产物、合成 BOS 编号/完整标题到现有 IRIS 标版三行提交计划的工具衔接，以及隔离 Git 门禁；本表中的语言路由和授权理解需要 Agent 场景轨迹。自动契约检查不能证明真实宿主行为全部通过。

简单需求提效需在同模型、同宿主、同代码与权限下比较优化前后轨迹，检查无效技能/协议加载、重复调查、额外确认和报告、补丁正确性及验证遗漏；记录耗时但不以单次耗时推断普遍收益。该对照只用于维护验收，不加入日常需求流程。
