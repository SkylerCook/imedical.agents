# BOS Plugin

查询输出默认列表，需求号与完整标题为必需列，待办补预计完成时间、工作量补执行时间及状态，各类默认列表末尾均为发起人、发起组；可指定“只要需求串”或自定义其它列。需求串按编号数值升序、去重、单行半角逗号分隔，均保留简明查询口径与计数，见[输出格式](skills/bos-demand-query/SKILL.md#输出格式)。展示偏好由 Agent 处理，不增加 CLI/MCP 参数或改变查询范围。

0.13.0：`bos-demand-query --todo [日期或范围]` 查询个人开发待办，无日期查全部，提供日期按预计完成时间；`--workload 日期或范围` 按必填执行日期统计个人工作量，单日/范围均含截止当天。接受人确定开发归属，当前人结合状态判断待办或已流转，返工仍为待办，已转他人的挂起计工作量；未知组合单列核对。完整口径见[查询协议](references/usage.md#个人待办与工作量口径)。旧通用查询模式保持兼容，正常更新能力包并刷新已启用索引即可，无私有配置迁移或旧文件清理，不自动更新业务副本。

本插件所有自有 skill 的帮助请求（`--help`、查看用法）先按[统一帮助协议](../../docs/guides/capability-help.md)展示帮助并结束，优先于插件启用、连接检查和业务前置。源定义随正常能力包更新分发，已有 thin-index 继续读取 source；帮助不自动启用插件。

0.12.0：业务拆分与代码归属分开，主子代码草稿v4、显式日志bindings及无代码跳过沿[共享协议](../../docs/demand-code-ownership.md)。子项分别验收和补日志，共用唯一主提交；旧v2/v3草稿和普通select保持兼容。完整更新能力包并刷新已启用索引，不直接补丁项目副本，无私有配置迁移。

0.11.0：`bos-demand-entry` 支持“提需求给某组，解决某问题”或主题加资料的自然语言调用，无需 Git 或额外开关；新主题草稿以 v3 source=request 复用 bug/change 正文、文本/Excel 和编号回填。接收组仅作交接信息，不自动发送、指派或提交；产品标识未知时可先按真实主题命名。结合工作上下文、代码与已有验证判断完成状态，已完成条目通过原 remarks 追加备注，见 [skill](skills/bos-demand-entry/SKILL.md#来源选择与主题提需)。正常更新能力包并刷新已启用索引取得；旧代码 v2/工作 v3 草稿可读，无实例迁移或旧文件清理，不自动同步业务项目。

0.10.3：新夜跑事前生成并批准 executionPlan、周额度基线、逐条最低测试与双开发/双测试 worktree 安排，派发前物理落盘 PLAN 和角色上下文；旧批次不迁移。沿正常更新刷新已启用索引，无额外配置迁移或旧文件删除，见 [治理接入](../../docs/night-governance.md)。

0.10.2：新夜跑按共享 workflow 启用 `night-convergence/v1`，显式总时限及最多 4 次问题尝试，存在依赖才绑定版本和检查；独立需求不增加依赖资料。正常更新并刷新已启用薄索引后只用于新批次，旧 run 保持原行为，无旧文件清理；未自动启动或同步业务项目。接口和限制见[夜跑策略](../../docs/night-policy.md#返修收敛与按需依赖)。

`bos-demand-entry --work --split --excel` 从明确工作记录整理并导出；默认仍为代码来源。工作记录使用目标、内容及可选预期成果/工作结果，进度如实保留，不强制验收标准；回填编号后不进入 Git 提交，不自动修改来源。代码 v2 草稿保持可用，工作记录新增 v3。

`bos-demand-entry --split` 显式审查拆合，`--excel` 导出，`--split --excel` 组合使用；省略模式时进入 `--text`。保留按业务目的整理的默认行为，复用原草稿与导出流程，共享文件边界不绕过。更新能力包并刷新已启用薄索引即可取得，无配置/schema 迁移。

0.9.0：新夜跑使用一个多仓 schema 2.1 run，启动前集中取得必需授权并实际预检；运行中异常分支挂起交接。回执、计时和数据处置接入既有执行器，见[决策接口](../../docs/night-policy.md#schema-21-启动契约)。已有 2.0 run 不迁移；正常更新能力包并刷新已启用入口后，由项目显式接入新 profile，无自动业务写入。

跨插件阶段依赖以 manifest 的 availableDependencies 为事实源；触发时按[可用性依赖协议](../../docs/plugin-availability.md)检查，缺口仅阻塞对应阶段，显式 disabled 保留。

为不同技术栈提供 BOS 查询、需求处理和代码更新日志补录入口。使用 Node.js 内置模块，需要 Node.js >=22.5.0；这是 Agent 工具链依赖，不是业务系统生产运行依赖。版本以 manifest 为准。

| 入口 | 用途 |
|---|---|
| [bos-init](skills/bos-init/SKILL.md) | 初始化个人身份，或接入项目并生成发现入口 |
| [bos-demand-entry](skills/bos-demand-entry/SKILL.md) | 从 Git、提需主题及资料或工作记录生成文本/Excel，回填编号；代码按需衔接提交 |
| [bos-demand-query](skills/bos-demand-query/SKILL.md) | 按发起/接受/当前人员或组查询待办、历史及编号详情 |
| [bos-demand-handle](skills/bos-demand-handle/SKILL.md) | 实施、验证和交付需求，提交校验成功后准备并按授权补录日志 |
| [bos-code-update-log](skills/bos-code-update-log/SKILL.md) | 预览并按授权将已有 Git 提交补录为代码更新日志 |

本次路由说明通过正常更新能力包并刷新已启用薄索引取得，无配置迁移或旧文件清理，不自动同步业务项目。

插件无 IRIS 强依赖。普通与夜跑按当前需求复用项目已启用插件，支持不同项目的不同技术栈及混合体系；新增体系无需修改 BOS 分支，不增加启动扫描或配置。IRIS 项目按范围直达前端/后端技能，混合或边界不明时使用 iris-coding；其它项目沿用自己的规范。简单任务由当前 Agent 连续修改、自查和目标验证，正式协作资料按条件加载，具体分流见 [bos-demand workflow](../../workflows/bos-demand.workflow.md)。

0.3.0 接管标版需求补录，产品标识由项目约定或用户明确提供；本地文本/Excel 不要求查询凭据。提交按需复用 demand-delivery-plugin。旧入口由更新器迁移，已有数据协议继续兼容，更新和接入见 [迁移说明](../../docs/demand-delivery-migration.md)。源仓修改不会自动同步业务工程。

处理需求时主动读取影响理解、实现或验收的截图和附件，复用已有证据；关键资料无法读取时说明缺口并澄清后再实施依赖部分。仅查询详情仍按用户需要读取媒体，具体约定见上述 workflow。

首次接入从 bos-init 真实路径开始。个人初始化不启用项目；项目接入也不代替个人凭据填写。查询与代码更新日志共用 BOS_MCP_CONFIG 指向的仓外文件，按 skill 名分段且凭据独立；[使用说明](references/usage.md)定义优先级、TODO 填写与离线核对，defaults 成功不等于身份完整或真实连接可用。[接入与迁移](references/adoption.md)包含项目与用户级接入步骤。普通框架更新只分发能力，不启用插件、不修改个人配置或客户端。

示例：“查看 BOS 12345 的详情”“处理 BOS 12345”“处理 BOS 12345，验收通过后提交”。只要求查询时不会改代码；只说验收通过不会自动授权提交。

夜跑可直接调用 `$bos-demand-handle --night 12345,12346`，或自然语言说明“今晚处理这些需求”。Agent 复用当前工程、需求范围、截止及已有授权，按[夜跑 workflow](../../workflows/bos-demand-unattended.workflow.md)准备批次，用户无需手填 JSON。`--night` 是技能路由，不是 BOS 脚本参数；普通处理保持原流程，不新增提交、部署、数据或 BOS 写入授权，也不自动创建多会话。0.8.0 增加此显式入口；已有项目更新能力包并刷新已启用技能索引后生效，无私有配置迁移，不自动启动夜跑。

此入口的新批次显式启用决策策略，引用现有工作区计划与 Overlay 预检，并按宿主记录额度策略；Codex 在启动及派发前读取真实额度，停止领新和收尾阈值由 workflow 定义。旧批次保持原策略。本地源仓变更不表示已更新项目安装副本。

0.5.0 在需求处理的全部本地提交校验成功后，直接复用本次仓库与完整 hash 自动准备 BOS 日志计划；展示具体计划后复用明确的 BOS 补录预授权或请求一次授权。“验收后提交并把本次提交补录到 BOS 代码更新日志”可同时明确两个动作。缺少日志配置、拒绝或接口失败时保留本地已提交结果；未知结果先核对，已确认成功不重复写入。编排见 workflow，不改变通用 demand-commit 或需求状态；业务工程主动更新后生效，无新增配置迁移或旧文件清理。

0.4.0 统一分段配置，运行时不保留旧格式或编辑器设置回退；旧平铺配置须明确运行 migrate-config 原地转换，详见[配置与迁移](references/usage.md)。个人配置不会被项目更新器自动修改，日志缺失只阻塞日志技能。代码更新日志的 plan 不联网，submit 需明确 BOS 写入授权，字段与结果判定见[接口说明](references/code-update-log.md)。

## 验证

运行 node --test plugins/bos-plugin/tests/*.tests.js；发现/流程集成见 scripts/tests/bos-plugin.tests.js，场景验收见 [需求场景](references/scenarios.md)。测试使用合成数据与隔离仓库，不连接真实 BOS。CI 配置不等于跨平台通过，真实宿主及项目试点另行取证。

框架是 BOS 查询与日志能力的唯一维护源，适用于组织统一分发、个人独立配置。新使用者从 [私有配置初始化](references/usage.md)开始；实例仅在仓外生成，真实凭据不进入框架。待办、项目待办、历史模式由脚本统一处理。已有本机技能按 [迁移步骤](references/adoption.md)改为引用，不维护第二份实现。

客户端原生工具是可选接入方式，服务来源、stdio 注册示例与验收见 [客户端 MCP](references/client-mcp.md)。
