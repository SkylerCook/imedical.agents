# iMedical UI 评审

帮助请求（`--help`、查看用法）：先读取[统一帮助协议](../../../../docs/guides/capability-help.md)，按当前定义展示帮助后结束；Overlay 未映射 `docs/` 时先按 `.agents/capability.json` 的 `CapabilityRoot` 定位协议；附带执行参数也不进入业务流程。

## 接收材料与范围

1. 读取目标项目入口和插件状态，确认用户要求评审的页面或截图及范围。未指定工程的截图可先检查可见表现，源码归属与技术栈保持待确认，不为评审创建连接或修改插件状态。
2. 接收单张/多张截图、用户明确的已打开浏览器页面或两者。识别材料是规范原图、设计稿还是业务运行截图；来源未知时注明，样例不能证明业务已实现。识别当前风格族与配色，IHOS 海蓝和 PURE 天蓝分别记录覆盖，只有一方材料也立即开始。
3. 读取 [共性规则](../../rules/imedical_ui.md)，按下表只加载涉及的章节；需要定位原图、参数或条款时回查 [来源目录](../../references/source-catalog.md)。

| 当前对象 | 参考 |
|---|---|
| 宿主边界、查询区、分栏、导航、页签、滚动 | [布局与导航](../../references/layout-and-navigation.md) |
| 标签、输入/选择、按钮主次、工具栏、控件状态 | [表单与操作](../../references/forms-and-actions.md) |
| 表格、分页、状态标记、弹窗、提示、渐变 | [表格与反馈](../../references/tables-and-feedback.md) |
| 登录、首页、关于、申请组合、步骤条及补充控件 | [页面模式与补充构件](../../references/page-patterns-and-supplementary.md) |
| 风格族、配色、跨风格共性或例外 | [风格差异](../../references/style-differences.md) |

完成条件：材料和本次可检查范围已明确；未知比例、未展示状态与缺少的评审基准有记录，可检查部分继续。

## 执行评审

4. 按 [评审方法](../../references/review-method.md) 选择截图、浏览器或混合路径。截图仅证明可见事实；浏览器先选择明确 tab/frame 并核对实际资源，再进行工具允许且不影响用户编辑的只读或可逆核查。
5. 将每个候选发现对应到当前适用条款，保留条款强度、场景与例外；按[对象语义和责任层](../../references/style-differences.md#按对象语义判断共性)判断业务共性或有据 family 差异。示例业务、设计器操作和未证实的像素估算不作为强制要求。
6. 只检查与本次对象直接相关的布局、控件及状态。缺少浏览器能力时使用已有截图继续，报告无法核查的项目；沿用宿主现有工具，不安装运行器或绕过工具限制。

完成条件：每个发现均有可定位事实与规范依据；推断、资源/源码证据和实际可见结果分别陈述，缺口未被包装为通过。

## 输出结果

7. 用位置、事实、规范出处、共性/family、建议 owner、证据级别和结论记录每项；结论使用“问题／疑似／未覆盖”。按 [方法中的报告格式](../../references/review-method.md#报告格式) 输出，短评审可合并相同原因，仍保留各自位置。
8. 列出 IHOS 海蓝、PURE 天蓝分别实际检查的材料与状态，另一方缺失、比例未知、不可见状态及业务效果明确列为未覆盖。AI 审查结果不代表正式 UI 组或用户验收通过。

报告优先交付在当前对话或用户已有台账；用户需要落盘时遵守项目交付位置，截图和业务证据不写入公共能力包。不新增评分阈值、验收状态机或默认全量测试。

## 操作与修复边界

评审保持业务数据、权限和用户未保存编辑。浏览器操作、身份与收尾按评审方法和实际授权执行；优先复用登录态，保存/提交不用于验证样式，连接信息不进入报告。

评审本身不改源码。用户同时授权修复时转入目标技术栈既有 owner：IRIS CSP＋HISUI 使用 iris-ui，其它体系沿工程入口；模块内 CSS 在既有授权范围内处理，跨模块或全局公共层改动先交用户审核具体影响与方案。
