# 表单与操作

适用于 IHOS 海蓝与 PURE 天蓝的业务层 UI 适配。先核对现有组件库、工程公共适配和实际主题，再补页面差异；HISUI 工程优先复用 HISUI。

## 读取和执行

1. 确认实际入口、宿主、主题、容器和业务契约，定位本次表单与操作区。
2. 先按下列共性核对两种 family；仅在已确认差异处补 family 适配。
3. 规范中的“必须/须/禁止”保持要求，“宜/不宜/优先”保持建议，“可”保持可选；明确例外一起执行。
4. 明文要求、构件图形参数、页面示例分别记录。MarkLion 的拖拽、复制、Shift 等设计器编辑说明不转成运行时交互。
5. 业务默认、必填、权限、确认流程、数据联动或保存含义发生变化时登记待核对，不因视觉条款自动改变。

PDF 页码为文件物理页码；其条款按 [来源适用范围](source-catalog.md#来源适用范围)首先约束 IHOS，PURE 需相应证据支持。MarkLion 文件按资料族、画板与完整 GUID 定位；数据可检索不等于所有内容都是强制规范。

## 查询与录入布局

来源：[PDF p45、p52（组件间距、数据查询布局）](source-catalog.md)。

- 查询布局按“查询条件—操作栏—表格—分页”识别责任区；面板标题对应一级导航菜单名称。具体业务字段和分组仍从需求及当前代码核对。
- **两种 family 均需兼容时**，查询条件区与表格区采用10px间距；仅支持 IHOS 时规范允许0px。不要把兼容条款改写成所有面板固定10px。
- 多行输入框的垂直间距为10px；按钮、表单水平间距为20px。测量相邻元素可用空间，扣除标签、同排辅助项及容器边界后调用原生控件适配。
- 图稿中的一排字段数、输入框宽度和具体查询条件是示例；保留业务分组、字段顺序、事件入口和动态字典内容，按真实容器适配。
- 同排包含下拉、链接、辅助按钮时分别分配空间；不要给控件整格宽后再挤入其它元素。
- 顶部和子页留白先核对宿主所有权。PURE 白卡外框与 IHOS 贴边布局不同，不能在父子两层叠加同一外边距。

## 字体、输入及选择器

来源：[PDF p14–15、p22–26（字体、输入框、选择器与框体）](source-catalog.md)。

- 正文参考14px；面板标题18 Regular，模态窗标题18 Bold；各标题类别分别核对，不将所有标题统一字号。
- 思源字体要求针对设计文件；运行时沿用工程现有字体与回退，不新增 webfont。医疗文书和打印另有规范，不因页面改造同步替换。
- 行距1.5倍、段距2倍的条款限定设计文件；不要据此覆盖全部运行时控件行高。
- 下拉列表默认不限制高度，同时顶部或底部至少距浏览器对应边缘20px。长列表须验证实际视口和原生控件定位，不实现无限高度溢出。
- 单选与多选控件按业务语义选择：只能选一项用单选框，可选多项用复选框，不能因外观偏好互换。
- 框体与输入框同列：标签在前、框体在后，文字右对齐、框体左对齐；竖向单列：框体在前、标签在后。
- 父子复选的部分/全部选择需有对应视觉状态；若当前业务未实现联动，先登记契约差异，不只画一个“部分选中”状态。

涉及数据行为的原文要求单独登记：

| 规范要求 | 本轮 UI 适配动作 |
| --- | --- |
| 单选为必填，默认第一项 | 核对字段语义、旧默认和保存值；未经业务核对不新增默认或必填校验 |
| 复选必填按业务定义，初始无默认勾选 | 保留已确认业务约定；差异记录原因与待决定项 |
| 多个同类别复选需全选 | 核对类别边界、选择范围与现有事件；新增联动按业务范围处理 |
| 两态切换可用开关 | 属可选控件，不据此替换已有两态业务操作 |

MarkLion 样本：[PURE 控件-01按钮+表格+表单+其他控件](../../../vendor/imedical-ui-standards/pure-controls/res/控件-01按钮+表格+表单+其他控件/data.js)。

- `d9de2a4b-1493-4e53-a07f-e861db9c13b9`：“* 输入框”，分段样式中星号红、标签黑；是已标明必填构件的表现，不决定哪个业务字段必填。
- `b00b4b1f-8e81-4769-bc0d-5250ebab399b`：单选、复选及选中/悬浮/禁用/部分选中变体，可用于状态覆盖。
- 32px输入高和6px圆角属于构件几何样本，先与当前组件库核对；不生成覆盖所有输入的全局尺寸 CSS。

## 按钮层级与排布

来源：[PDF p20–22（按钮类型、状态、排布与例外）](source-catalog.md)。

- 主要按钮用于突出关键操作；一个区域只有一个按钮时优先使用主要按钮。次要按钮用于常规动作，通常搭配主要按钮，不建议单独使用。
- 与内容右对齐的操作组，如查询区：主要按钮在次要按钮左侧。
- 操作区独立成行，如弹窗底栏：主要按钮在次要按钮右侧。
- **例外**：严格排布因布局限制、功能特殊性而降低体验时，可按用户习惯和整体表现调整优先级；记录具体原因，不机械交换既有按钮顺序。
- 规范对主要按钮提出建议：红、黄、绿在同一区域各至多一次，尽量减少多色并存。依据动作语义复用原生按钮类别，不自行复制颜色与状态样式。
- 默认、悬浮、点击、加载、禁用分别核对。禁用鼠标应为不可点击样式；实际禁用能力也要验证，不能只改变颜色或光标。
- 按钮文案变化与初始化/重建来源一起修改；保留既有 handler、翻译 key 和保存逻辑，避免渲染后循环改字。

## 图标及业务确认

来源：[PDF p15–17（图标类型与操作交互）](source-catalog.md)。

- 图标按功能语义从已有库选择。纯图标按钮**必须**有 Tooltip；与文字组合时仍需核对可见标签、禁用与焦点反馈。
- 规范的面性图标用于面板/页签标题，线性图标用于行列操作或辅助动作；按对应类别使用，不能为省空间把所有操作都图标化。两族标题构件和树节点的对应证据见[面板与树的图标角色](layout-and-navigation.md#面板与树的图标角色)；图标角色共用，具体资源与状态沿当前主题，不靠类名前缀猜颜色。
- 删除/关闭确认及“×”悬浮/选中红色属于原文要求。确认流程会改变操作链时先核对已有确认、未保存保护及业务要求，避免二次确认或静默新增拦截。
- 不把设计示例中的按钮数量、动作名称或固定组合复制成业务能力。

## Family 差异按需补齐

| 项目 | 共性优先 | 必须保留的差异 |
| --- | --- | --- |
| 表单和按钮结构 | 复用原生控件与语义类别 | 不同 family 的背景、边框、hover/selected 等由实际主题负责 |
| 主色 | 使用当前主题能力 | IHOS海蓝`#3047A9`，PURE天蓝`#008FFF`；不得用一个硬编码蓝色覆盖两者 |
| 承载与外边距 | 明确父子责任，避免叠加 | IHOS贴边与PURE白卡外框不同；兼容查询/表格间距仍按10px条款 |

色板来源：两家族控件-01主色色块文字均可通过 `69fea5b7-1616-4747-8cdd-c1c96a19109a` 定位。颜色值用于来源核对，实施优先复用现有主题。

## 定向验收点

- 两种 family 均检查初始、异步填充、字典重载和窄容器；标签/辅助项同排，内容无意外裁切或横向溢出。
- 查询字段分组、ID、事件、参数、默认值与保存值对照；业务待核对项单列，不能报已完成。
- 按钮重建后文案、顺序、handler稳定；禁用不触发、加载不重复执行，原有权限与确认仍有效。
- 纯图标 Tooltip 可见且不遮挡关键操作；键盘焦点、长文案及实际支持语言按改动覆盖。
- 32px/6px等几何只在适用构件核对，不拿单个样本否定原生控件的其它合法类型。技术检查与用户视觉验收分别记录。
