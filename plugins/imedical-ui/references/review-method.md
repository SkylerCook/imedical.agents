# UI 评审方法

供 imedical-ui-review 按材料类型读取。规则正文沿 [共性规则](../rules/imedical_ui.md) 和场景参考，本文件只规定如何取得证据、形成发现与交付。

## 输入与覆盖

1. 确认评审对象是截图、当前浏览器页面，或截图与浏览器的组合；记录用户限定的页面、区域和问题。
2. 标明材料来源身份：规范原图、设计稿或业务运行截图；未知则注明。前两者用于理解/比较设计，不作为业务已实现证据。同时识别风格族与配色，IHOS 海蓝与 PURE 天蓝不能仅凭蓝色外观判定。
3. 单张截图或只展示一个 family 仍可开始；另一基准未提供时报告未覆盖，不据此否定当前可见项。
4. 记录已知视口、缩放、图片比例及页面状态；不知道的项目标为未知，不能补成常用默认值。
5. 优先沿用项目已有需求、台账及证据位置。截图含业务信息时，只在本任务授权范围使用和引用。
6. 材料不足只限制依赖它的判断；先完成可见部分，不为凑齐模板中断整个评审。

完成条件：读者能知道评审针对什么、看到什么，以及尚未看到什么。

## 选择适用要求

按对象读取对应章节，保留原条款的必须、建议、可选和例外：

| 对象 | 按需参考 |
|---|---|
| 外框、查询组合、面板、导航与页签 | [布局与导航](layout-and-navigation.md) |
| 表单、标签、输入选择、按钮和工具栏 | [表单与操作](forms-and-actions.md) |
| 表格、分页、状态、弹窗和提示 | [表格与反馈](tables-and-feedback.md) |
| 登录、首页、关于、申请组合、步骤条及补充控件 | [页面模式与补充构件](page-patterns-and-supplementary.md) |
| 共性是否成立、family 或配色差异 | [风格差异](style-differences.md) |
| 明文、构件参数、示例的依据 | [来源目录](source-catalog.md) |

- 优先使用已提炼 MD，再按需回查 PDF 物理页码或画板/节点；不默认全量加载原始包。
- 节点 GUID 跨资料族可能重复；规范出处同时注明资料族、批次和画板/节点，避免误引。回查参数时执行[有效图层与参数提炼](source-catalog.md#有效图层与参数提炼)，有效变体、paint、透明度及祖先状态未核清的数值不升级为要求。
- 区分明确条款、构件几何、页面组合示例和设计器说明。示例字段、默认值或业务流程不自动成为产品要求。
- 按[对象语义](style-differences.md#按对象语义判断共性)区分业务共性、皮肤资源与有据例外；共性只引用一份，差异限定实际对象及 family/配色。源码证明的适用范围与截图实际覆盖分别记录。
- 先辨认宿主与业务容器的留白所有者。现象可确认而责任层未知时，建议 owner 写待源码定位。
- 来源冲突或适用条件不明时保留双方依据，列为疑似/待确认，不能挑一个值宣布违规。

## 截图路径

1. 保留原始截图，使用截图编号、区域名称或原图坐标定位；不修改原图制造对照效果。
2. 分清浏览器外框、系统导航、业务 frame、弹窗及裁切边缘。截图尺寸不直接等于内容视口。
3. 先检查可直接观察的关系：截断、遮挡、换行、对齐、层级、滚动位置、重复留白与可见状态。
4. 只有比例和测量对象可核实时才报告精确像素；截图缩放未知时用相对关系或注明估算。
5. 不把看不到的部分判为缺失；截图没有横向滚动条，也不能证明所有宽度或动态阶段都无溢出。
6. 当前可见按钮可评审层级和排布；hover、焦点、真实禁用、等待、键盘操作和业务效果不能由单图确认。
7. 有多张图时核对是否同一页面、版本、视口和状态；条件不同不直接作为改前/改后因果证据。
8. 示例患者、字典内容和订单仅作视觉材料，不从截图推导业务必填、默认、权限或保存契约。

完成条件：可见发现有原图位置；精确数值及不可见状态的证据限制明确。

## 浏览器路径

1. 使用当前宿主已提供的浏览器工具，读取其操作约定；确认用户指定或本次授权覆盖的 tab 与目标 frame。
2. 多个页面可能同名，先核对实际页面上下文和角色；目标不清楚时只做范围识别，不操作候选业务页面。
3. 在导航、刷新或切换前检查当前是否有未保存输入、表格编辑或未完成弹窗。保留用户状态，不能用清屏或关闭重开取得干净样本。
4. 按需要读取目标 frame 当前加载的组件/主题/locale/公共资源与计算样式，确认实际生效关系；另发请求不证明该 frame 已加载对应版本。
5. 报告只保留必要的资源相对名称、版本和错误摘要；票据、cookie、连接参数、患者资料及原始请求内容不进入公共报告。
6. 初始核查优先读取可见 DOM、几何、控件只读状态和实际 Console/Network 证据。读取不到的 frame 或资源明确记录，保留已有截图结果。
7. 在现有授权与工具限制内，可做不影响编辑的滚动、悬浮、聚焦、展开/收起或尺寸核查；先确认动作可恢复且不会触发业务写入或丢弃编辑。
8. 刷新、导航、切换业务对象、筛选或重新查询可能重建页面；仅在用户授权覆盖且已确认不损害编辑时使用，并记录前后条件。
9. 保存、提交、审核、上传、删除、修改权限或业务数据不属于 UI 评审。不能为了验证禁用按钮而试点这些动作。
10. 优先复用已有登录态。认证按用户授权和工具要求处理；需要人工交互认证时交回用户，恢复后核对实际身份与范围。不猜凭据、不擅自切换身份。
11. 无法安全改变某状态时，保留当前状态并将相关行为列未覆盖；只读属性核对不冒充真实点击效果。
12. 工具不具备尺寸、资源或交互能力时，退回已提供截图或报告具体缺口；不安装新 runner、下载浏览器、改变安全设置或越过工具限制。
13. 只读评审不改页面 CSS/DOM 来制造符合结果，不把诊断脚本加入业务资产；使用现有测量辅助时明确其采集范围。
14. 完成或等待用户时停止本次操作，恢复安全可逆的焦点、滚动或面板状态；只关闭本次创建且已确认无用户编辑的临时资源。

实际证据按阶段标注，例如首屏、数据加载后或侧栏收起后。只核查本次问题需要的阶段，不默认遍历全部页面、账户或主题。

## 证据与结论

证据级别描述判断基础，不是分数或自动验收等级：

| 证据级别 | 能支持的判断与限制 |
|---|---|
| 截图可见 | 指定图像、区域和状态下的表现；未知比例时不支持精确 CSS 像素断言 |
| 浏览器实测 | 指定 tab/frame、视口、资源和操作后的实际表现；不外推到未测状态 |
| 资源/源码核对 | 当前资源、组件配置或代码机制；单独存在不能证明视觉已生效 |
| 推断 | 根据现象提出原因或责任层候选，仍需补证 |

结论使用以下含义，复用项目现有记录，不创建新的验收状态流转：

- **问题**：事实可复核，且与当前适用条款存在明确差异；不把建议性条款写成无例外的硬性违规。
- **疑似**：比例、适用条件、归因或条款冲突尚未排除；写明已知事实和最小补证动作。
- **未覆盖**：材料未展示或本轮无法安全核查的基准、状态、行为或技术对象；不得改称通过。

没有发现明确问题时，表述为“已查范围内未发现明确问题”，同时交代范围和未覆盖项。

## 报告格式

先说明本次材料、识别出的 family/配色、实际检查范围和限制，再逐项列发现：

| 位置 | 事实 | 规范出处及适用条件 | 共性/family 差异 | 建议 owner | 证据级别 | 结论与建议 |
|---|---|---|---|---|---|---|
| 截图编号/区域或目标 frame/控件 | 可观察表现，含必要测量条件 | MD 章节及 PDF 页码/资料族与画板节点 | 共性或指定 family，未知则注明 | 模块/宿主/组件/业务 owner 或待定位 | 对应证据基础 | 问题/疑似/未覆盖及最小建议 |

同因多处可合并描述，保留各处位置与证据；纯外观现象不足以认定公共组件、服务器或部署是原因。

- 分别汇报 IHOS 海蓝、PURE 天蓝的已查材料与状态；只有一方时，另一方明确列未覆盖。
- 总结只涉及已核查内容，不新增打分、合格分数线、全量测试承诺或正式验收结论。
- AI 评审可为修改与人工复核提供依据，不能代表 UI 组、用户或业务负责人正式通过。
- 用户同时要求修复时，交给目标技术栈已有适配 owner；模块内 CSS 在已授权范围处理，跨模块或全局公共层改动先审核具体缺口、影响与方案。
- 原图、业务证据和连接信息留目标项目，报告按用户指定位置交付，不写入共享能力包或公开原型。

## 结束核对

确认每个发现可定位、规范引用可查、共性与差异分明；未确认因果与未覆盖状态仍保持原样。
确认本次可逆操作已妥善恢复，未保存编辑保持、临时资源归属清楚；未能恢复时如实交接。
