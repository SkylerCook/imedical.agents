# IHOS 与 PURE 的共性和差异

需要同一业务同时适配 IHOS 海蓝、PURE 天蓝时读取本页。
目标是共用业务结构和适配方法，差异按证据补充；不预设必须新增公共 CSS。
规则和原件版本从 [来源目录](source-catalog.md) 定位，布局执行方法见 [布局与导航](layout-and-navigation.md)。

## 先分清两个维度

- **风格族**：IHOS、PURE；宿主结构、面板组合和部分装饰可能不同。
- **IHOS 配色主题**：海蓝、天蓝、夜间；PDF p10 明确三主题交互逻辑与操作规则一致。
- IHOS 天蓝与 PURE 天蓝即使使用相近主色，也不据此判定所有布局和组件皮肤相同。
- 当前评审组合为 IHOS 海蓝、PURE 天蓝，分别记录结果；其他主题按项目支持范围检查回归。
- 本页对照覆盖海蓝 13 画板与 PURE 控件/布局合计 17 画板，不宣称其他产品或版本完全相同。

## 优先完成的共性

| 共性 | 业务实施方式 | 依据类型 |
|---|---|---|
| 查询、工具栏、列表、分页分区 | 同一结构表达区域语义，按容器分配空间 | 两套标准查询组合示例 |
| 常用表单和按钮构件 | 复用当前技术栈已有组件及状态 API | 两套控件构件 |
| 默认/悬浮/点击/禁用等视觉状态 | 保留组件能力，核对颜色和可读性 | 控件构件；PDF p20–26 |
| 操作按钮分组与主次 | 共用按钮语义和事件，按所在区域排列 | PDF p21；两套按钮示例 |
| 内容滚动、固定操作和尺寸适配 | 共用生命周期处理，随可用容器重新测量 | 两套页面组合及 PDF p53 |
| 弹窗最小尺寸与渐变边界 | 同一尺寸策略，主题只补有依据的装饰 | 两套布局控件说明；PDF p42、44 |
| 多面板、左右菜单和页签组合 | 保留业务信息层级，复用组件选型 | 两套布局画板 |

这些共性不要求运行依赖 HISUI；非 IRIS 工程使用其已有组件库。
IRIS/HISUI 的加载、body 属性、控件 API 与诊断路径由其实现适配能力负责。
规范插件提供来源和判断方法，不替项目创建第二套组件库或发布新的生产样式入口。

## 按对象语义判断共性

先区分两个问题：材料能否成为公司通用规范，以及本次业务能力应适用哪些主题。前者遵守来源证据要求；后者按用户目标、对象语义和实现责任层判断。只有一张 PURE 材料时，已明确的跨主题业务目标仍按共性实施，另一主题的实际渲染证据另记未覆盖。

归类时查看样式或条件影响的对象、用途及直接调用者，而非仅看 `border`、`background`、`hover` 等属性名。业务分组线、内部容器边界和操作悬浮区域可以属于共性；控件皮肤、主题色和宿主外侧边界沿已有组件/宿主能力及确证差异处理。

| 对象 | 共性落点 | 差异依据 |
|---|---|---|
| 行操作使用图标、评分控件选型 | 同一操作表达、组件及事件入口 | 图标资源、颜色与状态皮肤由主题能力选择；图标或文字、两套评分控件的切换需另有适用依据 |
| 附件排布、弹窗尺寸与重开/收起后的适配 | 共用业务结构和生命周期入口 | 主题只保留实际装饰差异，不能据此限定整块初始化或尺寸修复 |
| 内部分组线、容器与内容间距 | 按业务区域语义和已有复用点实现 | 外侧留白、主题色或已有明确适用依据的统计表分隔线/隔行底色可分别处理 |

例外记录当前对象与依据即可，不要求为无关存量主题分支补文档。将主题限定改为共用时，需核对 CSS 优先级、组件初始化与动态阶段；声明值未改不证明已验收主题的实际表现不变。技术栈适配负责源码核查，按改动风险选择已有验收基准的代表状态。

## 需要保留的差异

| 项目 | IHOS 海蓝依据 | PURE 天蓝依据 | 实施边界 |
|---|---|---|---|
| 业务内容外侧边界 | PDF p45、48–52 为贴合，无全局外边距 | 标准查询组合中左右及顶部内容外侧为 15px | 交给宿主或最外层内容容器，避免嵌套重复 |
| 查询与表格分隔 | PDF p52：仅 IHOS 可无额外间距，兼容 PURE 则 10px | 查询与列表组合示例间距 10px | 同时支持两者可采用 PDF 的 10px 兼容口径 |
| 页面与面板背景 | 主题浅底贯穿，部分面板弱化边界 | 蓝色宿主底和白色卡片形成分区 | 沿用主题与容器能力，业务不覆盖整页硬编码背景 |
| 主色及派生状态 | PDF p10–13 的海蓝及状态色规则 | 采用 PURE 控件的天蓝及状态色 | 引用现有主题语义，不把海蓝固定到共用业务选择器 |
| 导航与标签背景 | IHOS 的连续导航和标签组示例 | PURE 的分离式、固定菜单和侧页签示例 | 根据实际宿主选型，业务不重建全局框架 |
| 图标、无数据图和渐变资源 | 随当前风格和状态选取资源 | 随当前风格和状态选取资源 | 资源与对应主题匹配，保持滚动边界连续；操作采用图标还是文字按上文对象语义判断 |
| 组合样本尺寸 | 例如含按钮弹窗 900×530 | 对应组合例图 1040×550 | 两者都是内容示例，不维护两套固定窗口尺寸 |

相近配色不是共性实现已经合格的证据；需分别检查两个评审组合。
差异来自组件库时，使用现有配置；组件缺口和业务局部布局缺口分别交给对应所有者。

## 几何对照的使用方法

1. 定位资料族、画板、目标构件和有效变体，检查祖先可见状态。
2. 分清画板尺寸、构件边界、内部背景、文本框和导出预览尺寸。
3. 核对运行组件的 content-box / border-box、边框、内边距和控件外壳。
4. 先尝试现有组件尺寸 API 或公共布局 class，再补缺失的业务容器样式。
5. 对照首屏和动态内容加载后的实际边界；没有异常时保留现有实现。

例如，海蓝输入框节点 `6db38c4b-9827-45ff-a9f7-da7ce0dd0434` 的构件边界为 200×32。
同画板表头节点 `79134d65-8d9e-4f43-8bab-7b0b34a79ba1` 外层高 34，内部背景与分隔线另有边界。
这两类对象不能合并成“所有控件高 32”或“所有控件高 34”的通用 CSS。
PURE 查询表头示例也有不同层级的 33px/34px 边界，应看完整构件而非单个背景矩形。
字段宽度 200px、例图列数、窗口 900px 等仅在当前样本中成立，不自动推广到所有业务。

## 文案与交互的来源边界

- PDF p14 的思源黑体/思源宋体明确仅为设计字体，系统引用字体与打印字体保持各自约定。
- “选中组件切换类型”“按住 shift 拖动”“复制/删除选项”是设计母版操作，不是应用行为。
- 示例中的患者、药品、状态、字段名和列数量仅用于展示，沿用目标项目真实业务契约。
- PDF p26 的默认选中、全选与父子勾选；p38–39 的增改方式可能改变业务，单列待确认。
- 页签固定、导航展开策略、模态范围和按钮行为同样需要结合现有业务确认。
- 当前只是视觉要求时，保持原 DOM 标识、事件入口、权限、参数和保存值；发现矛盾先报告。

## 如何选择样式归属

| 发现 | 处理 |
|---|---|
| 已有组件或公共布局能满足 | 直接接入，清理当前页面的冲突覆盖 |
| 多处业务有相同布局缺口 | 核对实际重复模式与复用收益，在已授权业务公共能力中增量补充 |
| 单页排布或业务特有结构 | 使用页面作用域和局部容器样式 |
| 控件皮肤或全局宿主不符合 | 记录来源与复现，交给其组件/宿主所有者，按授权修复 |
| 只有一个主题需要差异 | 将差异限定于该主题与实际对象，不复制整个业务实现 |
| 当前没有足够证据 | 登记待核对项，保留实现，不以抽象重构代替问题定位 |

业务公共样式承载布局共性，主题颜色、控件状态和全局宿主由已有能力控制。
新增共性应证明实际复用收益；一次页面调整不自动升级为全公司全局规则。

## 两项评审的记录

- 共性修改写一份清单，在现有任务表中补充共性落点、差异依据和兼容基准；两项评审分别填写结果。
- 风格差异记录当前值、来源要求、实现所有者、已做处理及剩余人工核对点。
- 普通、悬浮、焦点、禁用、等待状态和长内容状态按实际改变范围选择验证。
- 涉及尺寸时按本次改变的机制选择首屏、侧栏切换、窗口重开、容器变窄或动态加载的代表状态；不默认展开全部页面、主题和宽度矩阵。
- 局部技术验证、实际加载生效和 UI 组评审分别记录，不能互相代替。
- 后续升级资料时按版本和来源摘要比较，不用目录日期猜测所有内容都已更新。
