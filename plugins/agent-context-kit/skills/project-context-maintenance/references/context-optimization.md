# 上下文优化

用于已授权的上下文精简、效率优化，或只读审查重复、过期和歧义。初始化也可用这些原则检查产物；不为普通编码增加例行维护。

## 以编程任务选择信息

结合用户目标及允许读取的工程证据，选取当前项目的典型任务走查；不预设技术栈或强制每个项目保存完整清单。

| 编程需要 | 值得保留的信息 | 验证方式 |
|---|---|---|
| 定位实现 | 源码层、真实 Git 边界、加载入口、适用的参考实现 | 检查路径及当前引用；没有运行证据时标为定位线索 |
| 正确修改 | 项目特有契约、公共资源下游、生成文件 owner、编码与维护分工 | 与相关代码/配置交叉核对；通用编程常识不复制 |
| 快速验证 | 已知可用的构建/测试/本地运行命令、前置条件、失败判据 | 优先复用当前有效证据；仅在授权且可执行时运行，未验证命令明确标记 |
| 准确交付 | 本地检查与部署/业务验收的区分、提交入口及必须人工完成的环节 | 核对当前规则和授权；不把人工验收扩展到所有小改动 |

这些信息有明确维护位置时只建立任务路由；缺失且能显著减少重复探索时补到 owner。命令不得带入凭据或私有连接值；没有统一构建链的工程记录实际可用验证方式，不虚构 npm 等现代工具链。

初始化时走查一个主要开发场景是否能找到起点和验证方法；维护时检查受变化影响的路径；优化时选择与已发现摩擦对应的任务。走查可以只读，不为验证上下文而擅自改业务代码、联网部署或创建真实任务。

对比时看是否减少重复搜索、无关读取、澄清往返和错误路径，同时保留必要约束与验证。无实际运行对照时仅报告结构改进，不宣称耗时或成功率提升；不为了记录指标增加常驻报告。

## 从问题确定改动

先确定当前主入口、相关规则与记忆的 owner，查看目标文件实际内容及已有改动。区分三类问题：重复读取和多处维护、事实时效、约束范围不清。没有证据的问题不升级成强制规则；只读请求不写文件。

| 内容 | 优化方式 | 保留边界 |
|---|---|---|
| AGENTS 与索引重复路由 | 只保留一个路由表，入口链接到它；高频保护可留短摘要 | 专项约束必须能由触发场景到达，不能只追求行数 |
| rules/profile/memory 重复事实 | 规则归 rules，配置归 profile，记忆引用 owner | 先确认语义等价，不能仅按相似句子删除 |
| 无条件读取多个 profile 或所有插件 | 标明何种任务需要何种资料；已持有且未变化的资料复用 | Git、目标源码和最终 diff 等动态事实按操作更新 |
| 普通本地任务读取连接配置 | 仅连接、远端能力或实际配置问题时读取私有配置 | 不改变工具执行所需配置，也不复制敏感内容 |
| 记忆包含大段领域入口或历史流水 | 有独立使用场景时拆为领域文件，主记忆注明何时读取 | 保留有效决策及必要历史线索；不创建无用途的空文件 |
| 旧源码/环境快照 | 标明原核查日期、范围与是否复核；未知日期写未知 | 整理日期不是核查日期，不因路径存在断言运行态 |
| 模板 TODO、模式判定教程 | 删除无信息占位，教程留在初始化资料，profile 保存已选值 | 真实待确认项保留；不猜测、重置模式或移除未知键 |
| “等文件”“全部检查”等宽泛约束 | 依据职责和证据明确触发范围、已知对象及例外 | 不把示例当作完整清单，不把负责人分工或安全保护静默解除 |

缺少文件归属且影响写入时，只澄清该边界，并继续独立工作。已有明确授权不因常规重排或去重再次确认；扩大写入范围、改变权限或领域契约仍须对应授权。

## 验证与交付

- 对比变更前后：用户约定、工作区/Git 边界、编码、凭据、远端写入及验证真实性仍保留；不擅自变更插件状态或配置值。
- 检查改动文件编码、相对链接与被移动段落的引用；同一路由可达即可，不为减少文件数合并独立领域资料。
- 用本次目标回看读取路径：初始化能找到完整闭环，维护只更新变化 owner，日常优化无需初始化或插件推荐。无需新建固定报告、模式字段或自动维护任务。
- 交付说明实际改动及验证限制；文字缩短只能证明输入减少，不能直接宣称模型能力或耗时改善。

## 已部署项目

更新插件只取得新版指导资料。用户授权目标项目上下文维护/优化后，按实际内容定点调整；不批量覆盖 AGENTS、rules、memory 或现有 profile，不修改生成薄索引来建立第二套规则。原路径保留为入口或更新全部调用方，按需核对技能发现。仅改 canonical 的请求不触碰任何业务副本。
