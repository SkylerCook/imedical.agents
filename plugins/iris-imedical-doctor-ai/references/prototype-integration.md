# 从可变原型到实际集成

用户提供原型、截图或设计需求时使用。原型不是固定产品规范；下列内容是分析维度，不是必须实现的页面或流程清单。

## 提取设计意图

识别本次设计要解决的任务、用户动作、信息来源、确认点、成功反馈与异常路径。先确认哪些是设计目标、哪些仅用于演示，再映射当前工程能力。不要把演示患者、诊疗建议、定时动画、假保存和 UI 上的 Agent 标签解释成真实服务或执行授权。

## 复用宿主能力

对患者选择、历史资料、病历、诊断、医嘱和报告等能力，先检查当前宿主是否已有可调用入口。AI 集成负责串联任务与交互，尽量复用业务服务；缺口按需要补齐。不因参考图采用三栏布局，就要求其它工程也采用三栏布局。

诊断可作为首个映射场景，但不能推断其它动作与它共用同一接口。原型展示的阶段导航也不自动等于业务状态机或多智能体调度。

## 跨设计可复用的检查方向

- 患者、就诊和病历上下文可辨认；查看历史资料与当前业务写入对象有明确区别。
- 区分建议生成、医生确认、执行中、成功、失败和结果未知；具体状态结构与文案由设计和真实服务决定。
- 保存、采纳与关联视图更新通过现行接口及事件衔接，避免只改变 DOM 就报告业务成功。
- 医生能取消、调整、回看或使用传统入口；是否需要顺序执行由实际业务规则决定。
- 数据来源、时效与执行结果可追溯；风险或质控提示的依据需要核实，不从原型文案推导临床规则。
- 布局、主题、输入区和组件尺寸适配当前宿主；参考信息层次，不直接复制全局样式与像素值。

## 按需建立映射

使用 [集成分析模板](../templates/integration-plan.md)，对本次动作记录设计意图、当前工程能力、需要适配的部分、确认与验证方式。工程事实只写目标项目任务记录。

能力状态可区分已有、待适配、仅演示和待核实；不把某次映射永久保存为插件能力表。原型或框架变化时，重新核对受影响项，不必重做无关部分。
