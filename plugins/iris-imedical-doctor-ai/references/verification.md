# 验证方向

按实际修改选择场景，断言来自当次需求与目标工程现行契约，不预设方法名、字段或状态枚举。

## 诊断及业务集成

- 有效、无效、空结果、上下文不可用和请求失败分别核对。
- 医生选择的内容与最终业务入参一致，按实际规则检查主诊断、日期等字段。
- 取消、校验拒绝、部分处理、失败重试和结果未知分别验证，未成功不得误报成功。
- 切换患者或病历时仍有异步操作，检查结果归属与旧操作失效。
- 修改共享服务时验证传统页面及其它相关调用者；确认必要的保存后联动。
- 按当前存储策略验证恢复、重复执行及历史数据兼容，不预设快照或实时重取。

## 框架与设计

- 按实际发现/注册机制核对扩展组件、依赖失败、未知动作及生命周期。
- 涉及流式协议时检查分块、结束、取消、错误与会话状态；涉及语音时检查输入和资源释放。
- 原型落地检查设计动作到真实业务服务的映射；展示效果不是保存、质控或签名证明。
- 框架接口变化时同步使用方和相应测试；不要求新实现满足旧版样例的内部结构。

## 证据边界

字面量检查、语法检查、模拟运行和真实 HIS 验证分别说明。跨平台 CI 声明不等于结果通过。真实项目的运行、布局和设备验收按用户要求执行；不在能力源仓产生业务数据或产物。

## 卡片运行时接入检查

无论是否适用静态元数据审计，都应在目标工程实际加载链中核对：配置或静态清单来源明确；配置驱动时获取成功、当前上下文有效项目与过滤原因可解释、脚本地址解析正确；资源请求成功且版本可识别、脚本执行无异常、动作可解析、实例收到上下文及入口参数、依赖与主题样式生效、按钮事件实际触发。注册失败先沿证据链排查，不能默认归因于缓存。

控件初始化后验证事件传播与禁用行为；HISUI 等控件可能接管事件，不能仅凭原生 DOM 或简化 mock 点击成功认定有效。事件绑定方式按实际控件确定，并验证销毁后不残留处理器。无真实框架环境时明确缺口，不把静态工具升级为运行时证明。

## 脱敏回归场景

以下是目标工程的测试设计输入，不是已执行结果或固定实现；使用虚构患者/单据及可观测调用计数，不连接真实 HIS。选取受本次修改影响的场景。

| 场景 | 输入或故障注入 | 预期与证据 |
|---|---|---|
| 入口分层 | 同一有效上下文从现有正式、历史及快捷入口（如有）进入；AI 数据伪造快捷标记 | 仅宿主明确授予的例外有效；每次执行原业务校验，恢复不继承例外 |
| 参数传递 | 中间构造器只转发部分选项 | 在执行层检查实际上下文和入口，缺失时不误用别的病历或获得放行 |
| 默认范围等价 | 配置返回日期但旧控件未使用；两端使用相同有效选择 | 旧页面与卡片生成相同业务任务；差异有明确需求依据 |
| 独立选择 | 先单类预览再全部预览 | 全部任务与初次默认集合一致，无前次选择残留 |
| 主流程与辅助入口 | 主流程已从快捷区移除；分别改变卡片加载、导航项及辅助按钮配置；导航指向未注册动作 | 按各自配置取证并验证实际分发；不硬编码补回重复按钮；未注册动作按现有兜底处理；导航排序或点击不冒充业务完成及前置校验 |
| 配置引入 | 配置存在但被当前上下文合法过滤、配置缺失、配置请求失败、脚本相对地址错误分别输入 | 分清获取、筛选、加载与注册阶段；失败不伪装为空，过滤不被硬编码补载绕过；有效配置在当前会话能完成注册 |
| 加载与事件 | 脚本请求失败、执行异常、动作未注册、控件拦截冒泡 | 可区分原因并保留重试/人工入口；真实控件点击恰好触发一次 |
| 运行依赖 | iframe load 后 API 尚不可用；等待期间切换病历或销毁 | 未就绪不提交；等待结束重新核对上下文；资源及监听清理 |
| 摘要语义 | 同一底层项目用于不同文书，包含编码实体及类似标签的文本 | 摘要按文书用途生成；按已确认编码契约解码并以文本安全显示 |
| 空与失败 | 类别确认为无项目、查询失败、配置无法解析分别输入 | 仅可靠的空类别可隐藏；失败不能伪装空数据，仍能恢复或人工处理 |
| 无 Chat 宿主 | 传统入口未加载 Chat、未注册监听，通知 API 缺失或监听失败 | 原业务可独立完成；原刷新和宿主回调保持原契约；AI 通知失败不改变业务结果或导致重复提交 |
| 跨窗口与刷新 | 同源多层窗口、跨域外壳、不同就诊通知、实例销毁、刷新期间重复通知 | 仅有效同源范围和对应就诊接收；越界访问不阻断业务；刷新可收尾且销毁清理监听 |
| 共享调用方隔离 | 卡片传入专属选项，传统页面不传；分别执行预览与提交 | 新选项仅影响约定调用方；传统默认选择和业务任务保持原语义 |
| 回调与结果 | 取消、部分提交、设备无完成回执 | 卡片不触发原页面专属完成流程；仅报告已提交或未知，不自动重试 |

接口适配测试需让 mock 校验真实请求键名、参数序列及传输形式，而不是无论输入都返回成功；真实服务与打印设备仍需单独验收。

## UI 与状态交互验证

按本次变化选择以下检查，使用真实宿主主题和控件；固定像素差不作为跨工程标准。

| 场景 | 检查 |
|---|---|
| 宽窄容器 | 在工作台实际卡片宽度及窄容器核对分组、按钮折行和横向溢出；检查控件初始化、resize 后的布局 |
| 状态与对齐 | 状态标签有无、长文案、未知、失败及空结果；同一行按钮上下边界对齐，标题无图标残留或文字重叠 |
| 状态按钮 | 初次渲染、刷新、历史恢复时，保存、打印等有副作用的业务动作调用计数为零；允许必要的只读状态查询和数据读取；点击仅触发对应动作一次；成功后状态能按既有机制更新 |
| 预览与提交 | 打开预览不产生提交；选择范围和上下文正确，关闭/销毁清理资源，异步期间切换对象后旧操作失效 |
| 组合动作 | 对每一步记录目标与顺序，注入取消和失败，确认已完成部分、后续停止及联动均与文案相符 |

可用浏览器边界测量辅助核对同行对齐，但不能替代视觉检查；静态 CSS 或元数据扫描不证明运行时美观和主题兼容。本地合成数据、实际控件、真实业务环境的证据分别报告。
