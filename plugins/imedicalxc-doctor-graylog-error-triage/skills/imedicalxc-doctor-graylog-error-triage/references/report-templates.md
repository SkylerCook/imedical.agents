# 报告结构与字段

四类文档都由 `render-report.js` 生成，落在 `docs/agent-reports/graylog-triage/<env>/<yyyy-MM-dd>/`。

> **时区**：报告正文里的采集窗口、生成时间、每簇的「首次 / 末次」、慢请求「最慢样例」与耗时样例时间，统一显示为**本地时间（Asia/Shanghai, UTC+8，格式 `YYYY-MM-DD HH:mm:ss`）**，不带 `Z`。原始产物（`raw-errors-*` / `classified-*` / `pending-queue.json` 的 `firstSeen` / `lastSeen`）仍是 **ISO UTC（带 `Z`）**，用于排序与 Graylog 查询；两者相差 8 小时，不要混读。文件名里的 `<HHmm>` 同样是本地时间（`collect-errors.js` 用 `getHours()` 生成）。

## 巡检总览-<HHmm>.md

每轮一行结论，用来快速判断要不要深看。含：

- 时间窗（from / to / 重叠秒数，本地 UTC+8）
- **两路查询**：报错查询与慢请求查询原文、慢请求阈值，以及「按解析出的耗时毫秒数判定，框架文案分档最高只到 15秒」的提醒
- 抓取条数、簇数，以及覆盖日志的报错/慢请求拆分
- **严重度分布**表：`P0 · 不可预知程序异常` / `P0 · 慢请求（>= Ns）` / `P1 · 业务正常处理抛出`（有旧版无 severity 的簇时另给「未初判」行），附初判信号说明与 `analysis.severity` 可改判的提示
- **处置分类分布**表：`运行时缺陷（需改码）` / `业务异常·需人工介入` / `日志级别待复核` / `业务控制（无需干预）`，逐行给簇数与处理要求；慢请求不计入（单列说明）；旧版分类结果另给「未分类」行，`analysis.disposition` 可改判
- 归属分布：本组（**有本组堆栈帧 / 仅应用名推断 / 慢请求** 三行）/ 基础设施 / 他组 N 组 / 无关 / 待定
- **来源分布**：本组自身 / 本组调用他组（跨组，责任在被调方）/ 他组自身故障 / 基础设施 / 待定，逐行给簇数；旧版分类结果另给「未标注」行。来源与归属是两个维度，同一「他组 N 组」里可能既有本组调用他组（需本组容错）也有他组自身故障（与本组无关）
- **慢请求 Top**（按最大耗时，跨归属）：接口 / 归属 / 次数 / 最大耗时 / 平均耗时，取前 10
- 无关簇按疑似归属的明细（哪组、几个簇、多少条）
- 本轮产物清单
- 前端穿透模式与命中情况

## 本组问题-<HHmm>.md

只含本组簇，用来指导改码。开头是本轮概览（簇数按报错/慢请求与证据分档拆分、P0/P1 计数），随后：

**「P0 优先处理清单」**（有 P0 时才出）：跨章的处理顺序索引，列为 序号 / 类型 / 簇 / 证据等级 / 次数。序号与下文各章明细的簇号一一对应。

**「处置分流」**（有簇时出）：回答「哪些需要动」，列为 处置分类 / 簇数 / 处理要求 / 簇（序号）。需改码、需人工介入、需复核日志级别的簇排在前面，业务控制（无需干预）单列；旧版分类结果显示「未分类」行。**正文章节顺序与本表一致**。

- 簇标题：慢请求用 `慢请求 <接口全限定名>`；报错用异常类；**无异常类的报错退回消息首行**，超 64 字做「头 32 + … + 尾 32」截断（区分信息 `extCode` / `path` / 失效药品名都在行尾），并净化竖线与反引号以免撑破表格。
- 同一标题对应多个簇时补 `errorHash` 前 8 位，保证每行可定位。
- 证据等级为「仅应用名推断」的 P0 簇**无本组代码证据**，清单下方有固定提醒：先交叉同轮基础设施/他组簇再定性。

正文按处置分流分章（空章不渲染）。章内先 `evidenceLevel=module-frame`、再 `app-only`、最后 `kind=slow`：

| 章 | 内容 |
|---|---|
| 一、运行时缺陷（需改码） | `runtime-defect` 报错簇 |
| 二、业务异常·需人工介入 | `business-escalation` 报错簇 |
| 三、日志级别待复核 | `log-level-review` 报错簇 |
| 四、业务控制（无需干预） | `business-control` 报错簇 |
| 五、慢请求耗时归因 | `slow-perf` 簇，含阈值与覆盖条数说明；归属优先按接口包前缀，未登记时退回应用名推断 |
| 未分类（旧版分类结果） | 无 `disposition` 字段的簇，重跑 `classify-owner.js` 回填 |

章头给出簇数拆分与处理要求；含 app-only 簇的章节附「仅凭应用名、无本组代码证据」提醒；慢请求章附无堆栈与耗时归因要求；业务控制章附「不强制改码」提醒；日志级别章附「降级 / 保留 error」要求。

正文之后另有 **「附录：本组调用他组失败」**（`ownerKind=external` 且 `origin=self-calls-external` 的非慢请求簇，归属在他组、责任在被调方，本组只出容错方案）与 **「附录：待定归属」**。跨组附录的簇**不进 P0 优先处理清单**——清单只索引本组簇；`ownerKind=unknown` 的簇即使来源标成 `self-calls-external`（`selfAffected` 但没解析出被调方）也只留在待定附录，**不得重复渲染**。

每簇的公共字段：

| 字段 | 说明 |
|---|---|
| errorHash | 16 位，跨轮去重的键 |
| **类型** | 报错异常 / 慢请求（接口耗时超阈值） |
| **严重度** | P0 / P1，标注「脚本初判」或「分析轮改判，脚本初判 X」；旧版分类结果显示「未初判」 |
| **严重度依据** | 初判理由；混合簇另标「**混合簇，按最高级处理**」 |
| **处置分类** | `runtime-defect` 运行时缺陷 / `log-level-review` 日志级别待复核 / `business-control` 业务控制 / `business-escalation` 业务异常·需人工介入 / `slow-perf` 慢请求；标注「脚本初判」或「分析轮改判，脚本初判 X」；他组通知不展示该行 |
| **处置依据** | 初判命中的信号（业务异常 / 外部调用异常 / 人工处理关键词 / 运行时异常类 / 无异常类的 log.error）；混合簇附计数并标「混合簇，按最高优先级处理」 |
| 次数 | 本窗口内出现次数 |
| 归属 | ownerKind / ownerModule / ownerGroup |
| **归属判定** | 命中的规则名与置信度（如 `slow-interface-fqcn（high）`） |
| **来源** | origin 标签：本组自身代码/配置/数据 / 本组调用他组失败（责任在被调方，本组容错）：组名 / 他组自身故障（本组未参与）/ 基础设施组件 / 证据不足。混合簇附 `originCounts` 分布；旧版分类结果显示「未标注（重跑 classify-owner.js 可得）」 |
| 证据等级 | module-frame / app-only / interface-fqcn |
| 首次 / 末次 | 本地时间（UTC+8），格式 `YYYY-MM-DD HH:mm:ss` |
| 应用、涉及 URL | 打印进程与脱敏后的 URL |
| **源码位置** | 报错簇的快速定位：日志 `source_class_name` / `source_file_name` / `source_line_number` / `source_method_name` 四字段；日志未带 `source_*` 时退回堆栈最内层业务帧并在段标题注明口径。同簇多个位置按出现次数取多数，其余列在「源码定位」块 |
| 样本消息 | 脱敏后的原始消息 |
| 前端定位 | codegraph 命中给 html/element/jsMethod/jsLine；否则标注「启发式匹配，未经前端索引确认」 |

报错簇另有：异常类、锚点堆栈帧（最内层业务帧）、**「源码定位」块**（`source_class_name` / `source_file_name` / `source_line_number` / `source_method_name` 四行；同簇多位置时附按次数排序的清单）、堆栈摘要（头部 + `Caused by` 链 + 业务帧，中间 `...` 省略）、方案段 **「根因与修正方案」**。

无堆栈、无 `source_*` 的 app-only 报错簇（绝大多数落在「日志级别待复核」章）另出 **「日志语句定位」块**：`log-site-locate.js` 用日志 `logger_name` 锁定类文件，再按消息里的中文文案/长标识符匹配源码 `log.error/warn/...` 语句的字符串字面量，给出「文件 / 行 / 级别」、匹配得分最高的语句片段与近似候选。这是**文案匹配，不是堆栈证据**，块标题已注明；命中基础设施公共仓（如 hiscfsv、hisbase）时附「非本组代码、先核对归属」提醒；工作区源码级别与采集侧不一致（如代码 `warn`、Graylog 记 ERROR）时附「部署版本可能与本地代码不一致」提醒。索引缓存在 `config/.cache/log-site-index.json`（7 天，`GRAYLOG_TRIAGE_REFRESH_LOG_SITES=1` 强制重建）。

慢请求簇另有（**没有异常类、没有堆栈摘要**）：

| 字段 | 说明 |
|---|---|
| 接口 | 接口全限定名 `FQCN.method` |
| 耗时 最大 / 平均 | 自动换档：`<1s` 给 ms，`<60s` 给 s，`>=60s` 给 `X.XXmin（Ns）` |
| 最慢样例 | 最大耗时那条的时间（本地 UTC+8）与 traceId，供拉全链路 |
| 耗时样例表 | 时间（本地 UTC+8）/ 耗时 / traceId，最多 `maxSamplesPerCluster` 条 |
| 方案段 | **「耗时归因与优化方案」**，字段标签为 耗时原因 / 优化方案 / 验证方式 |

方案段未回填时按处置分类给不同占位提示：`runtime-defect` 要求给报错位置与代码改法；`log-level-review` 要求判定降级或保留 error；`business-escalation` 要求写明被调方与原始错误、给容错/提示方案；`business-control` 只要求确认业务语义与提示文案；`slow-perf` 要求按 traceId 分阶段分解耗时、区分数据量与代码缺陷。已回填则显示 rootCause / fix / verification，改判过时另显示「**严重度（分析结论）**」「**处置分类（分析结论）**」与改判理由。

文件末尾可能有「待定簇」附录，用于人工确认。

## 基础设施-<HHmm>.md

基础设施簇，只落盘不推送。标题按内容动态生成：`基础设施报错` 或 `基础设施报错与慢请求`，概览给出簇数与其中慢请求簇数。结构与 self 类似但不含修正方案。

## 他组通知-<组>-<HHmm>.md

给他组的转发文档，必须能独立看懂。标题按桶内实际内容动态生成：`报错通知` / `慢请求通知` / `报错与慢请求通知`。概览含时间窗（本地 UTC+8）、归属组、簇数（报错 X / 慢请求 Y）、严重度 P0/P1 计数，以及 **判定来源**：报错簇区分「医生站调用贵组接口失败 X 簇」与「贵组应用自身报错 Y 簇」（旧版分类结果给出「来源未标注」计数）。**通知文档不含本组内部的分析结论**——根因、修正方案、容错建议只在 `本组问题-*` 与队列里，不要把方案段一并转发。

报错簇每簇含：

- 异常类、次数、errorHash
- **来源**（`医生站调用贵组接口失败` / `贵组应用自身报错`；混合簇附分布）
- traceId
- 请求接口（URL 路径）
- 调用方服务
- 截断堆栈（`maxStackLinesNotify`，默认 25 行）
- 排查请求（明确请对方看什么）

慢请求簇每簇含：

- **接口全限定名**、次数、errorHash、最大/平均耗时、最慢样例 traceId
- 类型与严重度行（一律 P0）、归属判定 `slow-interface-fqcn`
- **没有异常类、没有堆栈**（框架 WARN 日志本就不带堆栈）
- 概览里额外写明「贵组接口耗时 >= Ns（按接口全限定名归属，**非调用失败**），请分析耗时原因并给出优化方案」

桶内有由 `notifyUnrelated` 提升进来的无关簇时，概览另给一行说明「由贵组应用自身打印、医生站未参与调用，请贵组自查」，避免对方误判为医生站调用出错。

不含本组明细、不含待定簇、不含 IP 与凭据。

## 触发式清理

`他组通知-*` 与 `基础设施-*` 是快照，只保留最新轮次；某组本轮不再报错，旧文件被删除。`本组问题-*` 与 `巡检总览-*` 是历史轨迹，不清理。

手工回放旧轮次时，`pruneStale` 只清理轮次 ≤ 当前轮次的快照，不会删掉更新的轮次。
