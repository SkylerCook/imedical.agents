# CLS 命名与格式规范

本文是 coding-iris-plugin 的 ObjectScript 命名与格式唯一事实源，供编码和 Review 共用。修改前读取适用约定，完成后对最终 diff 检查；不改变上传、编译和提交授权，不要求为格式检查连接服务器。

## 适用顺序

用户本次明确要求 → 项目显式规范 → 本文默认值。先检查项目入口和 profile 中已有的规范；要求已明确时直接执行，不逐次询问风格。历史代码提供业务实现、接口和兼容性证据，不自动构成风格规范。只有无法按上述顺序消解的明确冲突才集中询问。

## 改动范围

- 新类按完整规范编写；使用[类模板](../templates/class.template.cls)前，按[后端基类核对流程](../rules/iris_coding_backend.md#三层架构)适配 `Extends`，模板中的基类不代表项目继承要求。
- 已有类的格式规范仅用于本次真正新增的代码，如新方法、声明或语句；不得格式化原有代码，即使它因功能需求被修改，也保留其既有风格。新增代码可添加自身必要的分隔空行，但不整理相邻历史空白、类末尾或 EOF。
- 历史命名、空格、缩进、注释、空行和换行保持原样。格式自检发现原有代码的问题时不修正，也不影响提交。功能或语法修复按需求执行，不借修复附带调整风格。
- 不以服务器输出为由覆盖本地文件或接受无关业务/Storage 变化。
- 已有符号、继承成员、外部接口、数据库字段及其调用契约保持兼容，不因触碰所在方法就重命名。新增局部变量按规范命名；重命名已有符号属于单独的功能或重构范围。
- 本文不改变常量的表达形式、返回值类型、锁和事务行为；这些属于业务或接口契约，不是格式化动作。

## 命名

| 对象 | 默认约定 | 示例 |
|---|---|---|
| 新增局部变量、形参、普通属性 | lowerCamelCase，表达业务语义 | `patientId`、`displayName` |
| 新类名和方法名 | UpperCamelCase；包路径以项目约定为准 | `PatientSummary`、`GetDisplayName` |
| 新增类级 `Parameter` | 默认 UpperCamelCase，先满足 ObjectScript 成员名语法 | `DefineCode`、`MaxRetryCount` |

系统标识、覆写方法和对外映射使用契约要求的名称。不要把命名规范用于字符串内容、SQL 字段、Global 节点或已有接口键。

语言合法性优先于风格：未加引号的类成员名以字母或 `%` 开头，后续为字母或数字；不能把通用 `UPPER_SNAKE_CASE` 套用到 `Parameter`，例如 `Parameter DEFINE_CODE` 含不合法的下划线。合法的全大写名称、继承参数及已有契约保持原样，UpperCamelCase 只是新增参数的默认风格。宏按预处理器规则处理，不与类参数混同。

声明与引用一起核对，例如 `Parameter DefineCode = "ExampleConfig";` 对应 `..#DefineCode` 或 `##class(Demo.Config).#DefineCode`。带引号的成员名、非 ASCII 名称、动态 `$PARAMETER`、继承/跨类引用按目标版本和实际声明核实；不能机械删除下划线或重命名。引用中的 `_` 也可能是拼接运算符，编辑器红线或静态提示不构成已取得 IRIS 编译失败的证据。

## 命令、表达式与缩进

- 方法体每层缩进 4 个空格，不新增 Tab；项目显式覆盖时按项目规范执行。方法左大括号单独一行。
- 常用命令和函数采用小写缩写：`s`、`d`、`q`、`$g`、`$p`、`$o`、`$d`。新块式控制结构使用 `if`、`elseif`、`else`、`for`、`while` 全拼，`continue` 保持全拼；`} else {` 同行。
- 同一条件分支保持完整语法结构；历史命令式 `i/e` 不机械改写，也不与块式 `if/else` 混接。
- 普通赋值和二元运算符两侧各留一个空格，参数列表逗号后留一个空格，例如 `s totalCount = firstCount + secondCount`、`d ..Save(patientId, totalCount)`。一元运算符、间接引用、宏、对象访问和嵌入语言按各自语法处理。
- 命令与首个参数之间使用一个空格；同一行无参数命令后接下一条命令时保留所需的双空格。不要将命令分隔符当作普通排版空格压缩。

### 后条件

- 命令、冒号和表达式开头连续书写，不写 `q: condition` 或 `q :condition`。
- 框架默认将整个后条件表达式放在括号内；比较运算符两侧留空格，组合条件之间使用紧凑 `&&` / `||`，例如 `q:((value = "")&&(other = ""))`。这是一种选定风格，不是所有合法语法的集合。
- 语法允许括号内部的空白；不要宣称后条件内部一律禁止空格。对于未用外层括号包住的组合条件，不能把 `continue:(cond1)&&(cond2)` 改成 `continue:(cond1) && (cond2)`，后者的括号外空白会提前结束后条件。
- 保留字符串中的空格；不能对表达式用正则批量增删空白。命令冒号、参数后条件、SQL 参数绑定等不同位置不能套用统一的“冒号两侧空格”规则。
- 循环退出属于语法约束：在 `for`、`while` 或 `do ... while` 循环内用 `q` / `quit` 结束当前循环时，必须不带返回值参数；后条件不属于返回值参数。正确：`q:(subRowId = "")`；错误：`q:(subRowId = "") ""`。需要返回方法结果时，在循环结束后按方法返回契约处理，不能给循环退出的 `q` 追加返回值。编码与 Review 均须检查此项，它不是可选风格建议。

语法依据：[InterSystems ObjectScript Syntax Basics](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_syntax) 的 Postconditionals / Whitespace。循环退出依据：[QUIT (ObjectScript)](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_cquit) 的 Without an Argument / With an Argument。这些说明用于区分语言规则与框架风格，不代替目标 IRIS 版本的编译验证。

## 注释与空行

- 类及成员声明前使用 `/// `，方法体内使用 `// `，标记后留一个空格。解释用途、约定和非显然原因，不强制作者、日期或版本流水。
- 文档注释从行首开始，连续且紧邻对应声明；块内及声明前不插空行。使用纯文本，不添加 `<br>` 等展示标签。
- 方法之间、最后一个成员与类结束 `}` 之间保留一行空白；文件最后的 `}` 后保留一个换行符，保持原文件 LF/CRLF 风格。
- 以下约定用于新增类及已有类中本次真正新增的声明、方法或语句。历史注释按原改动范围保留，项目显式规范优先；注释整理不改变字段、索引、方法签名、SQL 映射或 Storage，不做全局空白压缩。

### 文档标签

新增标签使用首字母大写的英文名称、英文冒号和一个空格；内容允许中文、英文或混用。历史中文标签继续兼容，文档提取时英文标签忽略大小写，冒号兼容 `:` 和 `：`。

| 标签 | 中文兼容标签 | 说明 |
|---|---|---|
| `Name` | 名称 | 业务显示名称或简短用途 |
| `Table` | 表名 | 含 schema 的完整 SQL 表名，仅适用于表类 |
| `Description` | 说明 | 职责、业务含义、范围和必要限制；兼容 `Desc` |
| `Param` | 参数 | 参数名及调用方需要知道的约定 |
| `Return` | 返回 | 返回形式、状态和结构引用 |
| `Debug` | 调试 | 实际调试调用，或触发入口与必要前提 |
| `Demand` | 需求 | 已知且确需关联的需求号 |
| `Example` | 示例 | 有必要补充的使用或数据示例 |

- 只填写适用且已核实的内容，避免空标签、重复说明或编造来源、默认值、范围与限制；不用“相关信息”等空泛文字替代实际用途。
- 较长内容用连续的 `///` 续行，直到下一个已知标签前均归属前一个标签。提取按所属声明定位，不依赖固定行号。
- 标签别名归一后，除 `Param` 外同一块中同一标签仅出现一次；`Param` 按参数名区分，每个参数至多一条，不重复记录同一参数。

### 注册类与非表模型注释

本节的注册类指非持久化工具类、服务类及 DTO/响应模型，例如直接或间接继承 `%RegisteredObject` 的非表类。先根据实际用途和 SQL 投影分类，不能把 `%Persistent` 等表类因继承了注册对象能力而归入本节。

- 新增注册类在类声明前按顺序写 `Name`、`Description`：名称简短，说明交代职责、主要使用范围及必要的调用前提；涉及对象状态或生命周期时按实际补充。服务类说明提供什么能力，DTO/响应模型说明代表什么数据，避免只复述技术类名。
- 非表类省略 `Table`。类名、方法名使用 UpperCamelCase，属性和形参使用 lowerCamelCase，目录、包名、继承和接口名称仍以项目契约为准；不为补注释改变继承或存储行为。
- 新增属性写 `Name`；单位、格式、枚举、空值、来源、计算口径或业务限制无法从声明表达时增加 `Description`。类型、长度、必填、默认值等直接从声明读取，不在注释中重复维护；不增加无实际信息的说明。
- 类方法与实例方法按下节方法规则编写。新注册类可参考[通用类模板](../templates/class.template.cls)，不能把模板中的示例职责或参数当成目标项目事实。

### 持久化表类注释

- 新增表类按顺序写 `Name`、`Table`、`Description`，说明业务名称、一条记录代表什么、保存范围及必要生命周期规则。
- `Table` 必须与实际 SQL 投影一致，核对声明、继承关系及已有可靠编译元数据，不仅凭类名推算。无法确认的投影、系统列或继承字段标为待解析并报告缺口，不为补注释自动上传或编译。
- 表类属性沿用上述属性规则；索引在需要说明访问用途或业务原因时使用 `Name`、`Description`，不机械添加同义复述。索引字段、顺序和唯一性从声明提取，业务说明不能视为数据库已经实施的约束。

以下为格式示例，假设 SQL 投影已核对为 `Sample_App.ImportBatch`；具体业务说明须以目标实现为准：

```objectscript
/// Name: 导入批次表
/// Table: Sample_App.ImportBatch
/// Description: 一条记录对应一个客户端提交的导入批次。
Class Sample.App.ImportBatch Extends %Persistent [ SqlTableName = ImportBatch ]
{

/// Name: 客户端批次标识
/// Description: 客户端生成的批次标识；同一标识重试时复用原批次。
Property clientBatchId As %String [ Required, SqlFieldName = client_batch_id ];

/// Name: 批次结束时间
/// Description: Unix 时间戳，单位为毫秒；批次尚未结束时为空。
Property endedAt As %BigInt [ SqlFieldName = ended_at ];

/// Name: 客户端批次唯一索引
/// Description: 防止同一客户端批次标识重复创建记录。
Index idxClientBatch On clientBatchId [ Unique ];

}
```

### 方法注释

- 新增 `ClassMethod` 和 `Method` 至少用 `Name` 说明用途；`Description` 仅补充不与名称重复的适用范围、重要口径、失败情况或限制。影响调用方的状态变化、事务、权限及外部副作用等按实际写在方法头，实施步骤和判断原因放在相应方法体代码旁。
- 参数存在需要解释的业务含义或约定时，按签名顺序逐条写 `Param: parameterName | 业务说明`，参数名必须与签名一致，说明必要的必填、格式、单位、取值及输入/输出约定。类型直接从签名提取；无参方法不写空 `Param`。
- 有返回值时用 `Return` 交代形式、主要状态或结构引用，保持项目已有返回契约；无返回值的方法省略，不为凑标签改变实现。复杂结构按下节引用，不重复复制全部字段定义。
- 需要调试说明时，`Debug` 使用实际可执行的调用；实例方法或依赖上下文的方法不能伪装成独立类调用，应说明真实触发入口、对象状态及必要前提。默认只写调用或入口，确有必要再补预期结果；不得嵌入真实凭据或敏感连接信息。
- `Demand`、`Example` 按实际需要补充。模板中的调试示例只依赖示例类，不要求所有方法都有调试入口或关联需求号。

完整方法头示例如下，保留调用、空参数和返回状态的对应关系。类名及方法名为通用示例；假设目标实现确有这些参数与返回码，不能把 `1001` 当成框架统一错误码：

```objectscript
/// Name: 查询门诊有效期及住院登记信息
/// Description: 根据门诊就诊号查询有效期及关联住院登记情况。
/// Param: episodeId | 门诊就诊 ID，必填。
/// Return: JSON 字符串；code=0 成功，1001 表示 episodeId 为空。
/// Debug: w ##class(Example.RegistrationService).GetVisitInfo("")
```

### 返回结构与文档提取

1. 已有 DTO、实体类或 Schema 时，`Return` 引用完整类名、Schema 路径或稳定标识，字段含义在对应结构中集中维护。
2. 组合返回时说明输出路径与各结构的对应关系，仅补充改名、转换、新增字段或子集等接口特有差异；引用实体类不表示接口输出其全部属性。
3. 无对应结构、直接组装 JSON 时，在字段赋值旁写自然注释；较长说明写在赋值前。公共返回包装的通用字段归包装方法或模型维护，调用方只说明自己的业务数据及差异。

表结构文档结合类/属性注释、声明和实际 SQL 投影；接口文档结合方法注释、签名及结构引用。支持识别的直接赋值可按字段路径提取相邻说明，字段类型、可空性、条件返回及嵌套关系须以声明、Schema 或可验证代码为依据。动态字段、循环及跨方法组装无法可靠确定时显式标记待补充，不把单次赋值推广为完整结构。

缺少适用的必需标签、标签或参数重复、参数名与签名不符，以及注释和实际实现/投影冲突时应报告；核实契约后只修正授权范围内的内容。`Debug` 作为文档内容读取，提取或 Review 时不执行其中调用；远程调试仍按原授权边界处理。

这些是 Agent 编写、Review 及文档提取契约；现有 `check-cls-format.js` 不解析标签、校验业务语义或生成表/接口文档，脚本通过不能替代这些检查。

### 方法体与变量注释

- 局部变量、临时对象字段和中间结果使用自然语言 `//`，不套 `Name`、`Param` 等文档标签。解释名称和代码未表达的业务含义、来源、单位/时间基准、枚举/空值口径、临时作用域或非显然的计算原因；简单计数、直接赋值等自明代码不逐变量补注释。
- 短说明紧贴赋值写行尾，长说明写在赋值或相关代码块前，缩进跟随方法体；保持字段路径和注释对应，避免在方法头、结构模型和赋值处重复维护同一份字段说明。
- 不从变量名猜测约束或编造取值范围；注释按实际数据流核对，不能借注释规范重命名已有变量或改变计算逻辑。

以下仅演示说明位置，使用时须确认上下游单位及字段含义：

```objectscript
    s timeoutMs = timeoutSeconds * 1000 // 下游超时参数使用毫秒
    s result.ready = (pendingCount = 0) // 是否已处理完全部待办：1 是，0 否
```

## 编码与 Review 检查

- **新增类继承**：逐个核对所选基类与项目 profile、同职责类及公共基类的依据，检查完整继承链是否满足项目契约；模板合法或格式自检通过不构成继承选择正确的证据。基础设施类可以按职责选择不同基类，但仍须满足所属项目的明确约束；缺依据时报告待核对项，不自动判为通过。
- **提取后复用**：公共方法提取或搬迁后，沿单值、批量等相关入口检查是否仍重复有效期过滤、判重等相同业务规则。同一规则保留一处实现，入口处理各自参数和返回契约；先核实语义和批量性能约束，不机械抽取简单字段读取，不为消除表面相似扩大重构。
- **业务标识与归属**：审查本次相关路径中重复、同义且稳定的业务标识，先查已有定义及业务 owner；确需统一维护且属于类契约时，使用归属类的 `Parameter`。不塞入无关通用工具类，不要求所有字符串常量化；接口值与调用兼容保持。
- **Parameter 声明与引用**：核对语言合法性、引用拼写/大小写及继承契约，区分语法、默认风格和不确定项；规范或格式检查通过不能代替 IRIS 编译。

修改前确定规范来源及真正新增代码的范围；格式审查仅检查新增代码的命名、缩进、表达式、注释和空行，并核对未顺带改动原有代码风格。Git diff 的 + 行可能是原有代码修改、移动或重排，不能直接作为新增代码证明；对照任务开始时源码及最终 diff 判断。新建源码完整遵循规范，复制或移动的历史代码不因所在文件是新文件就自动成为格式化目标。功能、语法和接口/字符串/SQL/Storage 兼容性审查仍覆盖相关 diff。

需要独立 Review 时，向通用 [review-agent](../../../agents/review-agent/AGENT.md) 传入冻结 diff、需求、变更范围、项目显式覆盖和本文路径；混合任务附带各语言适用规范。只读 Reviewer 区分功能/语法缺陷、规范不符合项及可选风格建议，给出位置、规则依据和最小修改建议。没有独立 Agent 时由当前 Agent 按相同清单复核，不因格式 Review 创建正式 run。

## 可选本地自检

```text
node .agents/plugins/coding-iris-plugin/scripts/iris-tools/check-cls-format.js <file.cls> ...
```

只读比较所属仓库 HEAD 与工作区；新文件检查完整结构，已有文件仅提示变更位置。正常完成时，即使有格式提示也返回 0，不接入 Git hook、compile.js 或 commit-demand.js。文件不可读等执行错误返回非零，不代表业务代码不能提交。

复杂结构无法可靠识别时输出 `manual-review`，由 Agent 仅检查本次编辑部分。脚本不写文件、不连接服务器、不自动修复。检查器按 HEAD 变更区间提示，不能区分真正新增与原有代码修改；Agent 对照修改前源码筛选，仅处理新增代码，原有代码提示不作为格式修正要求。

脚本覆盖成员分隔、EOF、可识别结构和有限的 Parameter 命名检查：未加引号的 ASCII 声明非法名称输出 `CLS-PARAMETER-NAME` 提示；直接 `.#` 引用的可疑拼写、带引号/非 ASCII 声明及动态 `$PARAMETER` 输出 `manual-review`。字符串和注释中的示例不作为代码；复杂结构沿用 `CLS-STRUCTURE` 人工核对。不解析继承或跨类符号、不证明引用存在，不检查所有语法、命名风格、缩进、表达式格式、文档标签或业务语义。脚本通过不等于全部规范通过，更不替代 IRIS 编译。Agent 检查和脚本结果分别报告，纯风格问题不升级为功能缺陷或提交硬门禁。
