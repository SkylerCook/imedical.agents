# CLS 编码格式提示

本约定服务 Agent 编码阶段，帮助减少 IRIS 编译前后的无关格式差异。不改变手动上传、编译或 Git 提交流程，不要求编译证据、自动回读或额外授权步骤。

## 改动范围

- 新类按完整格式编写，可参考 `../templates/class.template.cls`。
- 已有类只规范本次新增、修改的位置及直接涉及的成员分隔位置，不扩大到整个方法或整个文件。
- 历史空行、缩进、注释对齐保持原样；格式自检发现未触及的历史问题时不处理，也不影响提交。
- 不以服务器输出为由覆盖本地文件或接受无关业务/Storage 变化。

## 编写约定

- 方法之间保留一行空白，最后一个成员与类结束 `}` 之间保留一行空白。
- 文件最后的 `}` 后保留一个换行符；不要把 EOF 换行与额外空白行混为一谈。保持原文件 LF/CRLF 风格。
- `///` 文档注释紧邻其声明；不主动整理历史注释内部空格。
- 方法体、字符串、宏、嵌入语言及 XData 不使用全局压缩空白或整文件格式化。

这些是 Agent 的编写约定，源于当前对话确认的编译现象，不宣称构成所有 IRIS 版本的完整格式化规范。

## 可选本地自检

```text
node .agents/plugins/coding-iris-plugin/scripts/iris-tools/check-cls-format.js <file.cls> ...
```

只读比较所属仓库 HEAD 与工作区；新文件检查完整结构，已有文件仅提示变更位置。正常完成时，即使有格式提示也返回 0，不接入 Git hook、compile.js 或 commit-demand.js。文件不可读等执行错误返回非零，不代表业务代码不能提交。

复杂结构无法可靠识别时输出 `manual-review`，由 Agent 仅检查本次编辑部分。脚本不写文件、不连接服务器、不自动修复。格式提示不能作为扩展需求范围的理由。
