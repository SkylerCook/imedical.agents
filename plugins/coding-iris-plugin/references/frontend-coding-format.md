# 前端命名与格式规范

本文是 CSP、HTML、JavaScript、CSS 及内嵌客户端代码的命名与格式唯一事实源，供编码与 Review 共用。修改前加载，完成后对最终 diff 复核；HISUI、UTF-8、i18n 和接口行为仍按[前端规则](../rules/iris_coding_frontend.md)执行。

## 适用顺序与范围

用户本次明确要求 → 项目显式规范 → 本文默认值。检查项目入口、profile 和适用配置，确定规范及运行环境；约定明确后直接执行，不重复询问。历史实现用于识别业务和兼容契约，不自动成为风格标准。只有无法按优先级消解的明确冲突才集中询问。

新文件完整检查；历史文件只处理本次新增、修改位置。不借格式任务重排 DOM、抽取文件、改变脚本加载顺序、升级语法或整理全文件。已有 DOM ID、全局入口、事件回调、接口字段、翻译 key、CSS 选择器及其大小写保持契约；重命名属于单独的功能或重构范围。第三方、生成和压缩产物应回到其维护源，不作为手工格式化目标。

## 通用格式与命名

- 每层缩进 4 个空格，不新增 Tab；移除新增行的行尾空白，EOF 保留一个换行。保持原文件 LF/CRLF；新文件默认 LF。UTF-8 字节检查沿用前端规则，不自动转码。
- 不设硬性行宽；长属性和表达式按语义换行，不拆字符串、URL、正则、插值及具有语义的空白。函数或规则块之间一行空白，不全局压缩空行。
- 新 JS 变量、形参、函数用 `lowerCamelCase`，构造函数用 `UpperCamelCase`，明确的常量标识用 `UPPER_SNAKE_CASE`；对象键涉及接口时按契约。
- 新 DOM ID 用 `lowerCamelCase`；新业务 CSS class 用带页面或组件前缀的 `kebab-case`，如 `patient-search-actions`。已有 HISUI class 不改名，不为格式额外复制框架状态 class。
- 文件名和路径按项目 profile；未明确时新文件用 `kebab-case`，如 `patient-search.js`。不改历史文件路径及引用。
- JS 普通注释用 `//`，必要接口文档用 JSDoc；CSS 用 `/* */`，HTML 用 `<!-- -->`。注释解释用途、约束和非显然原因，不强制作者、日期流水。

## JavaScript

- 未声明运行环境时采用 ES5 语法：`var`、普通函数；项目明确支持现代语法时可覆盖。不因风格引入 `const`/`let`、箭头函数、模块、Promise、构建或 polyfill；ES5 语法也不保证 DOM API 或库在目标浏览器可用。
- 字符串默认双引号，语句以分号结束；字符串值、转义和正则语义不得因换引号改变。左大括号同行，`} else {` 同行，新控制结构使用大括号。
- 赋值与二元运算符两侧、逗号后留一个空格；控制关键字与 `(` 之间留空格，函数调用名与 `(` 之间不留空格；对象属性冒号后留空格。
- 新比较默认 `===` / `!==`。接口有类型转换约定时先确认数据类型和兼容语义，不机械替换历史 `==`，不为了通过审查改变业务判断。
- 组织、初始化时机、选择器和请求封装按前端规则及项目契约；不自动加 `use strict`、改写 `this`、事件绑定、同步/异步行为或返回结构。

## HTML 与 CSP

- 标准 HTML 标签和属性小写，属性值双引号。CSP 指令、自定义标签及其属性按实际契约保留大小写，不全局小写化或排序属性。
- 保留文本节点间空白、`pre`/`textarea` 内容、内联元素间距和脚本执行顺序。换行不能改变页面文本或 DOM 行为。
- 按语言区域审查：客户端 JS/CSS 用本文；服务端 ObjectScript 和插值内表达式按 [CLS 规范](cls-coding-format.md)。不能对整个 CSP 文件统一替换空白、引号或分号。
- `#(expression)#` 是运行期表达式，`##(expression)##` 是编译期表达式；两者都不是自动按输出上下文转义的标记。
- 服务端值进入 HTML 文本、带引号属性、JS 字符串或 URL 时分别核对输出上下文及目标版本的转义 API；HTML 转义不能代替 JS 转义，URL 参数编码也不能代替属性转义。避免将动态值直接拼进脚本或属性。语义不明时查项目 helper 和官方说明，不凭模板猜测自定义标签行为。

语法与转义依据：[InterSystems CSP Tag-based Development](https://docs.intersystems.com/latest/csp/docbook/DocBook.UI.Page.cls?KEY=GCSP_tagbased) 的 Compile-time Expressions、Runtime Expressions 和 Escaping and Quoting HTTP Output。链接为 Caché 文档；目标 IRIS 版本仍需对应文档与实际编译核验。通用结构及项目标签边界见 [CSP 模板](../templates/csp-template.md)。

## CSS

- 左大括号同行，每个声明独立一行，冒号后一个空格，声明末尾写分号；逗号分隔选择器分行，规则块间一行空白。
- 不自动排序属性、去重声明或合并简写；保留浏览器回退、前缀、重复声明、选择器顺序和层叠语义。不能为排版改变值、单位或选择器范围。
- 样式作用域、主题和 HISUI 状态归属沿用[前端规则](../rules/iris_coding_frontend.md#hisui-优先原则)。新增业务样式限定在页面/组件范围；格式任务不增加主题硬编码、扩大全局覆盖或追加 `!important`。

## 编码与 Review 检查

修改前确定变更范围、用户/项目覆盖和 JS 兼容基线。完成后检查最终 diff 的命名、格式、各语言区域、字符串/插值/转义、CSS 层叠、接口名称及无关历史行；新文件不能漏检。

调用 [review-agent](../../../agents/review-agent/AGENT.md) 时传入冻结 diff、需求、范围、本文路径、命中的其它规范、项目覆盖、兼容基线和已有检查结果及覆盖范围。区分功能/语法缺陷、规范不符合项与可选建议，给出位置、规则依据和最小修正；纯风格不作为功能缺陷或新增提交门禁。无独立 Agent 时按同一清单串行复核，报告为自审，不创建正式 run。

本轮不新增格式化器、工具依赖或门禁。UTF-8、i18n 检查只证明各自覆盖项；独立 JS 语法检查不证明 ES5、浏览器兼容、CSP 编译或页面可用。禁止把完整 CSP 作为普通 JS/HTML 格式化，或把混合片段直接交给 JS 解析器后据此认定语法错误。分别报告静态检查、Agent 审查、浏览器与 IRIS 编译证据，未执行项如实说明。
