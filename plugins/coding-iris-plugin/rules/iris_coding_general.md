# 通用编辑安全规则

本文保存跨语言、跨模块通用的编辑约束。前端、后端和部署任务还必须读取各自专项规则。

## 统一任务分流

所有通用、前端、后端和 i18n 编码入口使用本节，不复制另一套判定。

- executionPath: fast | full | guarded。fast：低风险、单仓、边界清晰、可本地验证；full：跨边界、调用链不明或证据不足；guarded：权限、Storage、数据迁移、远端写入、部署、复杂编码或验证失败。
- 文件数量仅触发重新评估；一个源码文件加两个测试文件不机械升级。新风险、跨仓或证据不足才升级。
- orchestrationMode 与 executionPath 相互独立。普通 skill、短时只读协助不创建正式 run；持久恢复、正式任务图、并行写入、跨会话协作或用户明确要求才路由共享调度协议。
- guidanceMode 与两者独立，遵循 ../../../agents/_shared/execution-guidance.md。所有模式保留 profile、Git 状态、编码、目标验证、最终 diff 和授权门禁。
- parallelAssessment 只在存在独立范围时判断收益；宿主和用户允许时，最多两个临时只读子 Agent，主 Agent 保持唯一写入者。没有并行收益不输出评估报告。

## 基本原则

### 自主使用知识资料

在插件已启用且资料可用时，Agent 根据任务目标、当前已知信息及查询收益，自主决定是否使用 `../skills/iris-imedical-knowledge/SKILL.md`。本地只读检索不要求用户点名知识库或另行确认，也不是固定必经步骤。

需要补业务背景、寻找可复用实现、理解跨模块关系或核对疑点时可以查询；这些是参考场景，不是穷举触发条件。即使已找到源码，也可在背景不足时查询；当前证据足够时直接继续。可在任务中途按新问题查询，不局限于启动阶段，不受 fast/full/guarded 路径限制。

按问题读取少量相关片段，复用已有有效结果。资料无帮助或不可用时沿当前源码、配置及已有工具继续，不反复检索、不为普通任务要求初始化或同步知识库。知识内容是线索，关键结论用当前工程证据核实。自主查询不扩大远端读取、菜单刷新或任何写入的授权范围；无需额外输出查询决策表。

- 修改前先读取目标工程 profile、相关源码和调用链，理解现有结构和命名习惯。
- 默认沿用目标工程已有模式；允许需求范围内有证据支持的局部改进。重大架构、依赖或公共契约变化先形成具体方案并确认。
- 保持改动范围最小，只修改与任务直接相关的文件和代码块。
- 不回滚、不覆盖用户已有改动；遇到同文件已有变更时先读懂再合并。
- 不做无关重构、无关格式化、无关元数据更新。

## 文件编辑安全

- 保留原文件编码、换行风格和特殊 EOF。
- 历史 CSP/JS/CSS/ObjectScript 文件避免整文件重写，优先局部补丁。
- 生成或移动文件时遵循目标工程 profile 的目录与命名约定。
- 本地缺少远程已有实现时，可用 MCP 只读读取远程内容补上下文，再按需落本地做增量修改。
- 删除文件、批量覆盖、大范围同步、数据库变更等高风险操作必须先取得用户明确确认。

## 默认方法与质量建议

可以合并或重排分析、实现步骤；以结果、领域契约和有效验证为准，不要求逐步证明遵循流程。

- 一个函数或方法只承担一个清晰职责。
- 重复逻辑达到真实维护成本时再抽取公共函数。
- 错误处理集中、清晰，避免在多个调用点复制复杂兜底判断。
- 新增 TODO 只能记录明确后续演进方向，当前代码必须保持可运行。
- 命名使用业务语义，避免含糊缩写。

## 完成检查

- 检查改动范围，确认没有无关换行、编码、空白或格式化变更。
- 后端变更如需验证，用户明确要求后再使用目标工程 MCP 编译相关类。
- 前端 CSP/JS/CSS 变更如需部署，用户明确要求后按[前端验证规则](iris_coding_frontend.md#验证)通过字节门禁，直接上传 UTF-8 源文件并验证；legacy 转换仅用于用户明确指定的历史工程。
- 无法运行必要验证时，在回复中说明原因和剩余风险。
- 本地验证通过后状态只能进入 `acceptance-pending`；只有用户明确确认验收，才能进入 `accepted`，并且验收不隐含 feedback 写入授权。
