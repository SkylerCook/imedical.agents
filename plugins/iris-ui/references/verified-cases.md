# 已验证的匿名案例

以下来自一次 HISUI 改造中的前后对照。它们解释具体机制，作为诊断线索；不证明所有工程使用相同版本或存在同一缺陷。原始图稿、部署及业务证据保存在源项目，本文件不带工程身份或连接信息。

| 案例 | 已证实机制与修法 | 验证范围与限制 |
| --- | --- | --- |
| 主题间控件宽度不一致 | 新容器对各主题生效，尺寸逻辑却只处理一种主题，另一个保留默认控件宽。通用尺寸与专属视觉分开处理，复用原生 resize | 真实 HISUI 与公共资源的匿名多宽度、多主题对照；未替代完整主题视觉验收 |
| 父子留白重复 | 宿主页签已负责外侧间隔，子页再次添加，产生偏移。按已核实宿主限定清除重复部分，独立页仍保留自身留白 | 三个共用页的原生 tabs 夹具及独立打开对照；未修改父平台 |
| 空态首屏横向滚动 | 异步内容新增垂直滚动条，内部仍用之前宽度；开侧栏触发重排才消失。观察实际内容宽度后合并调度既有 resize | 三主题、三宽度、四共用页；覆盖首屏、展开/收起和内容增减。真实空态复测通过，业务流程未由此验收 |
| 收起侧栏仍留展开宽度 | 回调早于动画和开关收尾，重排时旧面板仍占位。绑定原生完成阶段并忽略过期回调，再做最终 resize | 原生组件夹具与多页实测；只验证该布局恢复 |
| 同格链接挤到下一行 | combo 被设成整格宽，没有给同格链接留空间。局部容器让控件使用剩余空间，保留原生控件与入口 | 三主题、六宽度、初始化/重载对照；实际页测量同排，未改取值契约 |
| 选项区只用半宽 | 标题跨列形成多余第三列，固定表格布局将内容区分半。删除多余跨列，统一两列结构 | 三主题、四宽度；初始化、分类切换、回显、清空对照，采集值保持一致 |
| 刷新时工具栏文案闪变 | 初始配置、事后 refresh 改字及数据重建相互覆盖。直接修改初始定义，删除事后改字 | 三主题、三页面、四个重建阶段对照；未改变 handler 或保存逻辑 |
| 原始输入框提前绘制 | 控件在 ready 后才解析，公共主题属性已存在仍可看到原始 HTML。局部展示保护保留测量，并在成功/异常释放 | 慢加载及故障注入对照，用户实测该现象解决。未做旧版完整对照，不能宣称机制首次由改造产生 |
| 风格外边界与内部间距混用 | 先分清宿主、业务页、内部面板及 modal。公共已正确处理的边界保留，只修业务重复留白；公司风格差异沿通用规范，不把内部留白全部清零 | 两风格、主页面/内嵌页/modal 的匿名前后对照；已验收风格指标不变。实际页面只读尺寸与新补丁发布、视觉验收分别记录 |
| 空工具栏仍占高度 | 当前 HISUI 源码以真值判断工具栏，空数组仍生成容器；无工具栏场景改用 null，实际按钮数组保留 | 当前源码及两风格匿名组件几何已核实；局部修复尚未据此认定下游已部署或实页验收，不推广为隐藏全部工具栏 |
| 模板预览外壳影响旧清理 | 外壳改变隐藏状态后，渲染器原有可见性选择器可能漏清旧页。保留数据、模板坐标与打印调用，在外壳适配留白/缩放，并核对空态和再次选择 | 四份模板、两风格的匿名坐标/替换对照及用户视觉结论；不代表所有模板或实际打印设备通过，横线几何阈值仅在该样本成立 |

## 纠正过的判断

### 业务共性被主题条件误包

以下三组是同一次改造的匿名复盘，用户确认的跨主题业务目标及实际实现对照支持本次修正；它们不新增公司级尺寸或视觉规范。

| 观察对象 | 判断与修正 | 保留的边界／兼容证据 |
| --- | --- | --- |
| 操作图标、评分控件 | 同一操作在一种主题用图标、另一种用文字，评分控件选型也被主题分支拆成两套；用户要求的业务表现是共性的。共享操作结构和控件选型，图标资源与状态色继续交给 HISUI | 不因“主题使用不同图标资源”反推操作模式必须不同；请求、事件、持久化评分及禁用语义保持原契约 |
| 附件卡片、弹窗适配 | 仅在某主题调用完整的卡片布局、弹窗尺寸或打开后 resize，造成其它主题保留旧结构。沿 helper 定义、调用及直接共用入口核对，把通用初始化和动态适配移至共享路径，实际差异留在窄分支 | 核对首次打开、重复打开及本次影响的动态阶段；主题色、宿主外侧间隔和有据例外不随之清除 |
| 内部分组线、容器样式 | 将 border/background/hover 一概视为皮肤，漏掉业务分组线及内容层级。按对象用途和责任层共享内部结构与分组语义，再核对 HISUI 已有视觉能力 | 去掉主题选择器会降低优先级，即使声明值不变也可能被旧规则覆盖；以已验收主题为兼容基准，分别记录源码、实际渲染及用户验收证据 |

反例：宿主外侧 15px 的风格差异、框架主题色、已明确保留单主题的统计合并行分隔线/隔行底色仍有自己的适用范围。修复对象是误包的业务共性，不是全部主题条件。扫描只能发现候选；规范推广证据与本次业务适用范围分开判断，详见[公司规则](../../imedical-ui/rules/imedical_ui.md)及[最终差异核对](../rules/iris_ui.md#最终差异核对)。

- 自由换行改变原查询字段分组，属于实现引入的回归；原型要求间距并不授权改变查询顺序和分组。
- “通用要求不应机械绑主题”不等于清除所有主题判断；某统计页合并行分隔线与隔行底色保留专属主题分支，已由用户确认。
- 一处 Console 错误、附件失败或空白不能直接归因于 UI。资源实际版本、调用栈、后端/存储响应和并行更新来源需分别核实。
- 一次部署曾覆盖并行程序的新代码，造成组件与调用方契约失配；责任在部署未保留服务器既有修改，不能把事故包装成公共组件天然缺接口。后续只从回读版本叠加小差异，并保留并行接口和回显逻辑。

## 部署经验的适用边界

代码相同、上传成功、编译成功、实页加载及业务通过是不同证据。并行服务器更新要求核对修改前基线、本次差异与当前远端；无法可靠合并时停止覆盖。

实际模式和能力以 [现行部署契约](../../coding-iris-plugin/references/deployment-protection.md) 为准。direct 不合并部署开始前差异，guarded 有自己的需求与基线条件；本插件首版只正确路由和暴露缺口，不提供新增合并或自动拦截能力，也不许诺远端锁。更完整的增量保护由部署 owner 后续建设。

## 实施自检中的机制线索

以下配置分支已与当前 vendor 源码核对，匿名夹具提供可重复的观测入口；具体浏览器结果另记，不能因存在夹具便称所有工程已验证。

| 线索 | 核对方式及适用边界 |
| --- | --- |
| 父背景填平卡片圆角或滚动槽 | 分别读取父容器、原生 wrapper/body 及滚动状态；同色父背景与对照底切换只帮助确认承载关系。保留 PURE／iHOS 及面板变体差异 |
| 树指定 iconCls 未进入普通图标分支 | 核对 `lines && autoNodeHeight`、文本测量及 `.tree-icon-lines`；单行 false 对照不直接替代确需多行的配置 |
| 只换 CSS 误记另一主题已测 | 初始化前设置 JS style/theme，再核对实际 CSS 与 body 属性；当前 iHOS 海蓝用 vben＋bgseablue，真实工程构建独立取证 |

场景动作和匿名观察沿[夹具回归](layout-lifecycle.md#匿名夹具回归)，实际测得结果保留在当前任务的维护验证证据，不写入业务数据或重复运行台账。

## 经验回归入口

这是已验收 UI **业务需求**的条件分支；纯框架维护沿维护生命周期，不触发自身反馈。

命中可复用经验或框架缺口时，核对当前项目 `agent-framework-evolution` 为 available 或 enabled、入口可读且满足 `0.2.0 <= version < 0.3.0`；显式 disabled、缺失或版本不兼容时停在候选及缺口，不自动改变启用集合。可用依赖并非日常 UI 实施的强制依赖。

符合条件后复用 [agent-framework-feedback](../../agent-framework-evolution/skills/agent-framework-feedback/SKILL.md) 的只读准入与去重。已有规范充分时修正实施；业务特例留项目；相同需求返修不虚增独立命中。写入及源仓隔离待审补丁严格沿其[唯一授权入口](../../agent-framework-evolution/skills/agent-framework-feedback/SKILL.md#写入授权与自动待审补丁)，验收、准入、授权和源仓隔离条件分别成立才执行。无写入授权时仅交付候选；不复制一套授权协议，不把业务安装副本当源仓修改。
