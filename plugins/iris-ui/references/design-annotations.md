# 读取标注与建立差异

有图稿、标注导出包或 UI 评审图时使用。原型表达目标表现，现行代码与需求共同确定业务契约。

## 确认来源

1. 区分设计画板、截图和标注查看器。沿[通用来源方法](../../imedical-ui/references/source-catalog.md)读取当前有效图层及父组状态，再核对尺寸、颜色、渐变、描边、圆角与阴影；存储参数不等于该变体实际绘制，查看器自身 CSS 不代表产品样式。
2. 核对画板尺寸、导出倍数和当前目标 frame 视口。倍图像素先换回画板坐标；不同视口比较容器比例、控件与间距，不机械要求绝对坐标相同。
3. 记录本次涉及的画板和页面状态。截图展示的示例字典项、患者和订单不是固定生产内容；未展示部分不能冒称有明确标注。

完成条件：能定位每个视觉要求的来源，并区分明确数值、布局关系与需要确认的业务含义。

## 落到实际页面

以用户可核对的差异为单位记录：原图/标注引用、目标表现、实际表现及版本、当前责任层、改法、验证和验收状态。已有台账继续使用；用户要求 Excel 对照时，在项目交付位置嵌入 UI 组原始截图并保留来源，不能仅给外链或改后截图。

逐项检查边缘与结构：宿主与子页留白、导航页签、查询分组、主分栏、滚动容器、预览纸张和底栏。渐变先确认承载层及滚动关系，边框与阴影先查原生组件能力；公共已满足的项不再造一套样式。

将需求分类为“公共能力已覆盖”“页面缺口”“需要业务决定”“超出当前范围”。复用点、部分完成和重复要求可关联同一改动，但每个原始条目保留自己的证据与未完成项。

## 结束判断

对照最终实际状态，而非只看某个源文件已加样式。动态内容、控件禁用/等待与重复打开可能改变画板中看不出的尺寸。技术验证及用户验收沿共享协议分开记录；用户尚未验收时交付可审阅结果和准确状态。
