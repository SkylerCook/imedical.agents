# 移动端开发插件

首版覆盖 Android 原生 Java/Kotlin 工程，提供开发、构建验证与日志优先排障。复用工程既有工具链，不绑定 IDE、Agent 厂商或模型；iOS、Flutter 等暂未提供专用流程。

- 接入：`mobile-dev-init`，通过既有更新与 profile 流程启用。
- 日常：`mobile-dev`，例如“排查这个应用闪退，先主动看日志”。
- [工作流](rules/mobile_dev.md)规定运行故障先读取日志，再定位和修复；[日志取证](references/android-logs.md)覆盖工具发现、多设备、进程退出与日志缺失。

无插件依赖；项目需要自己的 AGENTS、Android 构建配置，设备诊断需要可用 SDK Platform Tools 和已授权设备。纯开发或构建诊断不强制设备在线。

已有项目通过正常能力包更新取得后仍为 available，按初始化入口显式启用并生成薄索引；本次新增无旧入口需清理。不自动修改业务工程或部署应用。源仓规则检查不能替代真实宿主及设备验收。

## 当前骨架

日常 skill 按需路由到工程检查、页面开发、接口联调、WebView/PDA、功能移植和验证交付参考，复用项目现有命令；不为每个参考另建 skill。日志优先仍是运行排障前置。

首版尚无专用环境预检或构建记录脚本；后续先用真实需求验证，再抽取重复操作。IRIS 后端及治疗 H5 按任务复用对应插件，无全局强依赖。

项目建仓入口：`mobile-project-repo`。例如“给某医院旧版移动端建 git，源码在现场”：复用项目平台、归属和命名约定，先建空私有仓，再交付可直接给现场 AI 的提交提示词。未知历史不阻塞空仓创建；提交和推送分别遵循授权。
