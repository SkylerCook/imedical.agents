# 移动端项目建仓与现场交接

帮助请求先按[统一帮助](../../../../docs/guides/capability-help.md)展示后结束。实际执行先读取项目 AGENTS、项目管理说明与插件启用状态；尚未启用沿 mobile-dev-init 接入。

## 最少输入，主动完成

用户说“给某项目建 git / 建仓纳管”是建仓行动请求，不只输出方案。先从当前项目管理文档、仓库配置和已确认上下文取得平台、所有者、命名、可见性与工程代际；不要求用户重述已有事实。医院名称/代号及工程身份可明确时，先简短说明推导的仓库名与归属，再执行授权范围内建仓。

复用项目既有私有仓约定；项目没有明确约定时推荐私有。归属、平台或工程代际存在无法消解的冲突才集中询问缺项。不能仅因历史版本未知或现场源码未取回就阻塞创建空仓。只询问“可不可以”时先评估，不视为建仓授权。

## 建仓

1. 区分“从明确标准版本新建”与“现场旧工程回收”。前者在源码初始化前确认标准基线；后者历史未知时记录未知，不强求找回原提交，不用当前最新版填充。旧代际仓库命名沿项目约定，不套用新代际前缀。
2. 使用现有平台连接或浏览器登录态，核对所有者、名称是否已存在及可见性。已存在且身份匹配则复用，不重复创建；冲突或访问失败先查明，不把错误当不存在。失败后先查询是否已创建，避免盲目重试。
3. 创建空私有仓，不生成 README、许可证或 .gitignore，保留现场历史导入空间。读回真实仓库地址、Clone 地址、所有者、私有状态和空仓状态。
4. 未取得现场源码时到此完成建仓，立即交付下节提示词。建仓不自动授权源代码提交、推送、改绑标准仓或合并标准版本；现场执行按用户给现场 AI 的授权处理。当前会话已有对应授权时直接沿用，不重复索要。

项目既有规则若明确禁止空仓先建或要求专项审批，说明实际冲突；不能把仅针对标准源码初始化的基线要求误套为旧工程空仓创建前置。

## 建仓后必交付现场 AI 提示词

建仓结果与提示词一并交付，不等待用户再要。填入本次已验证的仓库名、目标 Clone 地址、项目名称/代号和已知工程代际；私有地址只出现在该项目交接中，不写回通用插件。未知源码路径写“当前打开的现场工程”，历史未知直写未知，不伪造基线。

提示词使用下面的结构，替换方括号内容后给用户直接复制；没有取得真实地址时明确建仓未完成，不把占位符当正式交付。

```text
请将当前打开的现场工程纳入 [项目名称/代号] 的私有仓库。
目标仓库：[已验证的 Clone 地址]
工程代际：[已核实的代际；无法确认则写待核实]
历史标准版本：[已知基线或“未知，不要求追溯后才开始”]

请先读取当前工程 AGENTS 和项目管理文档，自行核对路径、Git 状态、现有 remote、分支及源码身份。保留现场代码和未提交改动，不从最新标准版覆盖，不顺带升级依赖或工具链。

有 .git 时保留原有历史；无 .git 时以现场源码建立初始基线。不要删除 .git 或重建已有历史。目标远端先核实为空仓；若已有内容，查明来源并比较历史，不强推覆盖。需要修改 remote 时仅操作已确认的现场工程，保留原关联；命名和 upstream 关系沿项目约定，不猜测历史来源。

提交前检查拟提交内容以及拟推送可达历史中的凭据、私钥、签名文件、机器配置、缓存和构建产物。已有历史出现敏感信息时停止推送，说明阻碍，不擅自改写历史。保护与本次纳管无关的改动。

在本次纳管范围内完成本地提交，提交信息遵循当前项目约定。提交授权不等于推送授权；未另获推送授权时停在本地提交完成，报告待推送范围。已有明确推送授权时检查完整 outgoing 范围，先 dry-run 再推送，读回远端分支提交核对。

最后报告：实际工程、基线处理方式、排除项、提交 ID、目标分支、推送状态和未验证事项。源码已纳管不等于构建通过或现场运行版本已复现；按现有条件验证并明确缺口。
```

用户本次仅要求建仓时，说明“以下提示词供你向现场 AI 发起源码提交任务”，不在本机代执行；明确要求现场 AI 同时推送时，将模板推送段替换为本次目标分支和已授权范围，不再次询问是否推送。
