# Android 日志取证

1. 复用项目已有日志脚本或 IDE 会话；否则从 PATH、项目 SDK 配置、已配置 SDK 环境中查找 `platform-tools/adb`，不扫描全盘，不自动安装工具。只读取所需配置字段，不输出凭据。
2. 执行 `adb devices -l`。沿用户指定设备或已确认任务绑定选择目标，后续每条命令显式带 `-s <serial>`；多设备且无法确定目标时集中询问。`unauthorized` 请求用户确认设备授权，`offline` 或无设备报告实际状态，继续读取已有本地日志和代码。
3. 从当前构建变体确认 applicationId（含 suffix），核对设备应用及故障时间；读取目标设备 `adb -s <serial> logcat --help` 确认可用选项。先有限快照，不启动无期限采集。支持时使用 `adb -s <serial> logcat -d -v threadtime -t 2000`，崩溃补查 `-b crash`；不支持选项则按设备帮助降级，并通过执行超时/输出上限约束采集。
4. 按时间、包名、tag 与进程关联筛选，保留异常起点、完整 cause 链和相邻上下文。进程仍在时可查 PID 辅助过滤；闪退、重启或多进程场景保留 crash/system 相关上下文，不能仅用当前 PID 或包名过滤而丢掉证据。空输出或截断不证明没有错误，说明窗口和缺口。
5. 需要复现时先保存现有证据，再进行授权范围内的复现；实时采集限定时间并记录进程句柄，结束后停止自己启动的采集。不要执行 `logcat -c`。日志含患者信息、token、请求载荷等时只在本机任务目录处理，汇报脱敏片段，不写入能力包或上传外部服务。
6. 将时间、目标应用/变体、设备系统版本、异常堆栈与源码调用链交叉核对；区分直接证据与推断。设备不可用时明确真机验证待完成，不将静态分析当成运行结果。

使用系统已有 adb，不另建日志服务或运行器。命令选项以设备帮助为准，参考 [Android logcat](https://developer.android.com/tools/logcat) 与 [adb](https://developer.android.com/tools/adb)。
