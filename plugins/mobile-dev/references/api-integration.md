# 接口接入与联调

1. 从现有调用入口核对传输层、业务 action/方法、参数、返回结构及错误处理。其他端实现仅作参考，先区分业务契约和平台实现；复用项目现有 SOAP/HTTP 客户端与认证流程。
2. 明确必填/可选字段、类型、空值、业务成功条件和副作用；使用实际脱敏响应构造针对性验证。契约取消某个前提时，同步清理解析、显示条件、状态模型和测试中的旧依赖。
3. 分别记录组包、发送、HTTP/传输结果、业务结果、解析和界面状态，不能用某一层成功代替下一层。异常需有可诊断结果，不静默转为功能关闭。
4. 日志保留 action、状态、耗时和异常类型等必要上下文；凭据、会话、患者信息和完整敏感载荷不输出。无法看到响应时先判断是否被脱敏或过滤，不能据此断言请求未发出。
5. 异步结果绑定当前页面/请求状态，按契约处理重复点击、取消、超时和迟到结果；有业务写入的接口不盲目自动重试。
6. 需要修改 IRIS 后端时按目标工程已启用的 coding-iris-plugin 执行，治疗 H5 模板沿 iris-cure-form-dev；能力不可用时报告缺口，不绕过对应部署或连接约束。客户端本身无这两个插件的强制依赖。
7. 按[验证与交付](verification-delivery.md)分开报告模拟测试、后端联调与设备行为。
