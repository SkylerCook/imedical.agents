# 验证与交付

1. 按改动选择实际变体的构建、单测、lint 或设备测试，优先复用项目入口，不固定要求所有任务跑全量检查。
2. 核对源码工作区/提交、构建变体、APK 与设备已安装版本是否对应。versionName 相同不能单独证明是同一构建；按项目能力结合产物摘要、构建信息和安装回执取得证据，无法证明时明确版本待确认。
3. 安装或复现按已有授权执行，复现可能产生真实业务写入时先核对操作范围。回归使用原触发步骤、日志时间窗口和受影响页面状态。
4. 分别报告编译、自动测试、后端联调、设备运行与用户视觉验收；缺失层不以其它层结果代替。release 产物另核对签名与交付约定，不因构建成功自动发布。
5. 需要交付改前/改后文件时固定来源提交和基线，完整文件与 diff 按同一范围生成，排除其他需求并核对清单；复用现有交付 owner，不建立第二套打包工具。
6. 交付最小摘要：改动范围、原因与证据、验证结果、未覆盖项及产物位置。敏感日志留项目受保护位置，仅保留必要脱敏证据，清理本任务临时文件和采集进程。
