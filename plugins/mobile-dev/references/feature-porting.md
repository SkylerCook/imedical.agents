# 标准功能移植

1. 按项目管理方案确认来源仓、目标仓、分支、来源提交及共同基线，检查两边已有改动。目录名不证明仓库身份；移植不隐含建仓、改 remote 或推送。
2. 根据来源提交与实际 diff 圈定完整功能，识别共享文件中夹带的其他需求、接口依赖和资源。无法独立拆分时说明依赖，不直接整文件覆盖。
3. 比较目标工程现有认证、依赖、变体与定制实现，保留本地约定。复用已有差异审阅或迁移流程；仅在项目契约允许且提交独立时采用 cherry-pick。
4. 将来源功能适配到目标调用链，逐项核对参数、状态和资源引用。按[验证与交付](verification-delivery.md)在目标仓验证，来源仓测试不能代替目标验证。
5. 按目标工程约定记录来源提交、适配点和待验项；提交与推送沿用户授权分别处理，不把源仓其他需求一并交付。
