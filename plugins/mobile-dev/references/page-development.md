# 页面开发

1. 确定页面入口、目标角色和受影响状态，查找同类 Activity/Fragment、ViewModel、布局、列表与公共控件。沿项目真实架构复用，不强推新的 UI 框架。
2. 对照事件→状态→渲染→接口调用链制定最小改动，核对监听器、观察者和协程的生命周期；列表回收与重绑定不能留下旧数据或重复监听。
3. 按需求覆盖加载、空数据、失败重试、成功、返回和状态恢复。输入、重复点击及异步返回同时检查提交层和 UI 层，不仅靠按钮禁用。
4. 检查项目支持的屏幕、键盘遮挡、文字长度和交互范围；只验证实际受影响状态。权限、切后台、重建等改变时补对应行为。
5. 按[验证与交付](verification-delivery.md)验证。仅有截图不能证明状态恢复或提交成功，未运行的设备行为明确留项。
