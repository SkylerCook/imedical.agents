# Kotlin 开发规范

适用于 Android Kotlin 业务修改。先读取项目实际架构及相关源码，再选择实现；沿用 XML/View、DataBinding 或 Compose 等已采用方案。

## 开发前确定复用点

- 沿正常入口追踪 Activity/Fragment、ViewModel、状态、Repository/API 与保存调用。先查统一导航、图标、确认弹窗、loading、错误处理、防抖和表单控件，使用其现有接口。
- 新增交互同时核对同项目相邻页面的字号、间距、颜色、点击区域、按钮和返回行为。只有已有组件存在具体缺口时再扩展，并检查实际调用者。
- 业务默认值、模板映射和开关先查后台配置与登录下发；新增配置明确缺失、空值、非法值、旧服务端及切换账号后的行为。保留项目定义的兼容默认值，标识符区分 ID、代码和名称。

## Kotlin 状态与生命周期

- 用类型表达接口和页面状态；外部输入在边界解析并校验。对可空值按业务含义处理，避免用 !! 或任意空对象掩盖缺失数据。复用项目已有状态模型和序列化约定。
- 挂起函数的调度方式先查已有实现。阻塞 IO 离开主线程，UI 更新遵循主线程约束；复用已有 scope，取消随所属生命周期传播。捕获异常时保留 CancellationException 的取消语义。
- Fragment 中视图绑定、观察者和 Flow 收集随 view 生命周期管理，销毁视图后释放引用。按已有 Lifecycle/协程依赖版本选择 API，验证重建后监听和加载次数。
- 异步响应绑定请求及当前业务对象，检查账号切换、返回、重建和迟到结果。页面输入、选中项与已完成批次按项目恢复机制保存，避免重复执行写入。
- 写入超时或回调缺失时按业务查询接口核实结果；仅在能证明幂等或未成功时重试。批量操作保留已成功部分和取消位置。

## 业务兼容与验证

- 浏览、修改已有数据依据其持久化关联和实际生命周期解析。检查其他端创建、已开始未完成、旧数据缺字段以及配置变更后的行为，修复策略以服务端业务契约为依据。
- 对本次改变的解析、分组、状态恢复或重复提交分支补针对性测试，优先复用既有测试。构建使用项目现有 Wrapper、JDK 和变体。
- 页面改动验证统一控件的实际显示、键盘遮挡、底部操作区与返回确认。跨原生和 Web 页面时继续读取 [WebView 与 PDA](webview-pda.md)。
