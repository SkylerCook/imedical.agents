# 移动端开发工作流

仅在目标项目 `mobile-dev` 已 enabled 且任务涉及移动端开发/排障时加载。显式调用但未启用时，沿初始化入口接入；帮助请求先展示帮助并结束。

## 先取证

运行报错、闪退、ANR、白屏、网络或设备能力异常：第一项排查动作是主动查看实际日志，按[Android 日志取证](../references/android-logs.md)确认工具、设备、应用与时间窗口后读取；不先猜代码，也不把能自行读取的日志转交用户。

构建/依赖失败先读取现有 Gradle 失败输出；必要时按授权重跑失败的最小任务。纯新增功能先核对需求与现有实现，无需无故连接设备。仅要求诊断时止于证据和原因，不修改代码。

## 实现与验证

1. 读取项目 AGENTS、Git 状态及相关模块配置，确定实际仓库、标准或定制归属、applicationId/变体及源码入口；多个工程不按目录名猜目标。
2. 保留项目既有 Gradle Wrapper、JDK、AGP、SDK、依赖解析方式和编码；不借业务修复升级工具链。先查现有组件与实际调用链，修改最小必要范围。
3. 按改动选择对应变体的构建、单测、lint；设备交互、生命周期、权限、扫码、网络等需在适用设备上复验。构建通过不等于运行通过，release 构建不等于签名交付完成。
4. 修复后按相同触发步骤和日志窗口复验，并检查相邻受影响行为。日志未再出现但未执行原触发步骤，只能报告未复现。
5. 交付原因、改动、验证证据与缺口。沿项目目录约定保留必要的脱敏证据，清理本任务临时采集；默认不提交、不推送、不部署。

只读日志获取不扩大为清空日志、清数据、卸载、安装、重启设备或重启共享 adb server。复现涉及真实业务写入、设备状态修改时核对既有授权；缺少授权只暂停依赖动作，继续静态调查。
