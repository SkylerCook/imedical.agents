# 执行辅助协议

## 三层内容

- 硬约束：授权、凭据与数据保护、用户修改保护、工作区边界、编码、适用领域契约、验证真实性。所有模式均须遵守，不放入可选辅助资料。
- 默认方法：定位顺序、阶段拆分、角色分工、报告组织。允许合并、重排和采取有证据支持的局部改进；重大架构、依赖或公共契约变化另行决策。
- 辅助资料：示例、逐步清单、故障恢复和长参考，按需加载。

## guidanceMode: auto | concise | assisted

当前用户明确选择优先于项目 project_context_profile.md，缺省 auto；不能按厂商、国别、模型名或自称能力强弱判断。不自动写回配置。

- auto：精简入口开始。领域陌生、证据不足、工具失败或漏检时，只补读对应辅助章节；失败仍按风险规则处理，不靠辅助模式绕过门禁。
- concise：减少教学说明，仍读取全部命中硬约束、调查缺失事实并验证。
- assisted：小步骤、输入输出示例和检查点。IRIS 任务按需读取 coding-iris-plugin/references/coding-assistance.md，继续使用现有领域规则，不默认增加角色或报告。

guidanceMode、executionPath 和 orchestrationMode 分别控制辅助程度、风险深度和执行形态，相互不自动升级。未知配置报告后按 auto 处理，不推断授权。

## 上下文与产出

同一执行者仍持有且内容未变化的资料可复用；上下文丢失或文件变化时重读。源码、Git 状态、最终 diff 的新鲜度检查不可省略，不建设另一个缓存系统。

普通任务不新增路由日志、辅助档位报告或创造力说明；只在升级、阻塞和重要取舍时说明。项目入口只保留事实、硬约束和短路由。

每条新强制规则应说明触发条件、防止的具体失败和验证方式；缺少证据支持的普遍要求先作为建议。模型或宿主变化后复跑同一基准，以真实表现决定保留、降级或删除规则。

## 开发复用

准备新增或替换方法、类、组件、接口、脚本、依赖，或复制业务处理逻辑时，修改前执行本节，避免同一能力形成多处维护点。普通文案、样式数值等局部调整沿受影响上下文核对。所有 executionPath 和离线开发均适用，单 Agent 串行承担探索、设计、实现及复核。

1. 从目标入口和真实调用链查起，检查项目公共能力、已有依赖，再按需要扩大到相关模块、已安装能力和知识资料。结合业务概念、行为、输入输出、关键字段和调用者搜索，打开候选源码及消费者。检索限定在项目声明的源码范围和现有读取授权内。
2. 默认使用源码搜索。已有且有效的代码图谱可辅助定位，进入工具时遵循其有效性要求。图谱缺失、过期或知识查询不可用时沿源码和配置继续。源码不完整时注明覆盖范围。复杂通用技术问题沿现有 GitHub 调研要求查官方实现及成熟上游，核对许可证和运行兼容性。
3. 比较业务语义、权限、数据范围、副作用、错误处理、运行环境及消费者兼容性，选择直接复用、扩展现有能力、局部提取或新增实现。有明确消费者、契约兼容且重复逻辑存在实际维护成本时提取公共能力。扩大范围或改变公共契约沿既有授权规则处理。
4. 找到适用实现并确认契约后进入实施。未找到时在现有方案或交付中简述已查范围和具体缺口，按证据继续设计。修改前复核候选仍有效，避免只凭名称或旧索引判断。多个任务共用能力时在既有任务图明确唯一 owner、接口和消费依赖。
5. 最终 diff 后复核新增逻辑及新文件完整内容，检查等价能力、复制的业务规则、额外封装及公共化的兼容风险。发现重复时给出两处源码位置、契约比较、实际风险和最小修正建议。纯相似或抽象偏好作为建议，功能与安全问题沿现有严重度处理。

候选位置、采用方式、关键限制和验证结果随现有方案、handoff 或交付说明传递。有候选却新增时说明具体缺口。复用现有 I/O 和证据字段，常规取舍由 Agent 完成，必要用户决策沿既有边界集中询问。无需为此新建 run、配置、独立报告或准入状态。Review 通过源码独立核对实现者结论。无独立角色时如实标明串行自审。

共享内容相对当前能力包根解析。Overlay 未映射 agents/ 时从 ContextRoot 的 capability.json 取得 CapabilityRoot，再读取本文件。
