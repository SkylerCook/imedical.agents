# 可重复验收与收尾协议

启用 `night-convergence/v1` 的夜跑按[收敛接口](../../docs/night-policy.md#返修收敛与按需依赖)登记问题与每轮诊断/修复，执行次数和总投入任一耗尽则挂起该问题，保留失败证据及人工复现入口。先一条真实入口，再扩大必要覆盖；修复后定向复验，不机械全套重跑。未知写核对和资源退出继续，不能将待修复/待补验改称通过；未启用的旧批次保持原策略。

适用于 BOS 和其它变更的行为验证。简单需求在当前上下文保留下列事实，正式 run 引用现有事件和证据，不新增同义台账。角色代表职责；无 subagent、skill 或 YAML 支持时按本 Markdown 串行执行。

## 准备与执行

先按改动选层级：内部计算直接方法验证，对外接口走实际 Broker/REST/SOAP 入口，写入增加独立回读，页面行为才走无头 Playwright。纯后端不启动浏览器；为认证使用浏览器不算 UI 验收。返回契约变化检查消费者并补受影响页面用例。工具接入见 [分层验收](../../docs/night-acceptance.md)。

显式启用[成本分级策略](../../docs/night-acceptance.md#可选成本分级策略)时，消费冻结后复评与独立短审结论，只执行选定范围；静态证据和人工待验分别保留，均不计运行通过。投入阈值触发复评，已知缺陷与未知副作用仍按本协议处理。

编码前明确需求号、行为范围、角色与正常入口、数据前置、操作、可观察断言、目标版本、允许副作用和恢复方式。开发期间可准备环境，执行绑定最终部署版本。先打通一条真实业务路径，再扩大用例；普通 selector 或等待问题先排查，不直接转人工。

执行前检查认证、权限、页面、完整数据与工具能力。复用已有 fixture authority 的准确 kind/id/owner/关联/租约；到期不自动抢占。数据保留期限来自项目策略；在授权允许的影响范围内按下文保留验收数据，超出范围、影响统计、后续测试或共享配置的状态及时恢复。

新 2.1 夜跑在启动前集中核验授权、角色、实际入口及有界退出，受管部署与验收携带 work item 身份并自动归档回执；运行中权限/能力异常挂起受影响分支，继续原授权内工作，不追加授权问题。数据处置 dataDisposition 与资源退出 cleanup 分开验证；保留、必要重置或删除由项目显式选择，不能用 cleanup.verified 表示数据删除。接入和三策略各三轮成本对照见[项目适配](../../docs/night-acceptance.md#21-项目适配与数据成本)。

按正常入口执行。HTTP 200 仍需检查业务响应；DOM 文本仍需验证可见界面；自动刷新必须直接观察，不能手工查询替代。保存、删除同时验证真实副作用、关联保护及重复请求。无变更保存、取消和关闭不能代替正向用例。

前端版本取目标 frame 实际加载的资源响应；另发 GET 不证明页面已更新。后端取原生编译、回读与真实入口证据。请求首导航前监听，在 request 时保存 frame 父链；晚指定目标、后代 iframe、detach 和未知归属均保留。取消逐事件复核，禁止统一忽略 ERR_ABORTED；无法归因的错误保留 review-pending。

## 人工复验数据与收尾

在已明确允许新增、保留测试数据的开发测试库中，优先保留有人工验收价值的正常、边界及回归场景数据。复用已有环境与操作范围的授权，范围未变不重复询问是否允许保留；这不产生生产环境或其它对象的写入权限。项目已有保留期限、租约和副作用约束继续适用。

- 数据可定位：使用明确的批次标记，在项目已有测试证据或交付记录中登记环境标识、授权依据、批次、记录 ID（可引用完整清单）、角色与页面入口、场景、复现步骤及预期结果；适用时记录保留期限和后续处置约定。真实数据标识与入口留在目标项目受保护记录中，不写入公共框架。
- 按用途处置：保留用于正常、边界和回归复验的数据；删除用例仍实际删除指定测试对象，独立回读并记录删除及关联影响的结果。需要重复删除验收时，另列获准测试对象或重建步骤，不能用“保留数据”跳过删除验证，也不为清空批次而删除其它验收样本。
- 核实交付状态：交付前核对登记数据仍存在、批次与 ID 对应、入口可定位，分别记录保留、重置和删除结果。已授权、已登记且核验的保留数据属于正常交付状态，不作为资源污染、清理失败或交付阻塞；缺失、越权或未知副作用仍如实报告。数据就绪不等于功能验证通过或用户验收通过。
- 独立清理资源：数据保留授权不延伸到临时服务、无用脚本、中间文件、监听器或会话；这些仍按原有资源退出与临时文件规则收尾。

例如验证列表超过单页容量的行为时，保留带批次标记且数量超过分页阈值的数据，交付实际数量、ID 清单和对应维护页入口，供人工复验分页、搜索、引用及增删后的刷新；删除场景使用指定样本，处置后仍核对其余样本满足分页前置条件。该示例不授权具体业务库造数。

## 会话与运行资源

使用 [测试运行时](../../docs/testing-runtime.md) 的项目适配接口。心跳只在同会话轻量入口已证实延续空闲计时、无业务写入、时限明确且宿主支持后台定时时启用。有效业务活动延后心跳；每会话一个执行器持有凭据与心跳，跨进程不共享句柄。

网络异常先核实认证，确认过期才重新认证；恢复后复核角色、页面和数据。未知写结果先回读，不能自动重放。人工认证或恢复失败保留断点。批次结束、暂停、取消、截止时停止心跳，核实在途请求、监听器、浏览器及临时资源真正退出。通知阈值沿批次约定，不因失败自动增加提醒。

## 结果与交接

报告分别表达以下维度，复用已有证据与台账，不新建同义状态：

- 功能验证：说明实际验证范围、结果和证据；局部通过仅覆盖对应场景。
- 可复验交付：与代码和验证证据一并交付上述获准保留的数据登记及入口；无适用数据或未获保留授权时说明实际条件，不为凑交付物自行造数。
- 人工补验：仅列存在具体缺口的需求，逐号说明原因、角色/入口或环境、操作与预期；按需求号去重统计。
- 用户验收结论：分别记录未反馈、通过、不通过、暂缓；未反馈表达为“待用户验收结论”。人工补验与待用户验收结论可重叠，分别统计，不相加或统一归为“待人工验收”。
- 需求澄清：只有尚未确定且影响实现或验收的业务问题才列出，说明待决定事项；未收到验收结论不属于需求含义待确认。

无补验记录时表述为“未记录专项人工补验项”，不据此断言验证完整；记录不完整时先核对现有证据，无法核实则说明范围未知。用户验收通过不会自动抹除已有技术缺口；补验关闭须有对应场景证据，用户明确接受限制则保留原话与范围。

每项结果包含需求号、case/scope、版本、时间、断言、证据引用、未测项、失败类别与收尾结果。原始错误在项目受保护证据中保存，公共报告不含票据、请求参数或患者资料。分别统计开发自测、独立验收与人工留项；一需求的多次返修不增加需求数。

失败区分业务、脚本、环境、认证/授权、版本、证据不足及执行结果未知。前提未变不机械重试。困难项说明已测部分、缺口、有效尝试、人工入口/步骤/预期、风险与恢复条件。已知缺陷返回实现 owner，不包装成人工验收。

Coordinator 核验结果后引用现有 validation-evidence 的真实仓库、scope、fingerprint 和 sequence；相关修改使对应证据过期。工具返回 passed 仅代表指定范围，不自动标记整个 run 验证通过或用户 accepted。

自动执行结束、资源清理与用户验收分开表达；允许“执行已结束、清理完成、部分待人工”交接，业务仍 acceptance-pending。记录准备、执行、诊断、等待返修、证据整理耗时与人工介入/重试/撤回次数，同类样本比较才讨论提效。
