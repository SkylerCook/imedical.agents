01 / 从任务到结果

带着项目上下文，调用合适的能力。

借鉴 ReAct 的推理—行动—观察循环：以“优化一个已有页面”为例，边执行、边观察现场，并据此调整下一步。

  1. 01

    对齐上下文

    读取项目入口，明确目标、验收标准、必须保留的设计意图与允许修改的范围。

    知道在哪做、做到哪里
  2. 02

    选择能力

    从已启用的能力中选择相关 Skill，按需读取规则与参考资料。

    例如：前端编码技能
  3. 03

    执行与观察

    在授权范围内修改代码、调用工具，读取实际输出与错误，更新对现场的判断。

    用环境反馈修正判断
  4. 04

    验证与决策

    同时检查“是否正常运行”和“是否符合原目标”，据此继续修正、请求必要输入或交付。

    以证据判断是否完成
↶
未达标 → 带着证据回到判断与行动

保留原目标，根据新证据调整下一步；遇到权限、依赖或未知结果阻塞时停止盲目重试。

复杂任务可以分工协作。 探索、编码、审查和测试角色通过明确产物交接；不具备子 Agent 能力时，同一流程也可由单 Agent 串行完成。

04 / 从实践到下一次改进

经过验证的经验，才值得继续共享。

任务完成后，有复用价值的经验可以进入审查；适合共享的部分，经授权后沉淀为能力包的下一次改进。

  1. 发现经验

    从已验收的实践中识别可复用方法，区分通用做法和项目特例。

  2. 审查与沉淀

    核对新增价值、复用依据和验证边界，经授权后更新技能、规则或工具。

  3. 更新与复用

    完成相应文档、版本和检查，让适用项目通过既有更新流程获得改进。

回流按需发生。 普通任务不会自动改写共享能力；只适用于本项目的经验保留在本项目，没有合格的沉淀项也可以正常结束。
Evaluation / 用对照验证成长

资产规模看积累，任务表现看效果。

固定任务、初始代码、权限与模型设置，对比改进前后的结果；跨模型和宿主分别记录，不预设提效比例。

  • 任务正确性与遗漏
  • 返工与人工干预
  • 耗时与读取成本
  • 边界遵守情况

当前进展：已定义真实行为对照方案，完整模型／宿主矩阵仍待运行；已有机械测试不能替代实际提效证据。查看验证计划 ↗
